# 投稿资料与目标投稿包

- 状态：V0.42 已实现
- 日期：2026-09-03
- 范围：单篇论文的本地投稿准备与作者控制导出

## 产品合同

每篇论文工作区拥有独立的投稿资料目录。Rust 负责选择文件、扩展名与大小校验、SHA-256、
去重、只读复制和审计；WebView 只接收安全元数据，不接收原始路径。

支持的资料类别包括源文件工程、匿名主稿、原始图件、可编辑表格、参考文献、补充材料、投稿信、
标题页、声明和其他附件。每个新材料绑定稿件版本、目标选择、官方要求快照和具体清单项；旧版本、
旧目标或旧要求快照中的附件保留在本地历史中，但不会自动混入当前投稿包。

导入时除大小、扩展名和 SHA-256 外，还会按资料类别限制可选格式，并检查常见文件签名、PDF 可解析性与
加密状态、DOCX/XLSX/PPTX/OpenDocument 容器结构，以及 DOCX 批注和修订跟踪提示。图件与可编辑表格拥有
独立上传入口；期刊要求没有单列图表时，正文结构检测到的图表仍会形成上传槽位。合法 UTF-16 文本以警告
状态接收；伪装成 CSV/TSV 的 XLS/XLSX 会被明确识别并要求恢复正确扩展名，避免把错误命名的二进制工作簿
交给出版社。图件会提示作者继续按官方原文核验 DPI、尺寸和色彩空间。验证不代替出版社投稿系统的最终接收检查。

## 投稿包准备树

投稿资料页先显示一个面向作者的准备树，再显示证据级动态清单。树的根节点汇总当前稿件版本、
拟组包文件数、未纳入文件、校验阻断和必需项进度；分支覆盖主稿、原始图件、可编辑表格、当前
期刊必需附件、声明与作者确认，以及可选支持资料。

`SubmissionMaterialCatalog` schema v4 从当前确定性结构报告提供 `detectedFigureCount` 与
`detectedTableCount`。界面将其与图件/表格上传项实际绑定的独立文件数比较，显示缺少、多出或
数量一致。旧工作区缺少新字段时，前端只以现有图表清单槽位作兼容回退；再次分析后使用结构报告
中的正式计数。

准备树是导航摘要，不承担证据判定。“数量一致”不能证明图片精度、尺寸、色彩空间、表格可编辑性
或期刊格式合格；最终状态仍以动态清单、文件校验和官方要求快照为准。树中每个状态除颜色外还用
图标和文字呈现，中英文界面保留相同语义。

准备树、动态要求、分类上传和文件管理不会同时纵向展开。顶部 `tablist` 提供“准备概览、要求清单、
上传资料、已存文件”四种视图及实时数量，默认落在准备概览；方向键、`Home` 和 `End` 支持完整键盘
切换。上传入口只负责选取文件，要求视图保留义务和证据，已存文件视图集中处理纳入与删除，避免将
同一资料状态重复表现为多个并列列表。

## 同名附件替换

Rust 在写入前按当前稿件版本、主选期刊、官方要求快照、资料类型和上传项检查规范化文件名。同名
附件默认拒绝新增；桌面命令检测到冲突后显示跟随当前界面语言的原生确认框，并列出冲突名称。只有
作者点击“替换已有附件”才调用显式替换路径；取消不改变目录。本次选择自身包含多个同名文件时直接
提示消除歧义，不允许用选择顺序决定结果。

替换路径先校验并复制新文件，再以原子目录记录切换引用，最后清理被替代的应用托管副本。外部原始
文件从不修改。内容哈希完全相同的重复上传保持原记录，不生成重复副本；实际替换更新材料变更时间、
使更早的目标检查失效，并写入 `submission_materials_replaced` 审计事件。

## 投稿目标

期刊推荐仍是不可覆盖的本地运行记录。只有作者点击“设为投稿目标”，某个候选才成为这篇论文
当前的 `SubmissionTargetSelection`。选择记录保存推荐运行、期刊、出版社、等级、主页、
稿件版本和记录哈希；稿件版本更新后保留该选择，但在导出时提示重新核对。

V0.20 使用“一条主线 + 有序备选支线”。主线是唯一可登记投稿的目标；备选可提前形成独立的
官方要求快照和资料计划。提升备选时必须记录上一主线为尚未投稿、已拒稿或已完成撤稿，切换
形成不可变历史，避免产品暗示或协助一稿多投。

## 官方要求快照

每个目标选择拥有独立 `JournalRequirementSnapshot`。作者逐次授权后，Rust 读取期刊主页和
作者指南候选，优先 HTTPS；HTTP 和其他官方域名需额外本次确认。请求限制为已验证的公网地址、
最多四个候选页面和每次响应 2 MB；部分获取失败保持人工核验状态。页面正文只用于
确定性提取，工作区保存来源 URL、SHA-256、时间、短证据摘录和要求条目，不保存整页内容。

主页只用于发现官方作者指南，不直接充当投稿要求证据。发现器同时检查链接路径与可见链接文字，
可识别拼音或无语义路径；对官网采用公开动态新闻接口加载正文的情况，只读取同站点、限量返回的
指南正文。每项要求必须在同一局部句子中同时出现要求类别和明确义务、建议、禁止或数值限制，
因此导航中的“摘要/关键词”、论文列表中的“图片”以及引用导出弹窗中的“参考文献格式”不会生成
清单项。要求快照 schema v2 使旧版宽松抽取结果停止作为当前证据，作者重新获取后形成新快照。

网页不可读时，作者可粘贴官方原文并确认来源。无明确证据条目时保持“待人工核验”，不会把
出版社通用基线冒充为该期刊的具体要求。快照默认 90 天后提示更新。

## 导出结构

导出前先显示逐文件组包预览，包括文件用途、目标上传槽位、包内相对路径、必需/可选状态、是否纳入、
校验提示和 SHA-256 摘要。作者可以排除当前材料；排除必需材料后预检立即转为阻断，Rust 后端也会
拒绝绕过界面直接导出。一个文件只能完成它明确绑定的清单项，多个图件或表格不会再由单个附件代替。

双盲不是默认模式。只有当前目标的官方证据明确要求匿名投稿时，组包才会启用匿名安全模式：
`submission/` 使用独立匿名稿作为主稿，实名源稿不会写入该目录，标题页按独立上传项保留。仅发现
“匿名评审”字样但未识别到强制义务时，系统要求人工核验，不自动切换为双盲包。

目标投稿包严格分为：

```text
package/
├── submission/   # 作者实际向出版社上传的主稿及附件
├── records/      # 目标选择、官方要求快照和检查报告，仅供本地留档
└── README.txt    # 上传边界与警告
```

`records/package-manifest.json` 记录每个计划文件的用途、绑定清单项、纳入状态、相对路径和内容指纹，
便于导出后复核；`submission/` 中只写入预览中已纳入的当前材料。

旧的检查报告、HTML 预览和存证合集被重新定义为“内部审核档案”，不能再称为出版社投稿包。

## 投稿登记

ManuscriptDock 不登录或模拟期刊系统。作者在真实期刊网站完成操作后，勾选确认并登记目标、
稿件号或回执。若当前版本尚无本地存证，Rust 在同一动作中自动创建作者确认存证，再保存投稿
记录。导出不等于投稿成功，登记也不代表录用或出版。

## 后续预览能力

V0.24 的“预览”是可靠的文件装配预览，不是文档实页渲染。下一阶段计划在本机加入 PDF、Word 和
LaTeX 的真实页面预览，以及修订版本的页面并排和可视化差异；在本地渲染链完成前，产品不会把提取
文本或结构统计称为版面预览。
