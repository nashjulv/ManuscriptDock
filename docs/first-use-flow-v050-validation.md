## 本轮改变了什么

| 工作包 | 已实现行为 | 验证方式 |
| --- | --- | --- |
| R0 状态一致 | Rust 输出同一份清单、待办和最终就绪状态；报告绑定当前源稿、有效结构、目标、要求、附件、决定和规则版本 | 源码契约、失效与重开测试 |
| R1 反馈正确 | 空清单不再表示资料齐全；待确认不再表示检查全部完成；通过项使用正向文案；进度标题改为中性任务名称 | 自动化与原生中英文检查 |
| R2 识别与修正 | 中文作者按版面行识别；图表按编号题注、页码与原文归并；忽略正文引用和虚假的 Markdown 表格；提供带版本的作者/题注核对层 | 合成识别回归、真实 PDF 对照、双语核对控件测试 |
| R3 要求判定 | 投稿时限与篇幅分开；同义重复保留多份证据；四种作者结果；无明确适用条件不能免除；旧确认需要复核 | 中英文单位、去重、决定、必需文件与旧记录测试 |
| R4 检查到导出 | 无目标、无官网、无模型可做基础检查；每项待办可跳转；材料或决定变化要求重查；预检通过才可导出；重复导出不覆盖 | 原生 DOCX 全流程与实际文件哈希；Rust 导出、失效、重开回归 |
| R5 源稿与版本 | PDF 可建立关联 DOCX/TEX v1 工作区并双向导航；同格式新版本可重新确认旧目标、明确沿用历史附件；不自动继承声明或通过状态 | 关联/版本/哈希回归；双语文件选择与沿用控件测试 |
| R6 新手负担 | 学校、模型画像和增强规则折叠；准备期限明确是建议；推荐后聚焦并确认文章类型；卡片显示公开主题范围；重复导入区分同内容和同名 | 原生无学校/模型推荐、双语交互与指纹测试 |

结构核对不改写原稿；旧分解、核验决定和导出仍可追溯。详细取舍见 [ADR 0009](adr/0009-evidence-bound-preparation-and-linked-source.md)。

## 自动化验证

执行 `npm run check`：TypeScript、前端生产构建、Rust 格式检查通过；React **73/73**，核心 Rust **102/102**，桌面 Rust **51/51**，另有 **2 项真实网络测试按既有设置忽略**。Clippy 首次发现一处测试布尔断言写法，改正后单独重跑 `cargo clippy --workspace --all-targets -- -D warnings` 通过。`git diff --check` 通过。测试只使用合成数据。

macOS arm64 隔离调试 App 构建通过，原生导出共 11 个文件。实际核对 `package-manifest.json` 的主稿哈希、报告 v3 的上下文哈希，以及决定记录中的结构哈希、目标与要求快照 ID，均有对应记录。

核心新增场景包括：9/14/2 与双语题注去重、正文引用排除、投稿时限不误判篇幅、条件不适用需要依据、必需文件不可被确认替代、结构核对不改源稿、旧结构决定失效、同内容与同名区分、关联工作区保持独立版本、旧目标重确认、材料变化后重新检查、真实文件导出和重复导出、重开后继续操作。

## 尚未关闭的范围

这些项目不会冒称已经完成完整方案验收：

- R6 的有依据推荐规则组合、按附件类型提供合成示例、列表同时展示目标/阶段/关联来源，仍需后续细化；本轮先保留准确控件和明确入口。
- 通用作者核验在未建立目标/要求时会引导先核验目标；基础检查本身独立可运行。跨页面阅读位置尚未全面持久化。
- PDF 识别仍受字体、扫描、多栏和特殊编号影响；本次成功仅证明该样本及所列合成场景。没有新增 OCR、完整表格重建或 PDF 改写。
- 学校目录与期刊公开目录仍有覆盖限制；不能把候选推荐当作录用概率，手工来源仍需作者核实。
- Windows 原生文件选择、导出、重启，以及完整的窄窗口/三字号组合尚未逐项实测。现有三字号双语自动化回归继续保留。
- 英文界面中部分既有出版社身份数据和作者提供的原文保持中文；本轮新增按钮、核验状态、失败反馈和报告文案已配对。
- 本地调试 App 构建不等于正式安装包签名、公证或发布。
