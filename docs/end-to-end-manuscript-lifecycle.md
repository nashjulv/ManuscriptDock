# ManuscriptDock 端到端论文生命周期

- 状态：MVP 实施基线
- 日期：2026-08-24
- 适用范围：单机个人版

## 1. 结论

ManuscriptDock 的用户主路径统一为：

```text
概览 → 目标期刊 → 投稿资料 → 检查与修订 → 投稿包
```

五个主任务消费同一篇论文的不可变产物，并生成可恢复、可审计的本地记录。版本历史、存证和
知识体仍是内部生命周期对象，但只在“记录与高级功能”中按需出现。任何新论文版本都会使旧
检查、投稿与知识体快照变为历史记录；已选目标保留并明确提示按新版本复核。版本历史、本地
存证和个人知识体继续存在，但不再成为导出投稿包的主线关口。

## 2. 现状审计

| 环节 | 审计前能力 | 主要缺口 | MVP 修订 |
| --- | --- | --- | --- |
| 导入 | 可选择 DOCX、PDF、TEX 并建立只读快照 | 后续路径从“版本”开始，用户不知道为什么先管理版本 | 导入后直接进入检查 |
| 检查 | 结构、目标、规则检查分散在三个阶段 | 目标选择不是独立目的；结果与修订之间缺少直接动作 | 一次分解形成带哈希的统一资产，再由它生成知识体候选、规则结论与投稿包输入 |
| 修订 | 可安全修订部分 DOCX/TEX 字段 | 修订前后依据分散；保存后检查结果过期 | 从检查结果进入修订；保存新版本后自动重提取并复查 |
| 版本 | 支持保存、比较和恢复 | 被放在检查之前；恢复或导入新稿后没有清晰的下游失效语义 | 放在修订之后核验差异；新版本明确要求重新检查 |
| 目标期刊 | 无 | 作者缺少从当前稿件、个人用途和学校评价规则到投稿目标的可核验桥梁 | 保存投稿背景，生成国内外各 2/3/3 候选，并由作者明确将一项保存为投稿目标 |
| 存证 | 只有源文件 SHA-256 | 文件指纹不等于作者确认后的证据记录 | 建立作者确认的本地存证记录，绑定稿件版本、检查报告和时间并计算记录指纹 |
| 投稿包 | 只有内部 JSON/HTML 预览 | 评估档案被误称为投稿包，缺少原图和真实附件 | `submission/` 保存出版社文件，`records/` 保存内部记录；作者外部投稿后登记回执 |
| 知识体 | 即时生成只读示意 | 未持久化，也未绑定存证和投稿记录 | 结构分解后立即形成可追溯候选；投稿登记后再固化不可变知识体快照 |

## 3. 内部状态合同

### 3.1 导入

输入是作者选择的原稿；输出是 `ArtifactVersion v1`、内容指纹和审计事件。WebView 不获得
源路径，原文件不被覆盖。成功后唯一主操作是“开始检查”。

### 3.2 检查

检查阶段内部采用渐进披露，而不是继续增加顶级导航：

1. 本地确定性分解，持久化 `decomposition manifest`；
2. 选择适用的国家、出版商和研究报告规则；
3. 运行规则并生成逐条结论、JSON 报告和 HTML 预览。

分解资产绑定当前稿件版本、内容指纹和自身 SHA-256，并声明两个共同出口：
`knowledge_body_candidates` 与 `submission_readiness_inputs`。它保存可追溯的文本、表格、
图片片段及 Claim、Scope、Method、Result、Evidence 语义候选。规则检查直接复用该资产，
不得再次独立解析源稿。检查报告必须绑定当前稿件版本和内容指纹。若版本变化，旧报告只保留为历史证据，不得
继续作为当前存证依据。

### 3.3 修订

修订只覆盖能够安全定位和回写的结构化字段，不扩张为通用全文编辑器。作者先看到规则
依据和修改前后，再保存为新版本。保存成功后，系统对新版本自动重做结构提取与同一组
规则检查，避免把旧报告错误地带入后续步骤。

### 3.4 版本

版本阶段用于核验刚形成的当前版本、比较差异、导入外部修改稿或恢复旧稿。任何导入或
恢复都创建新的头版本，不改写历史，并让当前检查、存证、投稿和知识体状态重新进入待办。

### 3.5 目标期刊

目标期刊先保存学校/机构、学院或专业、论文用途和投稿截止日期，再绑定当前稿件版本、
内容指纹、目录版本和作者偏好。作者姓名可选且不参与排序。专业、用途、截止日期或偏好变化会重新生成；姓名、
学校变化也会生成新的归属档案与运行 ID。学校正式规则只有在官方来源、适用范围、有效期和
核验状态完整时才应用；未核验只输出候选初筛。作者可粘贴学校
正式原文并逐次授权模型发送学校名称、学科、用途和脱敏后的该段原文；作者姓名、来源网址、联系方式、身份标识和论文正文不发送，模型不得凭训练
记忆补写规则。机构评价目录只在后台参与资格判断，客户端不展示原始表格；数据仍必须具有
合法来源和固定版本。候选顺序不是录用概率，截止日期也不预测录用、见刊或收录时间。详见
[期刊匹配与投稿目标推荐](journal-matching-and-submission-targeting.md)。

候选被已核验规则判定为不合格时不得推荐。推荐运行持久化后，只有作者明确点击“设为投稿目标”
才建立 `SubmissionTargetSelection`，并成为资料检查与投稿包的目标输入。

当前目标是唯一投稿主线；其他候选可成为按顺序保存的备选支线。每条路线独立绑定官方要求
快照。联网读取期刊官网需要逐次授权，默认 HTTPS 公网地址，HTTP 与其他官方域名需要额外
本次确认；部分获取失败保持人工核验，无法提取时由作者
粘贴并确认官方原文。支线提升为主线前必须记录上一主线状态，所有切换保留不可变历史。

### 3.6 存证（高级记录）

MVP 存证是本机加密完整性记录，不宣称上链、公证或第三方时间戳。记录至少包含：

- 当前稿件版本与 SHA-256；
- 当前检查报告标识、结果与输出快照版本；
- 作者确认声明和确认时间；
- 存证记录自身的 SHA-256；
- 外部传输状态。

存证只证明“作者在某时确认了这一组本地对象和检查状态”，不证明研究结论为真。

存证不再是导出投稿包的显式门槛。作者在真实期刊系统完成投稿并确认登记时，若当前版本没有
存证，系统在同一动作中自动创建。

### 3.7 投稿包与投稿登记

单机 MVP 不模拟全球期刊网站的自动提交。产品提供两项真实能力：

1. 将当前主稿及作者提供的源工程、原图、表格、参考文献、投稿信、标题页、声明和补充材料放入 `submission/`；
2. 将目标选择、检查报告和清单放入仅供本地核验的 `records/`，并在 README 明示不得上传；
3. 作者在外部系统完成提交后，在本机登记投稿目标和可选回执号。

登记动作必须由作者明确确认，且不发生网络传输。未来期刊连接器或 PWC 服务仍需复用同一
外发确认合同，不能绕过本地快照。

### 3.8 知识体

完成结构分解后，系统立即从同一 `decomposition manifest` 生成知识体候选。机器提取到的
对象状态为 `candidate`，带原文片段、模态、来源标签和置信度；没有足够内容的对象才保持
`pending v0`。候选可以用于明确标注不确定性的查看与问答，但不能冒充作者确认结论。

只有当前版本已完成存证和投稿登记后，才能把本次生命周期固化为不可变
`KnowledgeBodySnapshot`。它固定引用分解资产 ID 与哈希，以及稿件、检查、修订、存证和投稿的具体版本，
并继续保持 Claim、Scope、Method、Result、EvidenceRelation、SourceAnchor、
AIReviewReport 和 Provenance 的对象边界。固化前由作者从 `ManuscriptDock Discipline
Index v1.0` 选择主要学科，形成状态为 `author_confirmed` 的
`ClassificationAssignment`；当前版本不得根据标题或摘要自动猜测学科。未来模型只能提出
带依据的候选分类，作者确认后才形成新的分类版本。

知识体记录生成独立的 SHA-256 哈希，覆盖知识体快照、学科分类、存证标识和投稿标识。
最终页完整显示 64 位哈希与分类协议版本。该哈希用于本地完整性复验，不等同于区块链、
公证、第三方时间戳或科学真实性证明。

知识体问答属于作者逐次触发的外部模型调用。Rust 在网络出口删除结构报告和投稿档案中的已知作者姓名，
并对标题、摘要、章节和问题中出现的已识别作者姓名、联系方式和长数字身份标识进行脱敏；
源文件和本机路径不进入模型请求。原始问题只保存在本机问答账本中。

## 4. 恢复与失效规则

应用重新打开工作区时，必须从磁盘恢复与当前稿件版本匹配的最新结构报告、检查报告、
存证、投稿记录和知识体快照。恢复不是重新执行检查，也不得把其他版本的产物显示为当前。

| 事件 | 保留 | 当前状态失效 |
| --- | --- | --- |
| 保存修订版本 | 所有历史文件与报告 | 旧结构、旧检查、旧存证、旧投稿、旧知识体 |
| 导入外部修改稿 | 所有历史版本 | 同上 |
| 恢复旧版本 | 被恢复版本仍保留，并创建新头版本 | 同上 |
| 重新检查同一版本 | 旧检查报告 | 旧存证及其下游记录不再代表最新检查 |
| 新建存证 | 旧存证 | 旧投稿与知识体仍是历史对象 |

## 5. MVP 验收路径

使用合成 DOCX 或 TEX 完成以下连续操作，且中途重启应用后仍能继续：

1. 导入并创建工作区；
2. 提取结构、选择规则并完成检查；
3. 修改一个安全字段并保存新版本；
4. 自动重查，比较新旧版本；
5. 计算国内、国际各 2/3/3 家期刊候选，调整一个条件并重新计算，再明确选择目标；
6. 补全目标期刊需要的投稿资料；
7. 导出分离 `submission/` 与 `records/` 的投稿包；
8. 登记一次手工投稿，并验证缺少存证时会自动创建；
9. 固化并查看知识体快照。

第 9 步必须验证：未选择学科时不能固化；选择后显示作者确认分类、
`ClassificationAssignment` 版本和完整 64 位知识体 SHA-256。重新分类创建新记录并推进
分类版本，不覆盖旧记录。

自动化测试覆盖状态恢复、版本失效、存证绑定、投稿前置条件、导出内容和知识体固化；桌面
构建继续验证 WebView 不获得任意文件系统能力。
