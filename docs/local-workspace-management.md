# 最近工作区管理

- 状态：MVP 已实现
- 适用位置：我的工作台 / 最近工作区
- 核心原则：归档可恢复，删除须确认，应用不能越过工作区边界

## 1. 用户目标

作者长期管理多篇论文时，最近工作区不能无限堆积，也不能把“暂时不看”和“永久删除”
混为同一操作。每篇论文因此具有独立的管理入口，并提供两种语义明确的动作：

- **归档**：从最近工作区移入“已归档”，完整保留论文版本、分析、检查、存证、投稿、
  知识体和问答记录，可随时恢复；
- **永久删除**：删除 ManuscriptDock 为该论文建立的整个本地工作区，不能在应用内撤销。

外部原稿不属于工作区，归档和删除都不会修改作者最初选择的外部文件。

## 2. 界面与交互

每一行把主要的“打开论文”和次要的“管理论文”分开，避免嵌套按钮和误触。管理菜单只
显示当前状态可执行的操作：最近工作区显示“归档”和“永久删除”，已归档显示“恢复到
最近工作区”和“永久删除”。

永久删除必须经过行内二次确认。确认区明确列出会被删除的范围，并提供取消与确认两个
按钮；关闭菜单、切换状态或按 Escape 都不会执行删除。按钮具有可辨识的论文名称、可见
焦点和不小于 44px 的交互目标。

归档、恢复和删除期间，该论文的管理入口进入忙碌状态。完成或失败后，工作台保留可见
反馈；即使用户删除了最后一个工作区，结果也不会随列表消失。

## 3. 本地存储语义

```text
projects/<workspace-id>/           # 最近工作区
archived-projects/<workspace-id>/  # 已归档
```

归档和恢复在同一应用数据根目录中移动完整工作区，不重写稿件或版本快照。操作前 Rust
必须验证：

1. 标识是精确 UUID；
2. 目标是目录且不是符号链接；
3. 清单中的工作区标识与目录一致；
4. 目标集合中不存在同名工作区。

归档和恢复分别追加 `workspace_archived`、`workspace_restored` 审计事件。永久删除还要求
WebView 传入显式作者确认，并由 Rust 再次验证上述边界后删除确定的单一目录。

## 4. 删除范围与恢复边界

永久删除覆盖该工作区内的全部应用数据，包括：

- 不可变稿件副本与所有论文版本；
- 结构提取、投稿检查和 HTML 预览；
- 修订集、存证、投稿登记与交付记录；
- 学术知识体、分类、哈希以及本地问答账本；
- 工作区清单和审计日志。

已经导出到作者另选目录的投稿包，以及原始外部稿件，不在删除范围内。MVP 不提供回收站
或删除后恢复；重要工作区应先归档，未来再增加作者选择目录的加密备份与迁移。

## 5. 与知识体根目标的关系

归档不会解除论文版本和知识体快照之间的引用，也不会降级知识体状态；恢复后继续使用同一
版本历史。永久删除则表示作者主动撤销这台设备上的完整研究记忆单元，因此知识体、问答和
来源链必须作为一个边界共同删除，不能留下脱离来源的孤立记录。
