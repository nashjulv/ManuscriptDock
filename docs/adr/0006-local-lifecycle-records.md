# ADR 0006：本地生命周期记录与七步状态机

- 状态：Accepted
- 日期：2026-08-24

## 背景

早期桌面端已经分别实现结构提取、规则检查、修订、版本和知识体预览，但顶级导航反映
内部模块而不是作者任务。结构与检查状态只保存在当前 React 会话，重新打开工作区后无法
恢复。投稿包也只是内部预览，没有作者可交付的导出物；存证和投稿登记缺失，因此产品无法
证明“当前版本经过了哪次检查、由谁确认、投向哪里，以及知识体固定了哪条链”。

## 决策

1. 顶级生命周期统一为 `导入 → 检查 → 修订 → 版本 → 存证 → 投稿 → 知识体`。
2. 结构提取、规则选择和规则执行属于同一“检查”阶段的渐进步骤。
3. 与当前稿件版本和内容指纹匹配的结构报告、检查报告、存证、投稿和知识体记录可从磁盘
   恢复；不匹配的记录只保留为历史，不显示为当前状态。
4. 修订保存后自动对新版本重做结构提取与同一组规则检查。其他新增或恢复版本明确让下游
   当前状态失效。
5. 本地存证绑定稿件版本、稿件 SHA-256、检查报告、作者声明和时间，并对记录本身计算
   SHA-256。读取时重新计算并验证，不把它表述为区块链、公证或科学真实性证明。
6. 投稿阶段先导出作者选择目录中的交付包，再由作者在期刊系统提交并手工登记目标和可选
   回执。自动投稿在连接器存在前不得伪装实现。
7. 投稿登记后才可持久化 `KnowledgeBodyRecord`；记录固定知识体快照、存证、投稿标识和
   作者确认的 `ClassificationAssignment`，并计算覆盖这些对象的记录哈希。
8. MVP 学科分类来自内置双语 `ManuscriptDock Discipline Index v1.0`，由作者选择。
   重分类产生新的不可变知识体记录并推进分类版本；旧版无分类记录继续可读，可通过补充
   分类升级。未来模型分类只能作为候选，不能绕过作者确认。

## 后果

- 工作区重新打开后可以继续当前版本的真实流程，不依赖前端内存。
- 每个下游完成状态都有可核验的本地对象，导航状态不再由页面访问推测。
- 导出是用户明确选择目录的可见写入；WebView 仍没有任意文件系统权限。
- 期刊网站提交仍由作者完成。未来自动连接器、PWC 存证或预印本发布必须建立新的外发确认
  和传输审计，不能复用“本机未外发”状态。
- 当前知识体核心对象模型未虚构 Claim、Method、Result 或 AIReviewReport 内容；生命周期
  记录增强来源链，但不会把确定性投稿检查冒充 AI 科学审核。
