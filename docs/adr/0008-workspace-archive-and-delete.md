# ADR 0008：工作区归档与永久删除边界

- 状态：Accepted
- 日期：2026-08-25

## 背景

最近工作区会随论文数量增长。作者需要把暂时不用的研究移出日常列表，也需要能够彻底清除
本机中的敏感论文数据。普通列表隐藏或只删除清单记录都会留下歧义和孤立数据，而不受约束
的目录删除又可能越过论文工作区边界。

## 决策

1. 归档是可逆状态：在应用数据根目录的 `projects` 与 `archived-projects` 集合之间移动
   完整工作区，不复制、不拆分、不重写不可变论文版本。
2. 归档与恢复前验证 UUID、非符号链接目录、清单身份和目标不存在，并追加可复验审计事件。
3. 已归档工作区不能直接进入论文流程；作者恢复后再打开，避免界面状态与存储集合不一致。
4. 永久删除必须在界面中二次确认，Rust 命令还要求显式 `author_confirmed`，并再次执行与
   归档相同的路径和身份验证。
5. 删除的最小单位是完整工作区。版本、分析、存证、投稿、知识体和问答不能被选择性留下；
   外部原稿和作者另行导出的投稿包不属于该边界。
6. MVP 不声明回收站、云端备份或删除恢复能力。删除成功后不保留包含论文身份的全局墓碑。

## 后果

- 最近列表保持轻量，归档论文仍保有完整可追溯性和恢复能力。
- 永久删除能满足本地敏感资料清除需求，同时删除目标被严格限制为一个已验证工作区。
- 归档是日常推荐动作；永久删除是明确不可逆动作。
- 跨设备归档、加密备份、保留策略和机构侧删除证明需要后续单独设计。
