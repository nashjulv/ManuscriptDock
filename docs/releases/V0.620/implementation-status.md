# V0.620 状态刷新与输入恢复

## 诊断

用户报告的诊断编号对应 `update_document_facts` 后台任务。错误为 `CONTEXT_CHANGED`，记录的最新项目版本为 12。原页面仍用旧项目版本保存；通用提示声称“已重新读取”，实际只显示错误而未刷新。最近任务入口也直接复用了列表快照。

## 修复

- 最近任务入口重新读取项目后再打开。
- 保存遇到版本冲突时读取最新项目，保留本次未保存输入，并要求重新核对确认。读取失败明确提示失败，不再声称已经刷新。
- 按字段比较原状态、本次输入和最新状态：不重叠的修改可并存；同一字段的不同修改或原稿替换时保留两份值，逐项选择后才能保存。刷新不会自动提交或覆盖稿件信息。
- 项目附件或版本更新时保留正在填写的稿件信息；更新后清除旧的作者确认。
- 顶部工具栏增加“刷新 / Refresh”按钮，全局读取当前项目、最近任务、材料、目录和准备状态。失败时保留当前表单。已失效的期刊推荐和投稿包预览不继续复用。
- 合并重复的准备状态请求，并防止迟到的刷新结果覆盖较新的结果。
- 修复关联 DOCX 后仍提示“当前主稿为 PDF”：顶部文件名及 DOCX 缺失提示现在遵循实际打包选择顺序（已启用匿名主稿、已启用可编辑主稿、导入来源）。目录中删除原始 PDF 不再被误解释为当前投稿主稿仍为 PDF；未关联 DOCX 时明确显示“尚未关联投稿主稿 DOCX”。原始导入快照仍保留，不修改或删除用户稿件。

## 版本与启动规则

按用户要求，后续每次 commit 只增加 `0.001`，显示三位小数。开发期间既有 V0.62 数值规范化为 V0.620；本组修改随 V0.621 提交，安装元数据为 0.621.0。

开发完成只构建和测试，不自行打开或重启应用。应用由用户手动打开、在终端启动，或明确要求后再启动。规则已同步到 AGENTS.md。
