# V0.56 本地目录与逐项材料生成

修改保留在工作树，不提交、不推送。

## 功能

- 本地目录采用紧凑工具栏、可折叠目录树、文件图标、列表列标题、修改日期、大小、选择状态和路径栏。支持双击进入目录、打开支持的文件、图标／列表切换、内部移动、手动和返回应用刷新。
- 选择文件夹时，投稿包位于该文件夹内；选择单个稿件时，位于稿件同级目录。路径为 `<稿件名称> - Submission Package - <任务短编号>/<期刊名称>`，区分任务和目标。正式导出也使用此位置。
- 旧任务缺少原始位置时提供系统文件夹选择入口；首次建立目录会复制旧版内部整理目录，保留旧文件。原稿和历史快照保持不变。
- 材料按目标期刊列出。仅支持生成且信息齐备的缺失材料有单项“一键生成”；“全部一键生成”仅生成当前符合条件的缺失项。现有文件不覆盖。
- 支持模板的材料另有“一键生成模板”，生成独立的 `-TEMPLATE.docx`，包含目标要求和明确的作者待填字段。不会写入未经确认的声明，也不会将材料标记为完成；已生成模板显示“模板已存在 · 需补充”。主稿不提供自动模板。
- 顶部“一键生成模板”批量处理可生成模板的缺失项。已有文件或模板时不能生成模板；已有文件时不能生成文件；只有模板时仍允许在事实齐备后生成文件。单项和批量共用后端判断，批量跳过已存在项；前端生成期间统一锁定按钮，刷新文件状态后解锁，后端项目级文件锁防止并发生成，写入禁止覆盖。
- 状态位于每项右上角，以标签展示“需手动补充”“可一键生成”“草稿已存在 · 待核对”“已提供”。生成按钮独立放在标签下方。
- 草稿和模板生成后复用右上角标签作为状态按钮，点击通过受控文件路径打开对应文件进行核对或补充。
- 当前生成使用本地 DOCX 模板，不包含 LLM 调用。匿名主稿不能自动生成；声明所需事实须作者确认。生成草稿仍需核对，不代表可正式投稿。
