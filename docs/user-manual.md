# 投稿舱 ManuscriptDock V0.44 产品使用手册

- 产品名称：投稿舱 ManuscriptDock V0.44
- 产品版本：V0.44（安装包版本 `0.44.0`）
- 适用平台：macOS 11+、Windows 10/11 x64
- 手册日期：2026-09-04
- 产品定位：本地论文投稿准备工作台 / Local-first manuscript submission workspace

> **投论文，上更好的期刊。**<br>
> *Go for Better Journals.*

## 1. ManuscriptDock 能做什么

ManuscriptDock 面向需要持续修改、检查和投稿论文的个人作者。应用把一篇论文从原稿整理为
可追溯的本地研究记忆，主流程为：

```text
概览 → 目标期刊 → 投稿资料 → 检查与修订 → 投稿包
```

当前版本可以：

- 导入 DOCX、PDF 或 TEX 稿件并建立只读源快照；
- 提取标题、作者、摘要、关键词、章节、图表、参考文献和投稿声明；
- 使用内置规则检查投稿准备情况；
- 安全修改部分结构化字段并保存为新版本；
- 比较版本，导入外部修改稿或把历史版本恢复为新的当前版本；
- 根据论文方向、稿件准备程度、用途、截止时间和学校正式规则，分别生成国内与国外的冲刺、匹配和保底期刊组合；
- 将推荐结果保存为唯一当前投稿主线，并建立有序备选支线；
- 先从本机目录核对所选期刊画像；本地资料不足时，经本次授权调用作者配置的模型寻找公开资料线索；
- 经逐次授权读取期刊官方站内作者指南，或由作者粘贴官方原文，生成本地要求快照；
- 只把作者指南中的明确约束句写入清单，排除官网导航、文章列表和引用导出工具等页面噪声；
- 从作者指南逐条保留摘要、正文及各章节字数限制，并识别报告清单、授权书、版权或作者协议等支持文件；
- 集中保存原图、可编辑表格、参考文献、投稿信、声明和补充材料；
- 导出包含真实稿件及附件的出版社投稿包，并登记人工投稿结果；
- 固化带学科分类和 SHA-256 哈希的学术知识体；
- 使用作者自己的 API Key，让主模型和两个备选模型回答知识体问题。

关键词标签采用确定性多格式识别：除 `Keywords` 和 `关键词` 外，也支持论文中常见的
`Key words`、`Key-words`、`Index Terms`、`关键字`、字间空格及冒号/破折号分隔形式；
Word 样式与常见 LaTeX/IEEE 关键词环境也会进入同一判断。升级后的既有工作区需再运行一次
“检查与修订”，系统会用新版解析器创建新的结构结果，不继续沿用旧的关键词误报。

V0.41 以前建立的期刊要求快照不会继续解锁当前清单。进入“目标期刊”，对当前主线点击
“重新获取官方要求”；系统会从主页定位官方作者指南，并只保留含明确义务、建议、禁止或数值
限制的局部原句。如果官网正文依赖脚本且无法安全读取，状态会保持“待核验”，请粘贴官方原文，
不要用期刊首页全文代替作者指南。

目标期刊记录使用 HTTP 时，授权后先尝试对应 HTTPS 地址；无法获取时显示具体原因。
仅在作者对明确地址作本次确认后，才允许未加密 HTTP 或其他官方域名访问。也可以随时粘贴
官方原文：手动保存来源网址不会联网。访问记录与失败原因可在目标卡片中查看。

ManuscriptDock 当前**不会**自动登录期刊网站、替作者完成投稿、预测录用结果、证明科学结论，
也不执行语法润色或语义改写。AI 语义与语法审计属于后续迭代功能，计划上线；当前不会以此名义
生成未经作者确认的修改。应用也不会把本地存证描述成区块链、公证或第三方时间戳。

## 2. 安装与首次启动

### 2.1 macOS

公开发布版应使用 Developer ID 签名并完成 Apple 公证。当前开发安装包可能被 macOS 标记为
“无法验证开发者”或“不安全”。只有在确认安装包来源可信、文件未被篡改时，才可在
“系统设置 → 隐私与安全性”中选择“仍要打开”，或在 Finder 中右键应用并选择“打开”。

### 2.2 Windows

Windows 10/11 使用 x64 安装包。系统通常已包含 WebView2；缺少时安装器会尝试补齐。
当前未签名开发包可能触发 SmartScreen。只有在确认安装包来源可信时才继续运行。

### 2.3 语言和界面

应用右上角提供“中文 / EN”切换。论文工作区左侧固定显示五个主任务：“概览、目标期刊、
投稿资料、检查与修订、投稿包”。版本历史、本地存证和个人知识体收在“记录与高级功能”中；
依据面板按需打开，避免与当前操作争抢空间。

## 3. 开始前准备

建议准备：

1. 一份 DOCX、PDF 或单文件 TEX 论文，文件不超过 250 MB；
2. 论文用途，例如毕业、学位、职称、项目结题或学术交流；
3. 希望完成投稿的截止日期；
4. 如学校有成果认定要求，准备学校正式文件中的相关原文和官方 HTTP／HTTPS 页面；
5. 如需模型功能，准备一个 OpenAI Chat Completions 兼容服务的 API 地址、模型名称和 Key；可在应用顶部随时打开“模型设置”。

优先导入 DOCX 或 TEX 源稿。PDF 更适合只读检查；扫描件、复杂多栏、异常字体、公式和表格
可能只能得到受限提取结果。

## 4. 快速完成一次投稿流程

1. 在首页点击“选择论文（Select manuscript）”。
2. 核对文件信息后创建本地工作区。
3. 在“目标期刊”直接用当前主稿生成国内外冲刺 2、匹配 3、保底 3 的初步候选；学校、专业、用途和截止日期可用于进一步调整。选择一个主目标，并取得该刊官方投稿要求；其他候选可加入备选支线。
4. 在“投稿资料”查看由文章类型与官方原文生成的动态清单，核对摘要、正文及各章节字数限制，并补充源工程、匿名稿、原图、表格、参考文献、投稿信、标题页、声明、报告清单和其他支持文件。“目标检查”不属于待上传材料。
5. 必需材料完成后，从页面底部的独立下一步进入“检查与修订”，提取结构、运行与当前目标绑定的规则检查，并将安全修改保存为新版本。
6. 直接在“投稿包”核对当前版本、目标与材料完整性，导出面向出版社的资料；只上传其中的 `submission` 文件夹。
7. 在真实期刊网站完成投稿后，回到应用登记稿件号或回执；本地存证会随作者确认自动建立。
8. 需要时从“记录与高级功能”查看版本历史、本地存证和知识体。

版本历史不再是检查与投稿包之间的必经关口。导入外部修改稿、比较版本和安全恢复旧稿都是
可选高级操作；只要版本发生变化，应用就会要求重新确认目标、重新组织材料并重新检查。
如果在检查后新增或删除附件、改变附件是否纳入组包，或者更新作者确认，旧检查也会失效；完成
最终材料状态后需重新运行一次目标检查。

下面各节说明每一步的具体含义和注意事项。

## 5. 导入论文与概览

在“我的工作台”点击“选择论文”。系统文件选择器只允许选择：

- `.docx`：适合结构提取和有限字段回写；
- `.pdf`：适合只读提取和检查；
- `.tex`：适合单文件 LaTeX 结构提取和有限字段回写。

导入后，Rust 后端在应用数据目录创建不可变副本、计算 SHA-256 内容指纹并建立 `v1`。
原始外部文件不会被移动或覆盖，界面也不会获得其完整本机路径。

如果文件不受支持、超过 250 MB、无法访问或内容在分析前被修改，应用会拒绝继续并显示原因。

## 6. 检查投稿准备

### 6.1 提取论文结构

点击“提取论文结构（Extract structure）”。应用在本机提取：

- 标题与作者；
- 摘要与关键词；
- 章节层级；
- 图、表、参考文献；
- 伦理、利益冲突、数据可用性等常见投稿声明。

提取结果以带 SHA-256 的 `decomposition manifest` 保存在当前论文版本中。它同时用于：

- 生成带来源的 Claim、Scope、Method、Result、Evidence 候选知识体；
- 生成投稿规则检查、HTML 预览和投稿交付包。

候选状态表示“已经提取、尚待作者确认”，不是空白占位。只有确实没有找到足够内容的对象
才显示 `pending v0`。投稿包会携带同一份分解清单，便于核对知识体与投稿材料来自同一次解析。

右侧证据面会显示检测到的标题、作者、摘要、章节和来源快照版本。请重点检查标题、作者和
摘要是否正确；确定性提取结果不是作者确认。

### 6.2 PDF 的特殊说明

PDF 先进行文档和页面分类，再优先读取原生文字与版面对象。只有无法读取的区域才会被标记为
OCR、公式识别或表格识别候选。当前安装包尚未交付完整 OCR 运行时，因此出现“需要 OCR”时：

- 可靠页面仍会保留；
- 不会对整篇 PDF 进行虚假的 OCR；
- 建议改用 DOCX/TEX 源稿，或人工核对缺失页面；
- PDF 结果始终属于受限结构证据，不等于恢复了作者源文件。

### 6.3 选择检查标准

通用初投稿规则始终启用。作者可以另外选择真正适用的国家标准、国际伦理规范、出版社或
研究报告规则。具体期刊最新作者指南始终优先于内置基线。

点击“运行投稿检查（Run submission checks）”后，结果分为：

- 通过：当前证据满足规则；
- 建议：不阻止继续，但建议优化；
- 阻断：进入后续步骤前必须处理；
- 待确认：系统无法可靠自动判断，需要作者核对。

检查报告绑定当前稿件版本、内容指纹、规则包和输出快照。更换稿件版本后，旧报告只作为
历史证据保留，不能继续代表当前版本。

## 7. 投稿优化修订

进入“修订”后，应用组合已选出版社的投稿要素，并只开放能够安全定位的字段。

当前主要支持：

- TEX：标题、摘要、关键词等有限字段；
- DOCX：具有明确 Title 样式的标题；
- PDF：只读，不直接修改。

修改前请在证据区核对原值、规则来源和字段限制。点击保存后：

1. 原版本保持不变；
2. 修改内容形成新的不可变稿件版本；
3. 保存修订来源和差异；
4. 对新版本重新执行结构提取和同一组规则检查。

当前修订台不是通用全文编辑器，也不承诺自动完成整篇论文排版。

## 8. 管理论文版本（高级记录）

版本库类似面向论文作者的本地轻量版本仓库。

### 8.1 导入外部修改稿

点击“选择修改稿”，选择与当前稿件相同类型的文件，可填写不超过 200 字的版本说明，例如
“补充方法与统计分析”。保存后，新文件成为当前版本；相同内容会被去重。

### 8.2 比较版本

选择两个版本后，可以在本机比较：

- 标题；
- 章节增加与删除；
- 词元、图、表数量；
- 投稿声明；
- 两个版本的完整内容哈希。

当前比较不是逐词红线，也不评估修改的科学正确性。

### 8.3 恢复历史版本

“恢复”不会覆盖或删除历史，而是从所选历史内容创建一个新的当前版本。恢复后，检查、期刊
推荐、存证、投稿和知识体需要按新版本重新形成。

### 8.4 新版本与后续结果

新版本不会自动继承旧版本的检查、期刊候选、存证或投稿记录。完成修改、导入或恢复后，应用会
提示重新检查并生成与当前版本绑定的新结果；旧结果继续保留为历史记录。

## 9. 选择目标期刊

### 9.1 同步离线期刊目录（可选）

展开“期刊数据设置”，可选择一个或多个 `.xlsx` 文件。系统只读取文件内已经保存的单元格值，
不执行公式、宏或外部链接；相同文件重复导入会去重，同名文件的新内容会形成新的活动快照。
中科院分区、JCR 和其他分区体系分别保存，不互相换算。原始工作簿不会复制进安装包或上传，
目录数据只保存在本机应用数据目录。应用把活动数据转换为可索引的本地数据库表；ISSN 与
EISSN 分字段保存并优先用于严格归并，刊名只作回退匹配。被完整名单替代的不完整来源不会进入
活动数据库。推荐结果会显示匹配到的体系、年份、分区和 Top 状态。

本地期刊画像还可保存出版社、主要发表方向、作者指南地址、年度发文量、同行评审方式、投稿至
发表周期、费用与 OA 状态及其来源时间。年度发文量只是出版规模代理，不是纸刊发行量；投稿至
发表总周期也不是首轮审稿速度。来源未公布的发行量或真实审稿速度保持“未知”，应用不会补猜。

选定投稿主线后，可点击“核对目标期刊画像”。系统总是先查询本机数据库；如果所需比较字段
在本地均有资料，本次不会调用模型 API。作者点击“核对本地；缺失时发现”即授权这一次受限任务；
只有本地画像仍有缺项时，Rust 才会把
期刊名称、已知出版社、公开主页和本地已有的 ISSN/EISSN 发给已配置的模型。论文正文、附件、
作者、学校、工作区标识、推荐分数和分区内部计算均不发送。

模型返回内容只保存为“待官网核验的发现线索”，不会自动写成官方事实、分区证据或推荐分数，
也不会覆盖本机目录。作者仍需继续取得期刊官网作者指南，形成带来源与有效期的正式要求快照。
未配置模型、未授权或模型无法支持的字段继续显示“未知”，不阻断现有离线推荐。

### 9.2 填写投稿背景

当前主稿已经足以生成第一轮内容适配推荐。完成投稿截止日期默认设置为约 90 天后，可按计划修改；
学校或机构、学院或专业以及投稿人姓名均可稍后补充，投稿人姓名明确不参与排序。论文用途有默认值，
也可改为学位、毕业、职称或项目结题。学校排名和导师名气不用于生成期刊候选；学校正式规则用于核对成果是否
满足作者所在机构的要求。

### 9.3 可选：提供学校正式要求

可粘贴研究生院、科研处或学院发布的正式原文，并填写官方 HTTP／HTTPS 来源。原文至少 40 个字符。

点击生成初步推荐即授权这一次学校规则抽取，不再要求额外勾选模型发送确认。按钮旁会持续显示
外发范围；本次请求只允许包含：

- 学校名称；
- 学科或专业；
- 论文用途；
- 已删除作者姓名、邮箱、电话、学号和长数字身份标识的规则原文。

官方来源网址、作者姓名和论文正文不发送。网址只保存在本机作为来源证据。模型只能结构化
作者提供的原文，不得依靠训练记忆猜测学校政策。没有可用模型时，可留空学校要求并先执行
本地候选初筛。

### 9.4 调整推荐条件

可以选择研究方向、文章类型、投稿语言、目标策略、开放获取偏好。目标策略包括：

- 冲刺（Reach）；
- 均衡（Balanced）；
- 务实（Pragmatic）。

系统分别为国内和国外期刊生成一套候选，每套目标为冲刺型 2 家、匹配型 3 家、保底型 3 家，
合计最多 16 家，并显示期刊身份、公开目录等级、本地分区证据、学校要求核验状态、投稿准备
时间状态和期刊主页。分组会参考论文内容与
专业方向、文章类型、结构准备状态、投稿语言、论文用途、完成投稿截止日期、开放获取偏好及已
核验的学校正式要求。

有可靠证据表明文章类型、主题范围、投稿语言或出版社业务方向不适配，以及被已核验正式规则
判定为不合格的期刊，不会进入任何推荐组。文章类型资料未列出仅表示待核验，不等同于期刊明确
不接收；系统优先展示已有正向支持证据的候选。若合格候选不足，系统显示实际数量，不会跨层级或用不合格期刊
补足。系统先考虑论文与期刊、出版社业务方向和投稿条件的适配，再以
本地分区证据校准相对层级并避免明显倒挂；分区不会单独决定推荐组。“保底型”表示门槛与投稿
准备条件相对可行，不代表保证录用。没有可靠的录用率、平均首轮审稿
速度或发表周期证据时，应用不会生成相关结论。所有分组都需要在投稿前核对期刊官网。

推荐结果分别以“中国期刊与出版社”和“全球期刊与出版社”两张靶图呈现：靶心是冲刺型，
中间环是匹配型，外环是保底型。图上的 `R1–R2`、`M1–M3`、`S1–S3` 与右侧期刊和出版社
资料逐项对应，点击任一坐标可定位清单项。环层只表达本次投稿组合中的角色，不是录用概率、
单一分区高低或内部评分；无论颜色是否可辨，坐标代码和右侧文字清单都保留完整信息。

### 9.5 回看推荐期刊与出版社

每次推荐生成成功后，完整结果会自动写入当前论文工作区，不需要手工保存。再次打开这篇论文并
进入“目标期刊”，页面顶部的“已保存推荐”会自动读取最近一次记录；也可按论文版本和生成时间
切换历史记录。每条记录保留国内、国外分组、期刊、出版社、目录来源与核验状态，但不向前端公开
内部评分和排序算法。旧结果不会因重新计算而被覆盖。点击候选中的“设为投稿目标”后，该期刊、
出版社、推荐运行和稿件版本才成为这篇论文的当前投稿计划，并在重新打开工作区后恢复。

### 9.6 主线、备选支线与官方要求

第一家期刊成为唯一当前投稿主线。之后可将其他候选加入有序备选支线；支线能够提前保存各自的
官方要求和准备状态，但不会被登记为并行投稿。把支线提升为主线前，必须选择“尚未投稿、已拒稿
或已完成撤稿”之一，切换原因和历史记录保存在本机。

尚未登记实际投稿时，可直接在已选期刊的推荐卡片中选择“取消主选期刊”，也可在投稿路线中选择
“取消当前主线”；阅读影响范围并二次确认后，再选择其他期刊。此操作只解除当前激活关系；推荐
记录、期刊要求快照、已上传附件、备选支线和不可变选择历史仍保存在本机。已经登记实际投稿的
主线不可取消，应先按真实状态处理投稿记录。
取消后，原有备选不会消失。系统把顺序中的第一条标为“建议下一主线”，但不会自动替换或登记
投稿；作者可以确认采用，也可以跳过它选择其他仍然合格的备选。

主线和每条支线分别提供“获取官方投稿要求”。作者每次勾选授权后，Rust 后端最多访问该期刊
官网和指南候选中的最多 4 个页面，每个响应不超过 2 MB；默认 HTTPS，HTTP 与跨域需逐次确认。
不会发送论文、作者身份或
本地资料。系统只保存来源网址、页面指纹、获取时间、短证据摘录和结构化要求，不保存整页副本。

如果官网依赖脚本、阻止访问或没有可识别说明，可粘贴官方作者指南原文并确认来源。只有得到
至少一项带来源的要求且没有待补充的获取失败后，系统才把清单标记为“期刊专属”；
部分成功保持“需人工补充”，超过 90 天会提示重新核对。自动抽取
不能替代作者在最终投稿前阅读官网原文。

要求快照会尽可能把摘要、标题、正文、引言、方法、结果、讨论和结论的篇幅限制拆成独立条目，
并保留对应的短证据摘录。报告规范清单、图片授权、版权协议、作者协议及其他附件会进入“支持文件”组。
系统可自动核对“是否存在”的项目；无法可靠判断适用性、格式或事实真伪的项目必须由作者人工确认。

### 9.7 上传图表与其他附件

“投稿资料”顶部使用四个切换按钮控制当前内容：

- 准备概览：默认视图，显示准备树、文件数和必需项进度；
- 要求清单：只显示当前期刊的动态要求、证据和作者确认；
- 上传资料：只显示按文件类型组织的上传入口；
- 已存文件：集中管理是否纳入组包、替换和删除。

每个按钮保留对应数量，页面一次只展开一个区域，避免同一附件同时在多组长列表中争夺注意力。
可以使用左右/上下方向键切换，`Home` 和 `End` 跳到首尾视图。

进入“投稿资料”后，“图表文件”提供两个独立入口：图片从“选择图片文件”上传，表格从“选择表格文件”上传。
只要主稿中检测到图或表，即使期刊作者指南没有把它们单列为上传项，这两个入口仍会保留。每个动态清单项也会
显示当前类别接受的格式：

- 原始图件：PDF、EPS、PS、SVG、PNG、JPG、TIFF；
- 可编辑表格：CSV、TSV、XLS、XLSX、ODS、Word、RTF、TEX；
- 源工程：ZIP、TAR、GZ、TGZ；匿名主稿：DOC、DOCX、ODT、RTF、TEX、PDF；
- 参考文献：BIB、BBL、RIS、NBIB、ENW、XML、Word、RTF、TXT；
- 投稿信、标题页和声明：DOC、DOCX、ODT、RTF、TEX、PDF、TXT；
- 补充材料与其他附件：上述文档、表格与图片格式，以及演示文稿、压缩包、常见音视频和科研数据文件。

“常见投稿附件”区始终提供按需入口，包括：

- 标题页与作者信息页；
- 投稿信；
- 伦理、知情同意、利益冲突、资金、数据可用性、作者贡献和 AI 使用等声明文件；
- BIB、RIS、NBIB、EndNote、XML 等可编辑参考文献文件；
- 附录、扩展方法、研究数据、代码归档、演示或音视频等补充材料；
- 情况说明、回复信、报告规范清单、版权或图片许可、作者协议及其他支持文件。

这些常见入口默认标为“可选”，方便作者提前整理，但不会假设每家期刊都要求同样的文件，也不会增加必需项计数。
如果当前期刊的官方作者指南明确要求同一类文件，常见入口会让位于带来源、义务强度和证据摘录的动态清单项；此时
以动态清单为准。该动态项不仅显示在“要求清单”，也会同步进入“上传资料”中的“当前期刊与主稿附件”，因此不必
来回切换页面寻找上传按钮。上传可选附件后，作者仍可在组包预览中决定是否纳入出版社目录。

“上传资料”完整汇总所有需要文件的清单项，并分成三组：原始图件与可编辑表格、当前期刊与主稿附件、常见可选
附件。完整 LaTeX 工程、匿名主稿以及期刊专属标题页、投稿信、声明、补充材料和其他支持文件不会再只出现在要求
清单中。已绑定文件的入口继续保留，并显示“添加或替换文件”，同名替换仍需作者明确确认。

页面顶部的“投稿包准备树”用于先看全局、再处理明细。根节点汇总当前计划组包的文件数、
未纳入文件、校验阻断和必需项进度；分支分别显示当前主稿、原始图件、可编辑表格、期刊必需
附件、声明与作者确认、可选支持资料。图件和表格分支把当前稿件结构扫描到的数量与已绑定的
独立文件数量并列显示，并提示缺少、多出或数量一致。

“数量一致”只说明扫描槽位数与已绑定文件数相同，不等于图片精度合格、表格可编辑，也不等于
满足期刊格式。最终仍应按下方带来源的动态清单逐项核验。结构尚未提取时计数为 0；应先在
“检查与修订”建立当前稿件结构，再回到资料页核对真实数量。

扩展名必须与真实文件内容一致。合法的 UTF-16 CSV/TSV 会以提示状态接收；如果名为 `.csv` 的文件实际是
Excel 二进制工作簿，系统会拒绝并指出真实类型。作者应把扩展名恢复为 `.xls`/`.xlsx` 后重新上传，或在 Excel
中另存为真正的 CSV。系统不会擅自转换可能影响数据精度、公式或工作表结构的科研文件。

上传前还会检查当前稿件版本、当前期刊和同一上传项中的文件名。发现同名文件时，系统弹出原生确认框并列出
名称；只有点击“替换已有附件”才会用新文件替换工作区副本，点击取消则不做任何改变。ManuscriptDock 外部的
原始文件始终不会被修改。本次同时选择多个同名文件时，由于无法判断采用哪一个，系统会要求只保留一个后重试。
内容哈希完全相同的重复文件不会再生成一份副本；发生实际替换时会重新校验文件、使旧目标检查失效并写入本地审计记录。

## 10. 本地存证（高级记录）

当前版本完成检查后，可以在“记录与高级功能”中主动创建本地存证；这不是投稿包导出的前置
门槛。如果作者直接完成真实投稿并登记，系统会在缺少存证时自动创建。记录绑定：

- 当前论文版本和 SHA-256；
- 当前检查报告；
- 作者确认时间；
- 存证记录自身的 SHA-256；
- 外部传输状态。

本地存证只证明“这台设备在该时间保存了这组相互绑定的对象”，不证明科学结论为真，也不
等同于区块链确权、公证或可信第三方时间戳。

## 11. 生成投稿包并登记投稿

### 11.1 导出投稿交付包

先在“投稿资料”补充期刊实际需要的源工程、匿名稿、原图、可编辑表格、参考文献、投稿信、标题页、声明、
报告清单和补充材料，逐项确认篇幅与格式；材料完成后进入独立的“检查与修订”步骤，完成与当前版本和
目标期刊绑定的检查，再到“投稿包”点击“选择导出文件夹”。目标检查不会作为缺失材料出现在上传清单中。
每个附件都会绑定当前稿件版本、目标期刊、官方要求快照和具体上传项。进入“投稿包”后，先在“导出前组包预览”
逐项核对文件用途、包内路径、上传项、纳入状态、校验提示和指纹；可选附件可以取消纳入，必需附件取消后会阻断导出。
旧版本、旧目标或旧要求的附件不会自动混入当前包，一个附件也不会同时冒充多个必需上传项。

“已保存的附加文件”支持删除工作区内的附件副本。删除前必须二次确认，原始外部文件不会受影响；删除后对应上传项会
立即重新计算，必需文件可能恢复为“缺失”。作者可从同一清单项重新选择正确文件，新增和删除操作都会写入本地审计记录。

双盲投稿不是默认设置。只有官方作者指南明确要求匿名投稿时，系统才把独立匿名稿作为上传主稿，并保证实名源稿不进入
`submission/`；要求不明确时只提示人工核验，不自动切换。目标要求、必需资料、组包预检或当前检查任一未完成时，
Rust 后端会拒绝导出。包内 `submission/` 只包含供出版社选择上传的主稿与真实附件；`records/` 保存目标选择、官方要求
快照、检查报告和带逐文件 SHA-256 的组包清单，只供作者本地核验，不应上传。旧的 JSON/HTML/
存证合集称为“内部审核档案”，不再冒充出版社投稿文件。这是本地写入，不会自动上传网络。
导出文件夹以原稿文件名命名，格式为 `<论文名>-submission-v<版本>`；目标期刊不会再取代论文名，
但仍完整保存在 `records/target-selection.json` 和包内说明中。

当前“预览”指文件装配预览，不是论文实页预览。PDF、Word、LaTeX 的本地实页渲染，以及修订版本的页面并排与可视化
差异，属于下一阶段能力；现有结构比较不会冒充版面对比。

### 11.2 在外部系统投稿

打开期刊、会议或预印本平台的真实网站，由作者自行登录、核对最新要求并上传文件。
ManuscriptDock 当前不保存期刊账号，也不代替作者点击最终提交。

### 11.3 登记投稿结果

回到应用，核对已保存的目标期刊，填写可选稿件号或回执，勾选“我确认已经完成投稿”，再点击
“登记投稿记录”。该操作只保存在本机，不向平台发送数据；若当前版本尚无存证，会自动创建。

## 12. 固化学术知识体（高级功能）

完成投稿登记后，先逐条审核本机分解出的 Claim、Scope、Method、Result 与 Evidence。
这里的 Claim 是论文希望成立、可被证据支持或反驳的核心命题，包括主要贡献、发现、结论或综述形成的
系统性判断，不是摘要的截短版，也不是“本文提出一种方法”这样的动作描述。方法动作进入 Method，观察
进入 Result，支撑材料进入 Evidence，适用条件进入 Scope。系统不会再用摘要最长句强行填充 Claim；
当源稿没有形成可靠核心命题时会保持 `pending`，由作者核对，而不是生成看似完整的空洞总结。
每条候选必须选择“纳入知识体”或“排除”：

- 纳入项在整组审核确认后从 `candidate` 升级为 `established`；
- 排除项保留来源与审核决定，但不会显示为作者确认的知识；
- 候选缺失的要素保持 `pending`，应用不会用占位内容补齐；
- 未完成全部候选决定或未勾选作者审核声明时，不能固化知识体。

“身份与版本”不属于上述研究语义候选。应用会从论文源稿的标题页、作者区和通讯信息区
提取并直接显示论文标题、作者、作者单位、电子邮箱、ORCID 或通讯信息，同时标注
ArtifactVersion、Snapshot 和来源片段。这些字段来自源稿已经明示的信息，因此不会被
“排除”按钮隐藏；识别不到时会明确显示“未可靠识别”。这些内容当前仍只保存在本机。

随后选择主要学科。当前分类完全由作者确认，使用
`ManuscriptDock Discipline Index v1.0`；系统不会根据标题或摘要自动替作者决定。

点击固化后，应用创建不可变知识体快照，并显示：

- KnowledgeBody 稳定标识；
- 完整 64 位知识体 SHA-256；
- `ClassificationAssignment` 分类及版本；
- ArtifactVersion、Claim、Scope、Method、Result、EvidenceRelation、SourceAnchor、
  Provenance、AIReviewReport 和 KnowledgeBodySnapshot 的版本状态；
- 身份与版本、知识边界与证据、能力契约、交互运行时、验证权利与信誉五部分架构。

知识体主操作区直接显示动态点云和关联网络，不需要先打开“查看依据”。点云围绕 Claim
十二面体缓慢运动；“身份与版本、知识边界与证据、能力契约、交互运行时、验证权利与信誉”
五个节点都可以点击或用键盘选择，并在图内显示该层的版本与内容摘要。启用系统“减少动态
效果”后，视图保持固定投影。图下方的“知识命题与来源”逐项展示 Claim、Scope、Method、
Result、Evidence 的实际文本摘要、确认状态、来源片段和置信度；这些文字直接来自当前分解
资产，不是图例占位文案。“查看依据”只保留只读哈希、版本和审计信息。

本机展示身份与联系方式不会改变模型隐私边界。默认知识体问答投影不包含
`SourceIdentityVersion`，并会继续删除作者姓名、邮箱、电话和身份标识。未来对外发布身份
信息需要独立的发布授权，不能沿用一次模型问答授权。

当前 `AIReviewReport` 可以为空。未来 PWC 评审形成新审核版本时，知识体快照必须引用具体
版本，不会悄悄覆盖历史。

## 13. 使用自己的大模型询问知识体

### 13.1 配置模型

应用顶部始终提供“模型设置（Models）”入口，无需先导入论文，也无需等到知识体固化。期刊
资料发现、学校规则抽取和知识体问答共用同一份全局配置。知识体问答台仍会显示当前可用模型
数量，并可打开同一份设置。固定提供：

1. 主模型；
2. 备选模型 1；
3. 备选模型 2。

为需要启用的槽位填写提供方名称、OpenAI Chat Completions 兼容 API 地址、模型名称和
API Key，再点击“保存模型设置”。远端地址必须使用 HTTPS；只有 `localhost`、
`127.0.0.1` 和 `::1` 可使用 HTTP。

API Key 在 macOS 保存到 Keychain，在 Windows 保存到 Credential Manager。应用界面不会
回显明文 Key，工作区、问答账本和 Git 仓库也不会保存 Key。同一次应用运行中，每个已保存
Key 最多向系统凭据库读取一次；期刊资料发现、学校规则抽取和知识体问答随后复用 Rust 进程内
凭据，避免操作系统反复要求确认。应用退出后缓存随进程销毁。

关闭存在未保存修改的设置窗口时，应用会先要求确认；已经写入操作系统凭据库的 Key 不会因
放弃本次表单修改而删除。主动勾选“删除已保存的 Key”并保存后才会删除对应凭据。

### 13.2 发起问题

选择提问类型“认可 / 疑问 / 挑战”，再选择目标对象并输入问题。点击“询问知识体”即表示
授权执行本次模型请求。Rust 在网络出口删除结构报告和本地投稿档案中已知的作者姓名、邮箱、电话、长数字身份标识和
本机路径后，发送：

- 当前问题；
- 脱敏后的标题、摘要和章节轮廓；
- 学科、知识体哈希和快照版本；
- Claim 与其他版本化对象引用；
- 能力契约、知识边界、拒绝条件和权利信誉引用。

不会发送源文件或完整本机路径。模型回答不能自动修改 Claim 或知识体，只作为绑定当前快照
的不可变问答记录保存。主模型失败后依次尝试两个备选模型。

“外部反馈”当前只是预留入口，不接收网络用户，也不会伪造认可、疑问或挑战。

## 14. 管理最近工作区

首页“最近工作区”中，每篇论文都有独立管理菜单。

- 另存完整工作区：把该论文的源快照、版本、推荐期刊与出版社、检查、存证、投稿和知识体记录
  原子复制到作者选择的文件夹；
- 归档工作区：移入“已归档”，保留所有版本、报告、存证、投稿、知识体和问答；
- 恢复到最近工作区：恢复后继续处理；
- 永久删除：经过二次确认后删除整个本地工作区，应用内无法撤销。

每篇论文导入后，应用会在系统分配给 ManuscriptDock 的应用数据目录下创建独立工作区。首页显示
默认资料库位置，应用启动时自动从该位置读取。另存只生成独立副本，不移动默认资料库、不修改
外部原稿，也不会让前端获得任意文件系统访问权。

永久删除不会修改最初导入的外部原稿，也不会删除已经导出到其他目录的投稿包。需要保留的
研究记录应优先归档，并自行备份外部原稿和交付包。

## 15. 数据和网络边界

| 操作 | 是否联网 | 可能外发的内容 |
| --- | --- | --- |
| 导入、结构提取、规则检查 | 否 | 无 |
| 修订、版本保存、比较、恢复 | 否 | 无 |
| 普通期刊匹配 | 否 | 无 |
| 学校要求模型抽取 | 仅在作者确认后 | 学校名称、学科、用途、脱敏规则原文 |
| 期刊画像模型发现 | 仅在本地不足且作者逐次确认后 | 期刊名、已知出版社、公开主页、ISSN/EISSN |
| 本地存证 | 否 | 无 |
| 导出投稿包 | 否 | 只写入作者选择的本地目录 |
| 投稿登记 | 否 | 无；只记录作者已完成的外部投稿 |
| 知识体固化 | 否 | 无 |
| 知识体问答 | 每次点击提问后 | 脱敏知识体投影和脱敏问题 |

任何模型调用都通过 Rust 后端执行。作者姓名、联系方式、身份标识和本机路径不得进入外部
模型请求；学校名称只在学校要求抽取中按作者明确授权发送。

## 16. 常见问题

### 16.1 明明有标题、作者或摘要，为什么没有识别出来？

PDF 可能没有可读文本层、字体映射异常、采用多栏布局或实际是扫描图像。先查看右侧警告和
候选页；当前版本没有完整 OCR 运行时，优先改用 DOCX/TEX 源稿或人工核对。

### 16.2 为什么保存修订后又要求检查？

检查、推荐、存证和知识体都绑定具体版本。任何新版本都不能继承旧版本结论，重新检查是为了
避免把旧证据误当成当前状态。

### 16.3 为什么期刊推荐显示“候选初筛”？

通常表示学校正式规则尚未核验，或所需评价目录没有合法、固定版本的数据。未核验条件不会被
当成零分，也不会让模型猜测。

### 16.4 模型返回 HTTP 402 怎么办？

通常表示提供方余额、套餐或计费状态不可用。检查账户余额与 API 计费，或配置可用的备选模型。

### 16.5 模型设置显示地址错误怎么办？

确认填写的是 API 基础地址而不是文档网页，并确认模型名称真实存在。远端服务必须使用 HTTPS。

### 16.6 为什么模型不能回答主要 Claim？

如果 Claim、Proposition、Scope 或 Evidence 仍是 `pending v0`，知识体没有足够事实依据。
模型必须说明缺少什么，不能用摘要冒充已建立的 Claim。需要先完成语义提取和作者确认；未来
专业 AI Review 由 PWC 提供。

### 16.7 删除工作区后能恢复吗？

不能。永久删除不经过应用回收站。归档可以恢复，删除只能依靠作者自行保存的外部原稿或备份。

## 17. 当前版本限制

- 完整中英文 OCR、公式识别和表格结构识别运行时尚未随安装包交付；
- PDF 不能直接修订；DOCX/TEX 只开放有限的安全字段；
- 尚未实现完整自动排版和每本期刊的全部格式差异；
- 期刊推荐不是录用率预测，当前论文实力信号以结构准备程度为主；
- PWC `AIReviewReport` 尚未接入单机流程；
- 不自动登录或提交到期刊、学校、预印本或评价目录服务；
- 知识体外部提问入口、公共发布和跨知识体网络尚未开放；
- 当前开发安装包尚未完成公开发行所需的 macOS 公证和 Windows 代码签名。

## 18. 重要概念

- **工作区**：一篇论文在本机的版本、报告、存证、投稿和知识体数据边界。
- **源快照**：导入时生成的不可变论文副本。
- **内容指纹**：用于校验文件内容的 SHA-256。
- **规则包**：可组合、带完整性校验的投稿标准或出版社基线。
- **本地存证**：作者确认的一组本地版本与报告记录，不等同于公证。
- **知识体**：围绕 Claim 构成的、可追溯、可版本化且具有能力边界的研究记忆单元。
- **知识体快照**：固定引用一组具体对象版本的不可变组合。
- **AIReviewReport**：审核抽取忠实性和结构边界的独立版本对象；当前由未来 PWC 服务提供。
