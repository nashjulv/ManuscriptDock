# ManuscriptDock UI 视觉方案

- 版本：1.4
- 状态：已确认 / MVP 实施基线
- 产品：ManuscriptDock（投稿舱）
- 参考样本：PWC 个人工作台的发布中心与原创投稿流程
- 适用范围：Tauri 桌面端；未来 iOS 伴随端按相同语义降维适配

## 1. 视觉结论

ManuscriptDock 采用“安静的学术操作台”视觉方向。桌面 MVP 以 PWC `/workspace/publish` 的实测布局、灰阶、间距和图标语言为基线；针对本地长时间阅读场景，字号整体上调约 1px，按钮高度与圆角轻微增加。所有绿色主按钮统一使用 `#A6CE39`。

直接采用的 PWC 页面规则包括：

- 扁平、低装饰的应用框架；
- 56px 顶栏、48px 任务轨道、574px 主工作面和自适应右侧面板；
- `#FAFAFA / #F5F5F5 / #F0F0F0` 三层灰阶、细分隔线和无投影框架；
- 左侧完成输入与操作，右侧持续显示预览、检查依据和处理状态；
- 表单按任务分组，以细分隔线代替大量卡片；
- 主操作固定在流程末端，草稿和取消保持次级；
- 高信息密度下仍保持稳定的网格与留白。

ManuscriptDock 必须强化的差异是：

- 持续显示“本机 / 需要联网 / 将要外发”边界；
- 原稿、生成版本和不可变快照具有明确身份；
- 确定性提取、规则检查与 AI 建议使用不同来源标签；
- 右侧不是装饰性预览，而是可追溯的“证据面”；
- 键盘焦点、可访问名称和状态文字不因视觉对齐而删除；
- 论文最终形成可持续演进的学术知识体，而非一次性表单记录。

### 1.1 品牌图标

统一品牌图标采用“论文折成一半的纸飞机”，以白底、`#A6CE39` 绿色机翼和
`#5B5956` 深灰蜡笔线条组成。纸张折线形成一个隐含的 `M`；下方两条横线保留论文
语义，纸飞机表达投稿动作。图标不单独显示字母 `M`，也不与 PWC 标志混用。
桌面应用图标将图形主体缩放至白色画布的约 82%，依据图形实际边界水平、垂直居中，
确保 Dock、Finder 和安装器中均保留稳定安全留白。

可编辑 SVG 母版为
`design-system/manuscriptdock/manuscriptdock-folded-paper-editable.svg`。应用顶栏、浏览器
入口、macOS `icns`、Windows `ico`、Linux PNG、Android 与 iOS 图标均从同一母版同步，
避免出现多个形状和颜色版本。顶栏同时保留“投稿舱 ManuscriptDock”文字名称；图标
作为装饰隐藏于辅助技术，防止品牌名重复朗读。

## 2. 保留的产品边界

以下元素不进入 ManuscriptDock 桌面端：

- 面向整个网站的全局业务导航、消息中心和机构入口；
- 链上存证、平台分发等 PWC 中央端术语直接占据个人工作区；
- 启动时强制出现身份绑定提示；
- PWC 商标、站点导航、账户头像和机构业务入口；
- 装饰性渐变、营销式状态表达和与投稿无关的站点能力；
- 以“提交”隐藏数据实际发送对象和快照范围。

PWC 是未来机构与集团中央端；ManuscriptDock 是作者控制的数据对接端。两个产品需要家族相似性，但不能看起来是同一套后台页面。

## 3. 应用框架

### 3.1 桌面窗口

```text
┌──────────────────────────────────────────────────────────────┐
│ 56px 产品栏：论文名称 / 本机状态 / 同步边界 / 全局操作          │
├────┬───────────────────────────┬─────────────────────────────┤
│48px│ 操作面                    │ 证据面                      │
│任务│ 固定 574px                │ 自适应                      │
│轨道│ 表单、修复、版本操作       │ 原文、预览、依据、差异、状态 │
├────┴───────────────────────────┴─────────────────────────────┤
│ 可选固定操作栏：保存本地快照 / 下一步 / 外发前确认              │
└──────────────────────────────────────────────────────────────┘
```

- 产品栏高度 56px，水平内边距 24px，不使用投影；
- 任务轨道宽 48px，图标按钮视觉尺寸 36px、圆角 6px，并提供可访问名称；
- 操作面承担当前步骤，不同时展开多个长表单；
- 证据面默认只读，显示原文、输出预览、规则来源和差异；
- 桌面宽屏主操作面固定 574px，证据面自适应；两者以 `#E0E0E0` 1px 边界分隔；
- 论文、版本和附件从任务轨道打开侧屉，不再永久占用第三栏。

### 3.2 宽度适配

| 窗口宽度 | 布局 |
| --- | --- |
| `>= 1180px` | 完整双面板，操作面与证据面并列 |
| `960–1179px` | 紧凑双面板，操作面固定约 44%，证据面自适应 |
| `< 960px` | 单面板，“操作 / 证据”页签切换，保留上下文和滚动位置 |
| `< 768px` | 伴随端布局，不承载完整论文排版编辑 |

桌面端建议最小窗口为 `760 × 640px`；低于 960px 时不得硬压缩成不可读的三栏。

## 4. 页面模式

### 4.1 开始页

使用与 PWC 发布中心一致的左右工作面：首页左侧为导入动作与两张 247px 任务说明卡，右侧为五步投稿指引。最近论文是安静的次级列表，不建立仪表盘式统计墙。

主要信息顺序：双语品牌声明 → 导入论文 → 本机安全说明 → 最近论文。

首页品牌声明固定同时显示中文与英文，不随界面语言开关隐藏其中一种语言，并使用独立行、字号和 `lang` 属性区分：

```text
投稿舱 ManuscriptDock
本地论文投稿准备工作台
Local-first manuscript submission workspace.

投论文，上更好的期刊
Go for Better Journals.
```

中文名称和口号是中文市场的主阅读层；英文名称、定位与口号是国际识别层。顶栏固定采用“投稿舱 ManuscriptDock”的顺序，避免把“Submission Dock”当成第二个英文品牌名。

首页“传输可见”的用户承诺统一为“你自主决定是否联网、使用模型和外部投送”，强调控制权属于作者；具体发送对象、数据范围和目的继续在实际动作前说明。

### 4.2 导入与结构确认

- 操作面显示文件身份、解析方式、结构字段和人工确认入口；
- 证据面显示 PDF 页面或原文定位；
- “未检测到”必须与“论文中不存在”区分；
- OCR、字体编码限制和页数异常均显示原因、进度与恢复办法。

### 4.3 投稿准备

沿用 PWC 发布流程的分步结构，但改为个人作者语言：

```text
原稿确认 → 本地版本 → 结构与元数据 → 目标规则 → 格式与声明 → 投稿包
```

步骤可以返回和保存，不以线性流程锁死用户。每一步只出现当前任务所需字段。

### 4.4 检查与修复

操作面显示问题、依据和修复选项；证据面显示论文定位与修改前后差异。确定性检查和 AI 建议分别标注，不合并为一个神秘总分。

### 4.5 投稿包与 PWC 对接

完成页直接呈现：已生成内容、仍需确认事项、可以执行的下一步。任何发送给 PWC、模型服务或预印本平台的动作，都先打开统一的外发确认面板。

| Surface Subtle | `#F0F0F0` | `--md-surface-subtle` | 轨道选中与任务说明卡 |

使用规则：

- 主要按钮使用可信绿色，不使用纯黑品牌按钮；
- 所有绿色按钮，包括“开始结构提取”及其处理中状态，统一使用 `#4A4846` 文字与图标；不再保留白色文字特例；
- 绿色只表示 ManuscriptDock 的可信主动作、本机安全和通过状态；
- 状态同时包含图标、文字与颜色，不能只显示彩色圆点；
- 页面背景与工作面保持细微层级，不使用玻璃拟态或渐变；
- 阴影仅用于菜单、模态框和拖拽中的浮动对象。

## 6. 字体与层级

全部应用界面使用苹方细体，运行时不下载远程字体。Windows 使用系统细体作为等效回退：

```css
"PingFang SC", "PingFang HK", "Microsoft YaHei UI Light",
"Segoe UI Light", sans-serif;
font-weight: 300;
```

学术感通过字号、位置、间距和灰阶表达，不混用粗体、衬线体或等宽字体。嵌入的原始论文页面保持其不可变源字形，不属于应用 UI 字体替换范围。

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Meta | `10–11 / 16–17px` | 300 | 技术标识与极短元数据 |
| Label | `12–13 / 18–19px` | 300 | 标签、来源和工作台标识 |
| UI Body | `14 / 21px` | 300 | 表单、列表和卡片标题 |
| Reading Body | `15 / 22.5px` | 300 | 全局正文基线 |
| Section | `17 / 25px` | 300 | 面板分组标题 |

- 中文标题不使用全大写或宽字距；
- 数字、版本号和计数继续使用苹方细体，通过布局对齐而不是切换等宽字体；
- 关键说明不低于 13px；触控端正文不低于 16px；
- 文本层级依赖字号、间距、位置和颜色；不通过混用字重破坏细体的一致性。

## 7. 间距、形状与层级

采用 4px 基础网格：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 48`。

| 元素 | 规范 |
| --- | --- |
| 产品栏 | 56px 高，水平内边距 20–24px |
| 任务轨道 | 48px 宽，按钮视觉 36px、6px 圆角；图标 20px、2px 描边 |
| 字段 | 36–40px 高，4–6px 圆角，命中区至少 44px |
| 主要按钮 | 30px 高、6px 圆角、水平内边距 11px、`13/19px` 字体；绿色为 `#A6CE39` |
| 面板 | 0–8px 圆角；并列工作面通常无圆角 |
| 分组 | 20–24px 垂直间距，以 1px 分隔线结束 |
| 发布指引卡 | 64px 高、6px 圆角、12px 内边距、8px 垂直间隔 |
| 双列任务卡 | 单卡 247px 宽、至少 172px 高、20px 内边距、10px 圆角 |
| 模态框 | 8–10px 圆角，唯一使用明确投影的常规组件 |

避免把每个区域包装成圆角卡片。页面骨架靠网格、细边框和留白建立，而不是靠阴影堆层级。

## 8. 核心组件

### 8.1 产品栏

左侧显示当前论文和返回路径；右侧依次显示本机状态、联网边界、同步或外发动作。外发动作与普通保存不能使用相同文案。

产品栏右侧固定提供“中文 / EN”分段式语言切换。中文是首次启动默认语言，用户选择保存在本机；切换不刷新工作区，也不改变原稿、文件名、论文标题、章节名或作者内容。

### 8.2 任务轨道

“我的工作台”是应用级入口，常态固定为左侧任务轨道第一项；在入口页显示当前状态，进入任意论文阶段后仍保持可见，并可直接返回最近工作区列表。它与论文级任务之间使用一条 20px 的细分隔线，避免把“工作台”和“原稿”误认为同一层级。

论文级 MVP 顺序为：原稿、版本、结构、目标、修订、检查、投稿包、知识体。知识体入口从首版可见但保持次级，用于表达终点，不提前展开复杂网络功能。

### 8.3 分步进度

使用数字、名称和状态文字。已完成、当前、需要确认、阻断四种状态必须同时有形状或图标差异。步骤允许回退并保持本地草稿。

### 8.4 表单分组

字段使用始终可见的标签，不以 placeholder 代替。每组顶部是短标题和必要说明，组间使用 1px 分隔线；高级选项默认折叠。

### 8.5 证据面

证据面顶部固定显示当前对象和来源；主体根据任务切换为 PDF 页面、输出预览、规则依据、差异或审查状态。所有问题都能从证据面定位回原稿。

### 8.6 状态行

标准结构为：`图标 + 检查名称 + 来源 + 状态文字 + 查看依据`。禁止用单独的通过率或彩色点代替状态说明。

### 8.7 固定操作栏

从左到右依次为取消或返回、保存本地草稿、主要下一步。涉及外发时，按钮必须写明目标，例如“确认并发送至 PWC”，不能只写“提交”。

### 8.8 知识体空间视图

- 顶部使用“单一知识体 / 两体关联 / 关联网络”三级页签渐进展开；真实对象不足时后级不可用并说明原因；
- 单体外圈标注 `KnowledgeBodySnapshot · Sx`，表示固定全部对象具体版本的不可变边界；
- 中心使用由 20 个顶点、30 条边构成的线框十二面体承载 Claim，不引入 WebGL 或重型图形依赖；
- 十二面体以约 48 秒一周的速度进行真实三维投影旋转，表达多视角检查而非装饰性动效；
- `ArtifactVersion`、`Scope`、`Method`、`Result`、`EvidenceRelation`、`SourceAnchor`、`AIReviewReport` 和 `Provenance` 八个对象围绕中心稳定分布，各由一条空间直线直接连接 Claim；
- `EvidenceRelation` 使用绿色菱形，表明它是有依据的内部关系对象；其余外围对象使用球体；
- 每个对象必须直接显示自己的版本号；`AIReviewReport` 可显示当前版与保留历史版，`v0` 表示尚未正式建立；
- 已建立要素使用 `#A6CE39` 实线边界，待建立要素使用灰色虚线并显示文字状态；
- 视图必须提供完整文本摘要，不能依靠空间位置、动画或颜色传达唯一信息；
- `prefers-reduced-motion` 下停止旋转并保持十二面体的可辨识静态投影视角。
- 两体和网络视图使用浅灰圆形边界表示各知识体仍保持独立身份、版本和权限边界；
- 跨体连接的中点使用 `#A6CE39` 菱形表示一等声明对象，同时显示关系语义、协议对象和版本；
- 没有成立依据的相似度边不得显示为正式关系；完整协议以[学术知识体关联网络模型](knowledge-body-network-model.md)为准。

## 9. 状态与反馈

| 状态 | 表达方式 |
| --- | --- |
| 本机处理 | 盾牌或设备图标 + “仅在本机” |
| 确定性结果 | 规则图标 + “确定性提取 / 规则检查” |
| AI 建议 | 星形或模型图标 + “AI 建议，待作者确认” |
| 处理中 | 进度、当前阶段、可取消或后台继续 |
| 需要确认 | 警示图标 + 具体问题 + 恢复动作 |
| 已生成 | 对勾 + 版本或快照编号 + 查看入口 |
| 将要外发 | 发送图标 + 接收方 + 数据范围 + 确认入口 |
| 失败 | 原因 + 未受影响的数据 + 重试或替代路径 |

- 操作在 100ms 内提供按下反馈；
- 超过 300ms 的处理显示加载或骨架；
- 长任务显示阶段、进度和取消能力；
- 提交类操作依次显示处理中、成功或失败，不允许无反馈；
- 切换“操作 / 证据”或返回上一步时恢复滚动、选区和表单状态。

## 10. 无障碍与平台要求

- 普通文字对比度至少 4.5:1；大文字至少 3:1；
- 所有流程可以仅用键盘完成，焦点顺序与视觉顺序一致；
- 图标按钮具有可访问名称、可见键盘焦点和明确选中状态；
- 表单错误出现在对应字段附近，并在汇总区提供跳转；
- 不依赖悬停显示唯一信息；
- 动画限制在 150–250ms 的透明度或位移，并支持减少动态效果；
- 验证宽度为 `760 / 960 / 1180 / 1440px`，伴随端另验证 `375px`；
- Windows 与 macOS 保留系统窗口行为，不仿制另一平台的标题栏控件。

### 10.1 中英文界面

- 导航、按钮、状态、帮助、空状态、错误恢复、结构结果、检查结果、知识体视图以及可访问名称均提供中文和英文；
- 语言切换使用语言自身名称“中文 / EN”，以 `aria-pressed` 表达当前选择，并同步更新页面 `lang`；
- Rust 本地引擎产生的内置规则名称、固定检查说明、解析警告和可恢复错误由界面层提供英文映射；
- 论文内容与作者数据遵循原文原则，不把语言切换误解为论文翻译；
- 英文文案以简短、可操作和不溢出为标准，不把中英文同时塞入每一行；
- 两种语言复用同一信息架构、权限边界和功能，不允许出现仅中文可完成或仅英文可完成的路径。

## 11. MVP 实施顺序

1. 将导入页收敛为 PWC 实测的 56 / 48 / 574 桌面骨架和统一 Token；
2. 建立任务轨道与“操作面 / 证据面”响应式骨架；
3. 把结构提取结果改为可定位、可确认的证据行；
4. 建立分步投稿准备、固定操作栏和本地草稿反馈；
5. 统一确定性结果、AI 建议、PWC 外发和知识体状态语言；
6. 完成键盘、对比度、窄窗口以及 macOS / Windows 视觉回归。

- [ ] 本机、联网和外发状态在动作发生前可见；
- [ ] 确定性检查与 AI 建议具有明确来源；
- [ ] 表单标签、加载、成功和失败反馈完整；

- [ ] 不存在依靠颜色或悬停传达的唯一信息；
- [ ] 不使用远程字体、装饰脚本或不必要阴影；
