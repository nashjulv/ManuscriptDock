# 期刊匹配与投稿目标推荐

## 功能定位

期刊匹配位于“版本”与“存证”之间，用于根据当前论文版本、作者填写的投稿背景、选择的投稿条件和本地期刊目录生成投稿候选。它不预测录用结果，也不替代期刊官网的最新作者指南。

当前版本聚焦计算机与人工智能，国内和国外期刊分别生成冲刺型 2 家、匹配型 3 家、保底型 3 家，合计最多 16 家。稿件版本或投稿条件变化后可以重新生成，旧记录保留为本地历史。

## 使用流程

1. 保存投稿人姓名、学校或机构、学院或专业、论文用途和完成投稿截止日期。
2. 可选导入一个或多个本地 `.xlsx` 期刊目录，用于离线核对候选。
3. 可选粘贴学校正式要求，并提供官方 HTTPS 来源。
4. 选择研究方向、文章类型、投稿语言、目标策略和开放获取偏好。
5. 分别生成国内和国外 2/3/3 分层候选，查看目录证据、学校要求核验状态、准备时间状态和期刊主页。
6. 选择唯一投稿主线，把其他候选加入有序备选支线。
7. 核对主线期刊画像：先查本机目录；本地不足时可逐次授权作者配置的模型寻找公开资料线索。
8. 逐次授权读取主线或支线的期刊官网，或粘贴并确认官方作者指南原文，形成各自的要求快照。

## 离线期刊目录

应用支持把用户有权使用的中科院分区、科睿唯安 JCR 和新锐分区工作簿同步到本机应用数据目录。各体系独立保存，不相互换算。

- 只读取工作簿中已经保存的单元格值；
- 不执行公式、宏或外部链接；
- 同一来源的新快照替换旧活动数据；被完整名单替代的不完整数据不进入活动数据库；
- 原始工作簿不会复制进安装包，也不会上传；
- 界面只展示与候选期刊有关的目录证据，不公开整表；
- 数据版本、来源哈希和导入状态保存在 Rust 后端；
- ISSN、EISSN 分字段保存并建立索引，优先用于跨来源身份归并，规范化刊名只作为回退；
- 出版社、发表方向、年度发文量、评审方式、审稿速度、投稿至发表周期、发行量、费用、OA 和
  来源证据作为可空比较字段保存；缺失不解释为零、免费、不支持或速度慢。

中科院分区表及 JCR 派生数据应在用户自身授权范围内使用。新锐分区作为独立的用户提供数据体系显示，不等同于中科院分区或 JCR Quartile。

## 本地不足时的模型发现

模型发现是所选期刊的资料补全入口，不参与初始推荐排序。系统先查询本机数据库；只有本地缺少
基本画像并且作者确认本次发送范围时，才调用已经配置的大模型 API。请求只包含公开期刊身份：
期刊名称、已知出版社、公开主页和本地已有的 ISSN/EISSN，不包含论文、附件、作者、学校、
工作区标识、推荐分数或内部算法字段。

返回值始终标记为“待官方核验的模型线索”，单独保存在当前论文工作区并记录提供方、模型、时间
和外发范围。它不会自动合并进全局本机目录，不会变成分区证据、录用概率或推荐分数。发行量、
审稿速度和投稿至发表总周期是不同字段；模型没有可支持信息时必须保留为空。正式投稿要求仍以
期刊官网快照或作者确认的官方原文为准。

## 学校正式要求（可选）

作者可以粘贴研究生院、科研管理部门或学院发布的正式要求。若选择模型结构化抽取，应用会在执行前要求逐次确认发送范围。

允许发送的内容仅限学校名称、学科或专业、论文用途和脱敏后的规则原文。作者姓名、来源网址、联系方式、身份标识和论文正文不发送；来源网址只保存在本机作为核验依据。

没有正式来源或尚未完成核验时，结果显示为“候选初筛”。模型不会根据训练记忆补写学校政策。

## 候选结果

- 国内期刊：冲刺型 2 家、匹配型 3 家、保底型 3 家；
- 国外期刊：冲刺型 2 家、匹配型 3 家、保底型 3 家；
- 冲刺型目标标准较高、竞争通常更激烈；匹配型强调内容与投稿条件契合；保底型强调相对门槛和准备可行性，但不表示保证录用。

有可靠证据表明文章类型、主题范围、投稿语言或出版社业务方向不适配，以及被已核验正式规则判定为不合格的期刊，不会进入任何推荐组。文章类型资料未列出只表示待核验，不等同于期刊明确不接收；系统优先展示已有正向支持证据的候选。若某一地区合格候选不足，结果显示实际数量，不以不合格候选补足。
系统先考虑论文与期刊范围、出版社业务方向及投稿条件的适配，再以本地分区证据校准相对层级并避免明显倒挂；分区不会单独决定推荐组，对应候选不足时也不会跨层强行补足。

## 推荐档案与回看

推荐生成后立即写入当前论文工作区的 `analysis` 区域，并绑定论文版本、内容指纹、投稿背景档案、
目录版本和生成时间。作者再次进入该论文的“期刊匹配”时，应用读取最近记录，并在“已保存推荐”
中提供历史切换。档案完整保留期刊与出版社字段；重新计算创建新记录，不覆盖旧结果。

Rust 读取完整记录后只向 WebView 投影期刊、出版社、分组、公开目录证据及核验状态。评分构成、
权重、阈值、排序理由和算法版本仍不跨越后端边界。

分组参考论文主题与专业方向、文章类型、结构准备状态、投稿语言、论文用途、截止日期、开放获取偏好、期刊公开目录证据以及已核验的学校正式要求。学校和导师声望不作为论文质量或期刊层级的代理。

每个候选可以显示：

- 期刊中英文名称与出版社；
- 公开目录等级；
- 与该期刊匹配到的本地分区体系、年份、分区及 Top 状态；
- 学校要求是否已核验、候选是否满足已核验要求；
- 投稿准备时间是否充足；
- 期刊主页和目录来源链接。

## 投稿主线、备选支线和官方要求

`SubmissionTargetPlan` 只允许一个主线目标，并可保存最多 8 个按加入顺序排列的备选目标。
备选路线可提前取得官方要求并保存资料准备证据，但不会成为可登记的并行投稿。提升备选时必须
选择上一主线为尚未投稿、已拒稿或已完成撤稿；新主线形成新的目标记录，原选择和切换原因保留。
在尚未登记实际投稿时，作者也可以确认取消当前主线后重新选择。取消只解除当前激活关系，既不
删除不可变选择历史，也不删除已经保存的推荐、要求快照、附件和备选路线；已有投稿记录时不能取消。
取消后备选仍按作者保存的顺序显示，第一条标记为下一主线建议，但不会自动替换。作者可确认采用
建议，也可跳过前序备选选择其他合格路线；最终主线始终由作者明确决定。

每个目标选择独立保存 `JournalRequirementSnapshot`，包括来源网址、页面 SHA-256、获取时间、
90 天新鲜度、短证据摘录和结构化要求。抓到网页但没有识别出明确条目时保持“待人工核验”，
不能作为期刊专属清单。备选提升为主线时，其要求快照作为有来源的准备证据继承，同时保留刷新提示。

界面不显示内部算法版本、权重、阈值、总分、分项分、内部排序理由或并列规则。完整计算记录仅保存在 Rust 管理的本地审计档案中，前端只接收展示所需字段。

## 数据与网络边界

- 普通期刊候选生成在本机完成，不联网；
- 导入目录只读取作者选择的本地文件；
- 所选期刊画像先查本机；本地不足时的模型发现需逐次授权，且只发送公开期刊身份；
- 学校要求模型抽取只在作者本次明确确认后联网；
- 期刊作者指南读取只在作者本次明确确认后联网，只访问所选主页及其同站 HTTPS 链接，并限制
  页面数量、大小、跳转和地址范围；不发送论文或作者身份；
- 机构规则同步或官方目录接口仍需独立授权；
- WebView 不接收原始工作簿、完整目录、算法字段或本机文件路径。

## 结果限制

- 候选顺序用于投稿准备，不是录用概率、影响因子预测或同行评审结论；
- 当前候选池不代表所有学科或全球全部期刊；
- 分区、费用、范围、周期和投稿政策可能变化，投稿前必须核对期刊官网；
- 截止日期状态只表示本地投稿准备窗口，不预测审稿、录用、在线发表、见刊或数据库收录时间；
- 本地目录中的缺失值不会静默猜测；作者主动使用模型发现时，结果作为待核验线索与目录事实隔离；
- 国内目录等级与国际目录等级不会自动互相映射；
- 被已核验学校要求排除的候选会明确显示冲突状态，不代表该期刊本身质量较低。

## 验收要点

- 国内和国外分别可生成冲刺型 2 家、匹配型 3 家、保底型 3 家，最多 16 家且全局不重复；
- 文章类型、主题范围、语言、出版社方向或已核验规则不满足资格条件的期刊不进入推荐，候选不足时不强行补足；
- 稿件版本、投稿背景或推荐条件变化后可重新生成；
- 本地目录更新形成新活动数据，并从活动数据库剔除被完整名单替代的不完整来源；
- 未核验学校要求时明确显示“候选初筛”；
- 推荐页和 WebView 数据中不出现内部评分或排序算法字段；
- 普通推荐不发生外部传输；
- 结果始终提示投稿前核对期刊官网。
- 主线唯一，未投稿时可确认取消并保留历史；备选提升必须记录上一主线状态，且各路线的要求快照互不混用。
- 本地画像足够时不调用模型；本地不足、未获本次授权时在联网前停止；模型线索不进入推荐评分或全局目录。
