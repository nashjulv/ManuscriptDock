# 期刊匹配与投稿目标推荐

## 产品定位

期刊匹配是“版本”与“存证”之间的本地决策阶段。它不回答“哪本期刊一定录用”，而是基于当前论文版本、作者确认的投稿偏好和可核验的期刊目录快照，计算当前最适合的投稿组合。目的不是压低投稿机会，而是避免把创新性与证据强度不同的论文一概推向顶刊，并同时保留有理由的冲刺目标。

首版聚焦计算机与人工智能，固定输出国内 3 家、国际 3 家。推荐前必须先保存投稿人姓名、
学校/机构、学院或专业、论文用途和完成投稿截止日期。上述档案或学科方向、文章类型、语言、
目标策略、开放获取偏好发生变化后，系统重新计算并形成新的推荐运行记录，旧记录不会被覆盖。

## PWC 方案的单机化裁剪

PWC 的完整对象是“稿件版本 × 期刊版本 × 机构规则版本 × 数据快照”。ManuscriptDock 保留
版本绑定、规则与模型分离、可解释评分和重复计算四项原则。学校规则采用最高单项权重 24%，
但必须同时具有学校/学院官方来源、适用用途、人员范围、有效期、原文证据和核验状态。
未检索或未核验时显示 `official_source_search_required_excluded_from_score`，只输出候选初筛，
不虚构规则、不把缺失项当零分，也不按学校声望推断。

模型只在作者主动提供学校要求原文并确认本次发送范围时执行结构化抽取。学校名称可随本次授权发送，以便限定规则主体；Rust 在网络出口删除作者姓名、来源网址、邮箱、电话、长数字标识和论文正文，只发送学校名称、学科、论文用途与脱敏规则原文。模型不得根据训练记忆或搜索摘要补写规则，期刊排序仍由本地确定性算法完成。

## 当前最适合，而非身份降档

推荐应区分两组事实：

- **论文自身的学术上限**：Claim 的创新性、相对已有工作的差异、证据强度、方法可靠性、结果完整度和可复现性。
- **当前投稿的现实可行性**：学校正式认可规则、论文用途、截止时间、稿件准备程度、语言和目标策略。

学校全国排名、院校类型、作者年级和导师名气不得直接换算成期刊档次。学校正式规则只用于判断“是否认可、是否满足用途、时间是否可行”；同一篇论文不能仅因作者所在学校不同而被降低学术目标。作者阶段和可验证的研究支持条件未来可用于解释执行风险，但不能替代论文质量。

当前单机版只有结构完备度信号，尚不能可靠裁定实质创新性。因而 V1.2 是“当前投稿准备适配”，不是完整的论文实力评估。未来由 PWC 的 `AIReviewReport` 形成带来源锚点、独立版本和不确定性的论文实力档案后，才能把创新性、证据强度和方法可靠性纳入层级计算。届时每组结果应包含冲刺、匹配、务实目标，并说明进入更高层级还缺少什么；不得输出虚构的录用概率。

## 版本驱动的品质优化闭环

系统把每个不可变论文版本重新投影为同一组品质维度：主张清晰度、创新差异、证据强度、方法可靠性、结果完整度、边界披露、来源锚点和投稿结构。修订工具针对当前缺口提出操作项；作者形成新版本后，系统自动重新提取、检查并计算维度变化，再更新期刊组合。

版本号本身不加分。只有新版本出现可追溯的实质改善，相应维度才提高；删除证据、引入矛盾或扩大无依据结论时允许降分。更高分可把更高层级期刊从“暂不匹配”提升为“匹配”或“冲刺”，但系统同时保留当前务实目标，并展示相对上一版本的分数变化与依据。当前本机版先实现结构维度的重算；创新、证据和方法维度待 PWC 产出版本化 `AIReviewReport` 后启用。

## 推荐流程

1. 作者填写五项投稿背景，Rust 校验后保存不可变 `JournalRecommendationProfile`。
2. 针对学校、学院/专业、论文用途和适用日期检索学校官网、研究生院、科研管理部门和学院
   公开文件；联网前必须说明学校名称、查询范围和外发内容并获得授权。
3. 搜索结果只作为候选来源；作者也可直接粘贴学校正式要求并提供官方 URL。学校名称在本次
   明确授权后可进入模型投影；URL 只在本机用于来源归属。其余投影仅包含学科、论文用途和脱敏原文。
4. 原文不写入推荐记录，只保存 SHA-256、来源类型、抽取模型、条件和核验状态；作者确认
   正式来源且抽取置信度达到门槛后，形成新的不可变规则档案。
5. 读取当前不可变论文版本的标题、摘要、章节、图表、参考文献和结构警告。
6. 本地关键词规则推断计算机/AI 子方向，并结合作者填写的专业；作者可覆盖推断结果。
7. 从内置、经核验的候选快照召回国内与国际期刊。
8. 分别计算学校规则、主题、专业、文章类型、内容完备度、语言、目标档位、用途、时间和开放获取。
9. 国内、国际分别排序并显示前 3 家，同时展示分项分、依据、排名来源和期刊主页。
10. 任一档案、学校规则或偏好变化后重新保存档案并计算新的 `JournalRecommendationRun`。

## 确定性评分 V1.2

| 维度 | 权重 | 含义 |
| --- | ---: | --- |
| 学校规则标准 | 24% | 已核验的学校正式规则、认定映射与资格阻断；缺失时不计分并归一化其余维度 |
| 主题与办刊范围 | 18% | 当前论文研究方向与候选期刊领域标签的关系 |
| 作者专业背景 | 5% | 学院/专业与候选领域标签的关系，不代表作者身份优劣 |
| 文章类型 | 8% | 研究论文、综述或应用型稿件是否在候选范围内 |
| 内容完备度 | 10% | 标题、摘要、关键词、章节、图表、参考文献和篇幅的结构性准备程度 |
| 投稿语言 | 6% | 作者语言偏好与期刊语言是否一致 |
| 目标策略 | 8% | 冲刺、均衡或务实策略与公开目录档位的关系 |
| 论文用途 | 8% | 学位、毕业、职称、结题或一般发表与目标层级的规划关系 |
| 投稿时间可行性 | 10% | 截止日期与本机内部投稿准备天数之间的余量 |
| 开放获取 | 3% | 无偏好、优先或必须开放获取 |

综合适配分范围为 0–100，仅用于当前候选集内排序，不是录用概率、影响因子预测、同行评审结论或学术质量裁定。结构完备度只能说明稿件是否准备充分，不能替代创新性与学术贡献评价。

学校资格/阻断规则不进入普通平均。违反已核验规则时保留该期刊，以“学校规则阻断”显示，
使用户看见“学术适配高但学校不认可”的真实冲突。姓名只用于本地档案归属和后续材料生成，
其变化会形成新的档案与运行 ID，但不改变期刊得分。

截止日期当前只计算“能否按计划完成投稿准备”，不能预测同行评审、录用、网络首发、见刊或
数据库收录日期。未来只有获得期刊官方周期数据或可核验历史统计后，才能增加出版周期维度。

## 数据来源与版本

首版目录版本为 `computer-ai-2025.1`，排名核验日期为 2025-04-16。

- 国内排名依据：[CCF 中国计算机领域高质量科技期刊分级目录（2025）](https://www.ccf.org.cn/ccftjgjxskwml/)。目录明确说明国内 T1/T2/T3 与国际 A/B/C 是两套独立目录，不进行等级等同。
- 国际排名依据：[CCF 推荐国际学术刊物目录——人工智能](https://www.ccf.org.cn/Academic_Evaluation/AI/)。
- 中科院期刊分区表来自中国科学院文献情报中心。其[用户协议](https://www.fenqubiao.com/User/UseProtocol.aspx)
  禁止向非授权主体传播数据，因而不随安装包内置。已订购单位可通过
  [官方开放平台](https://webapi.fenqubiao.com/)申请查询接口；只有授权接口返回且绑定年份的
  分区结果才能参与学校条件匹配。
- 办刊范围、语言和投稿类型以各期刊官网为一等来源，例如[软件学报](https://jos.org.cn/)、[计算机学报](https://cjc.ict.ac.cn/)、[JMLR](https://www.jmlr.org/)和[TACL](https://transacl.org/)。

候选池仅用于产品验证，并不声称覆盖所有期刊。目录更新必须形成新版本，历史推荐继续引用原目录版本。

## 数据合同与信任边界

投稿档案保存在 `analysis/journal-profile-{profileId}.json`，字段变化形成新版本并记录
`journal_recommendation_profile_saved`。每次运行固定记录：档案版本、`runId`、稿件版本和
内容哈希、算法版本、目录版本与核验日期、计算日期、输入偏好、推断主题及依据、完备度、截止日期余量、
两组推荐及分项得分、来源 URL、学校规则状态、限制说明和外部传输状态。同一稿件、档案与
条件在同一天产生稳定运行 ID；任一输入变化或跨日重算产生新 ID，以免截止日期余量停留在旧值。运行文件位于
`analysis/journal-match-{runId}.json`，审计日志记录 `journal_recommendations_computed`。

学校要求模型抽取形成派生档案并记录 `institution_rule_evidence_saved`。内部系统提示词和
权重实现不向界面公开，但界面必须展示规则是否核验、是否实际采用、是否等待授权中科院数据。
这一区分“保护内部方法”与“向用户隐藏影响结果的事实依据”。

- 不保证录用，不自动投稿，不把推荐顺序包装成“最佳期刊”。
- 投稿前必须访问期刊官网核验最新范围、格式、费用、周期和伦理政策。
- 不抓取或复刻付费商业榜单，不以搜索摘要作为正式证据。
- 不把中科院分区表、JCR 派生数据或非授权网络副本打包进客户端；不让模型猜测分区。
- 不把国内 T1/T2/T3 映射成国际 A/B/C。
- 学校规则检索优先使用官网、研究生院、科研处/科研院和学院正式页面或附件；搜索摘要不能
  作为正式证据。
- 已核验、当前有效、适用范围明确的学校规则才使用 24% 权重；资格规则可产生阻断。
- 未核验时该维度完全不参与评分，结果必须标记为候选初筛。
- 学校要求模型抽取必须在执行前说明发送范围；只发送学校名称、学科、论文用途和脱敏规则原文。作者姓名、来源 URL、联系方式、身份标识和论文正文不发送。
- 未来联网检索、PWC 机构规则同步和中科院官方 API 调用仍须单独授权并记录数据版本。

## MVP 验收

- 任意可提取的当前版本均返回国内 3 家、国际 3 家。
- 视觉、自然语言处理等方向调整会改变候选排序。
- 专业、用途、截止日期或偏好调整会改变分项和候选排序；姓名或学校名称变化至少生成新的
  归属档案和运行 ID，其中学校只有绑定已核验规则后才改变学校适配分。
- 当前推荐明确标注“投稿准备适配”，不把结构完备度宣称为学术创新评分；未取得 PWC 的
  版本化论文实力档案前，不输出伪精确的顶刊成功率。
- 相同稿件、档案和偏好重复计算结果稳定。
- 所有得分均在 0–100，界面明确提示“不是录用概率”。
- 不提供学校要求时，计算、保存和审计均在本机完成；选择模型抽取时，外部传输记录为
  `performed_to_configured_model_institution_and_redacted_rule_text`。
- 抽取出中科院分区要求但未配置授权官方接口时，状态固定为
  `verified_rule_waiting_for_institution_directory_data`，分区条件不计分。
