# ManuscriptDock 完整功能清单（代码实况）

> 核查基线：2026-09-14，项目版本 `V0.52` / `0.52.0`。  
> 本清单以 `apps/desktop`、`crates/manuscript-core`、Tauri 配置、规则包、测试和构建脚本的当前代码为准，不把产品规划文档中的设想视为已实现功能。  
> 状态说明：**已接通**＝界面或 IPC 与业务实现均存在；**底层已实现**＝Rust 命令/核心能力存在，但不一定有完整主界面入口；**预览/记录**＝展示或保存状态，不代表外部业务已执行；**规划中/未实现**＝仅有协议、占位或明确缺失。

## 1. 产品与技术边界

- 产品：投稿舱 ManuscriptDock V0.52，本地优先论文投稿工作区。
- 桌面技术栈：Tauri 2、React 18、TypeScript 5、Vite 5、Rust 1.93。
- 支持界面语言：简体中文 `zh-CN`、英文 `en`。
- 主稿支持格式：DOCX、PDF、TEX；单文件最大 250 MiB。
- 主稿选择阶段按扩展名分类，不校验文件魔数；损坏内容在后续解析时暴露。
- WebView 是展示层；文件、持久化、联网策略、模型密钥和业务记录由 Rust 管理。
- 原稿作为不可变输入保存；修订、恢复、导出和投稿均形成新版本或快照，不覆盖外部原文件。
- 基础结构分析和规则检查不依赖模型；模型外发与官网访问均要求作者明确授权。

## 3. 首次使用与工作区

### 3.1 稿件选择

- 使用系统文件选择器选择单个主稿。
- 允许 DOCX、PDF、TEX；取消选择时保持空状态。
- 返回安全元信息和临时 `selection_id`，不直接向 WebView 授予任意路径访问。
- 后续创建工作区必须使用仍有效的选择令牌。
- 不接受 DOC、`.zip` LaTeX 工程或无扩展名文件。

### 3.2 已有工作区匹配

- 根据所选文件查找本地已有工作区。
- 区分内容完全匹配与其他候选。
- 默认展示最多三项，支持展开/折叠和键盘打开。
- 重新选择文件后清空上一轮匹配。
- 不自动覆盖、合并或复用已有工作区。

### 3.3 创建本地工作区

- 将稿件复制到应用管理目录并计算内容哈希。
- 保存不可变原始快照、清单与初始版本。
- 创建完成后销毁临时选择令牌。
- 外部源文件不被修改。

### 3.4 工作区列表与存储

- 展示最近工作区和已归档工作区。
- 展示应用管理的本地库位置和存储摘要。
- 打开历史工作区并恢复其版本、材料、目标、检查和生命周期状态。
- 导出完整工作区副本到用户选择的文件夹。

### 3.5 归档、恢复、永久删除

- 活跃工作区可归档，归档工作区可恢复。
- 永久删除必须二次确认。
- 删除范围包含稿件版本、分析、检查、材料、存证、投稿和知识体问答记录。
- 管理过程校验工作区 UUID、manifest 与目录边界，并拒绝不安全的工作区根符号链接。

## 4. 桌面工作台与导航

工作区提供以下用户任务入口：

1. 概览：稿件、当前版本、目标期刊和准备进度。
2. 投稿材料：材料目录、声明、要求决策及历史复用。
3. 期刊：推荐组合、主备目标和官方要求。
4. 检查与修订：结构分析、规则检查、人工核验和安全修订。
5. 投稿包：存证、包计划、导出状态和投稿登记。
6. 版本/高级记录：历史版本、差异、来源恢复、生命周期和知识体。

界面会根据前置条件阻止操作并跳转到缺失步骤，例如未解决阻断项时不会打开投稿包导出目录选择器。

## 5. 稿件结构提取

### 5.1 TEX

- UTF-8 读取并去除注释。
- 提取标题、作者、摘要、关键词、章节、图表环境、参考文献和声明。
- 不编译 LaTeX，不展开自定义宏，不递归处理 `input/include` 工程依赖。

### 5.2 DOCX

- 读取 ZIP 内的 `word/document.xml`。
- 解析段落、样式、文本节点、表格、drawing/pict。
- 提取标题、作者候选、摘要、关键词、章节、图表和参考文献线索。
- 不是 Word 排版引擎，不保证理解完整 OOXML 资源和复杂布局。

### 5.3 PDF

- 优先使用布局 Markdown，再以文本提取和基础文本流补充。
- 提取文本、书签章节、作者/图表位置候选、页数和处理摘要。
- PDF 分析质量始终标记为有限，复杂多栏、公式、跨页表格和异常字体需人工确认。
- 识别待 OCR 页、表格页、分栏页和编码异常页。
- **当前没有实际执行 OCR**；无文本层页面仅标记为 OCR 候选。

### 5.4 结构报告与语义候选

- 结构报告包括标题、作者、摘要、关键词、章节、图表、参考文献、声明、字数、页数、覆盖率和警告。
- 抽取 `Claim / Scope / Method / Result / Evidence` 五类启发式语义候选。
- 每类最多三条，候选含来源、模态、置信度和可选片段锚点。
- 候选来自本地关键词/上下文打分，不是模型事实判断。
- `Complete` 仅表示解析质量，不代表全文、事实或科研结论已经验证。

## 6. 结构人工核对与来源恢复

- 查看自动识别的作者、章节、摘要、关键词、图表和参考文献。
- 人工校正作者顺序及有效结构。
- 填写核对说明并保存结构覆盖记录。
- 在操作系统默认应用中打开原稿进行页码对照。
- 内容或结构变化后，旧核对状态可能失效并要求重核。
- PDF 工作区可明确关联同一论文的 DOCX/TEX 源稿。
- 关联前必须由作者确认两者属于同一论文。
- 可在 PDF 档案与结构化源稿之间恢复访问关系。
- 不会把 PDF 自动转换为可安全修订的 DOCX/TEX。

## 7. 投稿材料管理

### 7.1 材料类型

- 源码工程
- 匿名主稿
- 原始图件
- 可编辑表格
- 参考文献文件
- 投稿信
- 标题页
- 声明文件
- 补充材料
- 其他支持文件

### 7.2 材料操作

- 按材料类型选择一个或多个文件，并应用扩展名过滤。
- 检查同批次和现有槽位的重名文件。
- 重名替换必须确认；仅替换应用内副本。
- 单独控制每项材料是否纳入最终投稿包。
- 删除材料必须确认，且不删除外部原文件。
- 材料绑定当前稿件版本、投稿目标、要求快照和清单项。
- 目标或要求变化后，旧附件不会默认混入当前投稿包。

### 7.3 历史材料复用

- 查找历史版本、历史目标或历史要求下的附件。
- 作者明确选择后复制为当前上下文材料。
- 找不到历史实体文件时报告完整性失败，不伪造成功。

## 8. 声明与投稿要求决策

### 8.1 声明类别

- 伦理审批
- 知情同意
- 利益冲突
- 资金来源
- 数据可用性
- 作者贡献
- AI 使用
- 其他期刊声明

### 8.2 决策能力

- 区分未知、符合、不符合、不适用和旧版“仅核验”状态。
- 保存依据、说明、适用条件、当前阶段和交付方式。
- 将声明确认与声明文件上传分离。
- 支持不同声明文件槽位及历史附件复用。
- 支持补充自动抽取遗漏的要求。
- 后续阶段才需要的文件保持延后，不被误算为当前已完成。
- “不适用”仅在要求本身有明确适用条件时可选，且必须填写依据。
- “尚未准备”不能冒充“不适用”；无条件要求不能被前端免除。

## 9. 期刊推荐与投稿目标

### 9.1 投稿背景档案

- 保存学校、专业、稿件用途、研究主题、文章类型、语言、目标策略、开放获取偏好和截止日期等背景。
- 重新调整参数并生成新的推荐运行。
- 保留历史推荐，不直接覆盖当前运行。

### 9.2 本地期刊推荐

- 按本地内置目录和导入目录计算匹配。
- 输出国内/国际组合，以及冲刺、匹配、保底等角色。
- 展示出版商、地区、排名体系、文章类型、匹配分数、目录版本、核验日期、机构规则状态和限制。
- 结果属于本地算法辅助，不是录用概率、创新性评级或权威投稿保证。
- 内置候选范围目前偏计算机与人工智能期刊；内置目录核验日期不是实时日期。
- 截止日期只估算内部准备余量，不预测审稿、录用、出版或收录时间。

### 9.3 主目标和备选目标

- 从当前推荐中设为主目标。
- 添加、移除备选目标。
- 清除主目标需作者确认。
- 将备选提升为主目标需填写原因。
- 目标绑定当前稿件版本，旧版本目标不能静默沿用。
- 可重新确认上一版本的期刊及仍有效的官方依据。

## 10. 期刊目录与画像（底层能力）

### 10.1 XLSX 目录导入

- Tauri 命令和核心 SQLite 存储均已实现。
- 仅接受小写 `.xlsx`，不支持 `.xls` 或通用任意表格布局。
- 文件最大 64 MiB，单 XML 成员最大 96 MiB，每表最多 100,000 行和前 64 列。
- 不执行公式，只读取存储或缓存值。
- 支持四套固定表头：中科院 2025、JCR 2024 指标/2025 发布、新锐 2026 两种布局。
- SHA-256 去重；保留来源历史并将旧来源设为 inactive。
- 提供目录汇总、名称/ISSN 规范化和证据查询。

### 10.2 期刊画像

- JSONL 导入出版社、主页、范围、指南 URL、发行量、发文量、审稿流程、平均天数、投稿至出版时间、刊期、APC/OA 和来源。
- 通过 ISSN 优先、名称兜底关联现有期刊；不匹配项不会自动创建期刊。
- 支持画像发现记录和候选保存。
- 模型发现结果强制标记为“需要官方核验”，不等于已验证画像。

## 11. 学校/机构要求抽取

- 输入学校、专业、论文用途、规则原文和可选官方 URL。
- 原文长度 40–30,000 字符。
- 必须确认本次向模型外发。
- 在发给模型前进行有限作者名、邮箱和长数字串脱敏。
- 提取 T1/T2/T3、CCF A/B/C、中科院分区、Top 要求、适用条件和歧义。
- 不允许把 CCF 与中科院体系相互转换。
- 模型不能自行浏览学校政策，也不得用先验知识补全原文没有的信息。
- 结果区分已验证、需核验、需搜索、未找到官方规则。
- 中科院授权官方 API 当前状态明确为 `licensed_official_api_not_configured`。
- 此处“已验证”仍依赖作者对原文来源的声明和模型置信度，不是外部权威独立验证。

## 12. 官方来源访问与要求快照

### 12.1 受控官网抓取

- 每次访问必须勾选仅本次授权；切换期刊不会复用授权。
- 使用真实 HTTP GET，不是演示数据。
- 抓取主页并尝试最多三个指南链接，必要时适配特定新闻正文接口。
- 支持 HTML、XHTML、纯文本及 BOM/charset/meta 编码识别，部分中文页面尝试 GB18030。
- 记录开始、完成、部分成功、错误、有效 URL、来源修正和 HTTP 使用。
- 单页最多 2 MiB；单会话最多 24 请求、90 秒。
- 禁止代理和自动重定向；逐跳校验重定向。
- 拒绝私网、保留地址、本地域和单标签主机，并固定已验证 IP 以降低 DNS rebinding 风险。
- 对特定虚拟 DNS 地址可通过 Cloudflare DoH 恢复解析。

### 12.2 已知访问边界

- 不是浏览器引擎，不执行任意 JavaScript，不支持登录会话或通用 SPA 渲染。
- 网络入口不解析 PDF 作者指南。
- 失败后可能在 HTTPS/HTTP 间换协议重试；降级 HTTP 会记录风险，但当前没有额外确认门槛。
- “取消访问”只写取消记录，没有中止在途 HTTP 请求的 cancellation token。
- 保存 URL 与真正允许联网是两层校验；能保存的 URL 不一定允许抓取。

### 12.3 手动官方原文

- 输入来源 URL并粘贴作者指南原文。
- 作者必须确认原文来自期刊或出版社官方指南。
- 校验 URL 和目标主页 host 关系。
- 保存为本地要求快照，不执行网络传输。
- 这是作者提供来源，不是系统对官网内容的独立验证。

### 12.4 要求快照

- 保存来源 URL、标题、正文哈希、抓取时间、host 状态、提取要求、证据摘录、限制、快照哈希和有效期。
- 新鲜期为 90 天，并绑定稿件版本和目标选择。
- 保留不可变历史和当前指针。
- 不保存完整网页 HTML/正文，不是可重放网页镜像。
- 未实现 ETag/Last-Modified 通用 HTTP 缓存；90 天是业务新鲜度，不代表自动重抓已经发生。

## 13. 投稿准备检查

### 13.1 检查结果

- 基于当前结构报告和选中规则包生成不可变 readiness 快照。
- 输出通过、不通过、待作者确认、警告与阻断项。
- 必须项失败导致 `Blocked`，建议项失败产生 `Warning`，确认项产生 `Confirmation`。
- 有阻断则总体阻断；仅有警告或确认则 `NeedsAttention`。
- 检查结果保存规则来源、版本和内容指纹。
- 自动存在性检查与人工核验分开；失败项不会为了显示完成而被隐藏。
- 旧版仅有 reviewed 标志的记录继续视为未完成，需重新明确决策。

### 13.3 规则引擎边界

- 18 包合计 56 条直接规则，并支持规则包继承。
- 对嵌入 JSON 原始字节执行 Ed25519 验签，同时校验 schema 和来源元数据。
- 验签证明与内置信任锚匹配，不代表标准机构认证或实时官网核验。
- 自动引擎主要支持存在性、章节下限、解析完整性、章节别名和人工确认。
- `confirmation.*` 不会自动通过，必须由作者处理。
- 未实现完整 CSL、逐条引文元数据、临床指南全部条目或科研真实性自动验证。

## 14. 安全修订

### 14.1 TEX

- 可修改现有 `\title{}`、`abstract` 环境和 `\keywords{}`。
- 不自动创建缺失字段，不支持所有关键词命令变体。
- 字符串/括号定位，不是完整 TEX AST；不验证修改后是否可编译。

### 14.2 DOCX

- 仅可修改第一个明确使用 `Title`/`title` 样式的标题段落。
- 摘要和关键词保持只读证据。
- 修改首个文本节点并清空后续文本节点，不能保证保留原标题混合字符格式。

### 14.3 PDF

- 不提供结构化回写字段。
- 应关联 DOCX/TEX 源稿后修订。

### 14.4 版本保护

- 字段值去空白后不能为空，单字段最多 20,000 字符。
- 修改必须基于当前版本，避免过期草稿覆盖新内容。
- 先预览旧值/新值，再生成新版本。
- 无实际变化时不创建重复版本。
- 不覆盖源稿，保存只读修订记录。

## 15. 本地版本库

- 获取全部稿件版本及当前版本。
- 展示版本号、来源、时间、备注和内容哈希。
- 比较任意版本的结构/文本变化，展示新增、删除和中性差异。
- 将历史版本恢复为新的当前版本，而非覆盖时间线。
- 当前版本变化后，旧目标、检查、存证、材料和知识体按上下文/指纹重新判断有效性。
- 新版本必须保持当前主稿文件类型；格式转换应作为投稿输出而非版本替换。

## 16. 本地存证

- 作者确认当前稿件版本和当前检查报告后创建记录。
- 保存版本、检查结果、payload 和哈希一致性信息。
- 为目标投稿包和知识体固化提供前置条件。
- 版本变化后旧存证不再代表当前版本。
- 这是本地哈希校验，不是第三方可信时间戳、公证、数字签章或不可篡改账本。

## 17. 投稿包与导出

### 17.1 通用投稿证据包

输出目录名：`ManuscriptDock-{工作区ID前8位}-v{版本}`。

固定产物：

```text
manuscript.{docx|pdf|tex}
decomposition-manifest.json
readiness-report.json
readiness-preview.html
local-attestation.json
submission-manifest.json
```

- 要求当前检查报告和本地存证。
- 缺少分解资产时触发结构分析。
- 不收集投稿附件。
- 输出是目录，不是 ZIP，也不会自动上传。

### 17.2 目标期刊投稿包

输出目录名：`{稿件名}-submission-v{版本}-{导出ID}`。

主要结构：

```text
submission/manuscript.{原扩展名}
submission/manuscript-blinded.{附件扩展名}
submission/{source-project|blinded-manuscript|figures|tables|bibliography|supplementary|cover-letter|title-page|declarations|other}/...
records/target-selection.json
records/readiness-report.json
records/journal-requirements.json
records/package-manifest.json
records/declaration-plan.json
records/declaration-summary.txt
records/requirement-decisions.json
records/material-checklist.json
records/effective-structure.json
README.txt
```

- 仅纳入当前版本、目标、要求快照上下文一致且勾选包含的附件。
- 排除无有效清单关联、延后阶段和不适用项。
- 匿名模式要求独立匿名稿，不复制实名主稿，系统不会自动匿名化。
- 重名附件增加材料 ID 前缀；共享声明文件可按哈希复用。
- 复制已有主稿和附件；只自动生成 JSON/TXT 记录，不生成投稿信、声明正文、标题页、图表或编译 PDF。
- `records` 明确用于本地留档，不应上传期刊。
- 导出前后进行哈希和上下文检查。
- 输出是目录，不是 ZIP，不执行外部投稿。

### 17.3 导出状态

- 区分已导出、未导出、文件已变化、文件不可用、记录保存失败、审计失败和历史不可核验。
- 文件生成成功不等于状态可信；导出记录失败时不宣称完成。
- 文件变化后旧记录不能证明当前包已导出。
- 外部传输状态明确显示未执行。

## 18. 外部投稿与修回边界

- 作者在期刊系统完成投稿后，可手动登记投稿目标和可选回执。
- 登记记录不等于期刊平台已独立验证。
- 当前没有自动登录、表单填写、文件上传、状态同步或回执验证。
- “修订”当前主要指依据本地检查修改安全字段并生成新版本。
- 当前没有完整的外部审稿意见收取、返修任务编排、回复信生成与投稿平台同步。

## 19. 学术知识体

### 19.1 已实现

- 从当前结构报告生成本地知识候选和来源身份。
- 五类候选逐项审核；每条必须明确纳入或排除，不允许遗漏或重复决定。
- 选择学科分类。
- 在当前存证与投稿记录满足条件时固化知识体。
- 生成知识体哈希、不可变记录和生命周期状态。
- 展示对象、主张、来源锚点、空间图、网络图和证据层。
- 网络默认是当前研究单节点，关系断言可为空。

### 19.2 状态边界

- `candidate` 是本地提取但未经作者确认。
- `pending` 不能当作已建立事实。
- `established` 表示作者已确认纳入，不代表外部科学验证。
- 来源追踪能力可用。
- 证据约束问答需要运行时模型和逐次授权。
- 方法适用性检查明确为 `Planned`。
- 跨论文知识网络、权益/声誉与自动验证目前主要是协议/数据结构，不是已运行服务。

### 19.3 PWC 专业审核

- 生产知识体默认没有 AI 专业审核报告和历史。
- `pwc.review.agent` 只出现在测试辅助代码的合成记录中。
- 当前未接入真实 PWC 专业审核服务，不能声称已有专业审稿能力。

## 20. 知识体问答与模型服务

### 20.1 问答流程

- 固化知识体后创建作者询问。
- 选择 `recognition / question / challenge` 立场。
- 选择知识体、主张、范围、方法、结果、证据关系、来源锚点、审核报告、溯源、能力契约或权益声誉等目标。
- 问题最多 4,000 字符，回答最多 24,000 字符。
- 保存询问、模型回答、所用模型角色和来源锚点。
- 按当前知识体记录与哈希过滤历史对话。

### 20.2 模型配置

- 三个顺序槽位：`primary`、`fallback_1`、`fallback_2`。
- 配置启用状态、提供商、API Base URL、模型名和 API Key。
- API Key 使用系统凭据库；普通 JSON 和前端只保存/显示 `has_api_key`。
- 远程地址要求 HTTPS，本地回环允许 HTTP。
- 禁止 URL 用户名、密码、查询参数和 fragment。
- OpenAI-compatible `POST /chat/completions`，超时 45 秒，禁用自动重定向。
- 地址未以 `/chat/completions` 结尾时自动追加，但不会自动补 `/v1`。
- 主模型失败后按顺序尝试两个备选模型。

### 20.3 外发与隐私

- 每次知识体问答必须作者确认外发。
- 发送当前问题所需的最小知识体投影。
- 对已知作者名、简单邮箱和连续长数字进行有限脱敏。
- 不应将其描述为完整 PII 清洗；部分 claim、对象和语义内容并非逐字段使用同一脱敏函数。
- 模型被要求不得捏造证据、方法、结果、引用或不存在的能力，信息不足时应拒答。
- 没有流式输出、通用工具执行、Token/费用统计或每次故障转移尝试的统一完整审计。

## 21. 生命周期与审计

- 保存工作区、版本、分析、规则、材料、目标、要求、存证、投稿和知识体相关不可变记录。
- 使用 `audit.jsonl` 追加工作区事件，并进行 flush/sync。
- 期刊目录使用单独 SQLite，主稿与多数业务记录使用文件/JSON。
- 导入、导出和部分材料操作校验哈希、相对路径、canonical path 和符号链接边界。
- 原始快照和不可变记录设置只读。
- 只读文件和 JSONL 审计不是密码学不可篡改存储；同权限用户仍可能修改本地文件。
- 工作区没有整体静态加密；bundled SQLite 不等于 SQLCipher。
- 审计不是逐事件签名哈希链。

## 23. 窗口、多屏与平台集成

- 默认窗口内容尺寸 1180×780，正常最小 760×620；小屏可进一步适配。
- 主窗口初始隐藏，恢复几何后显示，并有最长约两秒兜底。
- 保存逻辑尺寸、显示器身份、工作区相对位置和用户偏好/有效尺寸。
- 处理 DPI、拔屏、跨屏、最大化、最小化、全屏和系统贴靠，避免这些状态污染正常窗口偏好。
- 最多保存 16 个显示器偏好；异步写入有 revision/writer lock 防止旧写覆盖关闭状态。
- Windows 使用 Win32 显示器/DPI/拖动与排列检测。
- macOS 使用 AppKit points、visibleFrame、屏幕 UUID 和窗口通知。
- Linux/其他平台使用保守 fallback，缺少稳定显示器键和可靠 resize 识别。
- 打开主稿使用操作系统默认关联应用：Windows Explorer、macOS `open`、Linux `xdg-open`。

## 28. 代码实况结论

当前项目不是概念空壳：本地工作区、格式解析、版本、投稿材料、期刊目标、受控官方抓取、要求快照、签名规则检查、安全修订、本地存证、两类目录式投稿包、手动投稿记录、知识体固化、模型问答和桌面多屏状态均有实际实现。

当前产品的可靠定位是“本地论文投稿准备与证据工作台”，而不是自动投稿代理、权威期刊决策系统或专业审稿服务。其主要优势在于不可变版本、上下文绑定、来源证据、作者确认、显式外发和可核验导出；主要限制是 PDF/OCR 与结构化修订范围有限、目录及机构数据并非实时权威接口、外部投稿和 PWC 审核尚未接入，以及本地记录不具备加密公证属性。
