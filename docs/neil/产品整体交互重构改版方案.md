# ManuscriptDock 产品整体交互重构改版方案

> 文档用途：记录已落地的单文件交互原型，并作为后续正式产品实现与验收的依据；不是仅供选择的旧推荐稿。
> 更新日期：2026-09-15；产品基线 V0.52。本次为 DEMO 信息架构与交互改版，不表示正式产品版本升级。
> 核对依据：同目录 `产品整体交互重构改版DEMO.html` 的完整 HTML、JavaScript 和最终生效的 CSS 覆盖规则。
> 核查方式：静态代码核对，未进行浏览器操作验收。下文“已实现”仅指原型代码中存在对应结构或处理逻辑。

## 1. 方案摘要

采用“论文库 + 我的论文”双域，以及“论文项目控制台 + 单篇论文工作区”的任务组织方式：

```text
论文库：公共论文库 / 我的收藏 / 课题组论文库 / 添加论文库
  → 浏览来源、收藏、查看只读详情
  → 加入我的论文，创建独立工作副本
我的论文：全部 / 按当前生命周期筛选
  → 紧凑论文列表：任务状态 + 只读生命周期 + 下一步
  → 点击标题或查看详情进入概览，点击下一步进入对应任务页
  → 处理目标、资料、检查与作者确认
  → 创建投稿包导出记录，再手动登记投稿事实
  → 在档案查看版本编号、来源说明、存证说明与活动历史
```

生命周期回答“曾经到过哪里、现在在哪个阶段”；任务状态回答“当前版本能做什么、还缺什么”。两者不得合并为一套筛选状态。查看阶段不执行任务，也不推进生命周期。

## 2. 范围与真实性边界

### 2.1 已有原型范围

- 双域导航、来源论文搜索/分类筛选、收藏、添加本地论文库、创建个人工作副本；
- 我的论文生命周期数量筛选、辅助筛选、排序和紧凑卡片；
- 导入弹窗、单篇概览、目标与要求、投稿资料、检查与修订；
- 投稿包清单与导出记录、手动投稿登记；
- 版本编号切换与新建、来源与依据、存证说明、活动记录；
- 只读列表时间轴、可切换面板的详情阶段 Tab；
- 归档/恢复/删除、确认弹窗、抽屉、部分操作的加载/失败/重试；
- 中文/英文与 Aa 字号偏好。

### 2.2 不能当作已接通的能力

这是单文件内存交互原型。论文、库、版本、检查、导出及投稿记录在页面内存中改变，刷新后重新初始化；仅语言和字号使用浏览器 `localStorage` 保存。没有真实网络处理，不代表正式 React/Rust 业务链路、文件工作区或数据库已接通。

- 导入只检查文件名扩展名与大小，不读取正文、不解析 DOCX/PDF/TEX、不计算哈希，也不保存所选文件。
- 检查与要求更新通过定时器演示状态变化，不是真实规则引擎、官网读取、PWC 审核或模型推理。
- 导出仅添加内存记录，不生成文件、不下载 ZIP、不选择或写入本地目录。
- 版本为编号数组，没有正文快照、真实差异计算或新版本文件导入。
- 修回任务、审稿意见关联、回复信、自动投稿、状态同步均未实现；没有开始修回或标记完成的操作。
- 原稿预览为内置示例正文；存证只展示版本关联与活动时间，不是哈希证据、公证或可信时间戳。

顶部 DEMO 横条已从渲染结构删除，全站冗余的模拟/未连接平台说明不再作为统一展示要求；残留 `.boundary`、`.demo` 样式名不等于仍有顶部横条。不得要求界面统一贴 `DEMO 模拟` 标签。必要的业务语义仍在具体位置保留，例如修回“规划能力”、作者登记未经平台验证、导出不等于投稿。

文档必须保留上述原型事实边界。正式开发继续遵守本地优先、原稿不可变、作者确认和受控外发；任何联网、模型调用、外部投送都需明确授权。当前没有真实外发，也没有完整外发确认流程，不应称为已完成接入。

## 3. 信息架构与页面落点

### 3.1 全局结构

顶部为品牌“投稿舱 ManuscriptDock”、论文入口、“仅在本机”、中英文切换、Aa、设置。设置打开“设置与帮助”抽屉，包含折叠的流程与列表帮助及偏好保存说明，不是独立配置页，也没有模型配置表单。

左侧始终保留双域：

1. **论文库**：可展开/收起；公共论文库、我的收藏、课题组论文库、自建库、添加论文库。
2. **我的论文（总数）**：可展开/收起；独立“全部”及七个生命周期数量筛选。

默认打开“我的论文 / 全部”。顶部“论文”和工作区返回入口均返回我的论文并选中全部，但不会自动清空搜索与辅助条件。点击“我的论文”标题还会切换展开状态。

### 3.2 四入口与阶段导航的实际关系

打开单篇后，左侧双域下方增加四个工作区入口；它们按任务分组，不是七阶段的替代名称：

| 四入口 | 默认落点 | 组内任务页 |
|---|---|---|
| 概览 | `overview` | 下一步、阻断任务、最近活动 |
| 投稿准备 | `target` | `target` 目标与要求、`materials` 投稿资料、`check` 检查与修订 |
| 投稿与修回 | `package` | `package` 投稿包、`log` 投稿记录；修回只在阶段面板及记录页解释规划范围 |
| 档案 | `versions` | `versions` 版本、`sources` 来源与依据、`proof` 存证、`activity` 活动记录 |

每个单篇任务页上方都有七阶段 Tab 和一个阶段信息面板。点击阶段只更新面板，不更改当前任务页 `page`，不切换左侧四入口，也不执行投稿。面板中的具体行动通过 `stage-open` 打开任务页；“运行基础检查”这个行动会在进入检查页后启动检查演示。

因此允许同时出现“正在查看历史准备阶段面板、下方仍为投稿记录任务页”。四入口选中态由任务页确定，阶段选中态由独立的 `lifeSelection` 保存，真实当前阶段由 `lifecycle()` 确定。不能宣称阶段选择与四入口自动同步。阶段选择按论文 ID 在内存中记忆，后续阶段变化也不保证重置到当前节点。

### 3.3 路由边界

当前是单文件条件渲染，不存在正式 URL 路由。`section=mine/library` 表示全局域，`current` 表示当前论文，`page` 使用上表页面键。导入是弹窗，设置是抽屉；不要把 `import`、`settings` 写成已经实现的独立页面，投稿记录键为 `log`，不是 `submission-log`。

## 4. 状态模型与转换

### 4.1 四种含义分开保存

- **主生命周期**：左侧数量和时间轴的当前阶段。
- **任务投影**：卡片和概览的状态徽标、阻断与下一步。
- **历史事实**：`exports`、`records`、`events` 和经历阶段 `lifeHistory`。
- **当前有效性**：`requirements`、`materials`、`checked`、`confirmed`、`stale`、`exported` 等标志。

`exports` 有历史记录不意味着当前版本仍可导出；`exported` 可失效而 `exports` 不删除。手动投稿记录也不会因新版本或目标变更消失。

### 4.2 主生命周期与数量筛选

“全部”独立于时间线，不是阶段。七个阶段按下表顺序显示；判定优先级从已归档向草稿反向执行，每篇只计入一个当前阶段，数量按全体 `papers` 统计，不随标题搜索或辅助条件缩小。

| 阶段键 | 左侧名称 | 当前判定 |
|---|---|---|
| `draft` | 草稿 | 无后述高优先级条件，且无目标、未确认资料、无准备经历 |
| `preparing` | 准备中 | 有目标，或资料已确认，或 `lifeHistory` 包含准备中 |
| `exported` | 投稿包已生成 | 有 `exports` 历史，且无更高阶段 |
| `submitted` | 已记录投稿 | 有 `records`，且无更高阶段 |
| `revision` | 修回中 | `revision` 为真；仅预留状态，无触发操作和默认样本 |
| `completed` | 已完成 | `completed` 为真；仅预留状态，无标记完成操作和默认样本 |
| `archived` | 已归档 | `archived` 为真，覆盖其他当前阶段 |

时间轴的历史节点由真实标志、记录及 `lifeHistory` 决定，而非简单把当前节点之前全部涂为完成。草稿视为已经历；准备经历可由目标、资料、导出或历史记录推导。直接归档不把投稿、修回、完成等未经历阶段伪装为完成。恢复归档后仍可能显示曾经归档的历史节点。

### 4.3 当前任务状态投影

以下为 `status()` 的实际优先级，与生命周期枚举并非一一对应：

| 优先级 | 徽标 | 条件 |
|---:|---|---|
| 1 | 已归档 | 已归档 |
| 2 | 需要重新检查 | `stale=true` |
| 3 | 已记录投稿 | 有手动记录 |
| 4 | 已生成投稿包 · 未登记投稿 | 当前 `exported=true` |
| 5 | 可以生成投稿包 | 有目标、要求有效、资料已确认、检查已运行且问题已确认 |
| 6 | 准备中 | 其他情况，包括生命周期仍为草稿的项目 |

所以“草稿筛选下徽标准备中”“已记录投稿的生命周期下徽标需要重新检查”均符合当前双模型。修回/完成标志尚未纳入任务徽标投影，不能声称已闭合全生命周期业务。

### 4.4 唯一下一步与导出条件

列表和概览复用 `next(x)`，返回 `[目标页面, 按钮文案, 原因]`，不是已落地的独立 TypeScript 接口。顺序为：

1. 已归档 → 查看版本档案；
2. 上下文失效 → 重新运行检查；
3. 资料未确认 → 补充利益冲突声明/投稿资料；
4. 检查未运行或问题未确认 → 运行检查/确认检查问题；
5. 目标或要求缺失 → 选择目标/更新要求；
6. 当前尚未导出 → 预览并导出投稿包；
7. 尚无手动记录 → 登记投稿；
8. 否则 → 查看投稿历史。

`hasBlockers` 为缺目标、缺有效要求、缺资料、未检查、未确认或已失效的任一项。投稿包可导出条件为目标、要求、资料、检查、确认全部满足且非失效；归档时禁用导出。

基础检查不强制要求期刊或模型。原型以同一组检查标志承载基础与目标检查，尚无正式结果类型隔离，不应把它当作完整目标合规证明。

### 4.5 关键状态变化

| 操作 | 原型实际变化 | 保留与限制 |
|---|---|---|
| 导入/来源加入我的论文 | 创建 v1、无目标工作项目 | 不解析或复制真实稿件内容 |
| 保存资料 | 资料确认；清除检查、问题确认和当前导出标志 | 保留既有历史；不会主动清除 `stale` |
| 更改目标 | 要求无效，`stale=true`，检查/确认/当前导出失效 | 资料确认不自动清空；历史保留 |
| 标记要求过期 | 要求无效并触发上述失效 | 不是按真实日期自动过期 |
| 更新要求 | 要求有效但检查仍失效 | 定时器状态演示，快照日期为固定展示值 |
| 运行任一种检查 | `checked=true`、`confirmed=false`、`stale=false` | 留下活动文字；不保存独立历史检查结果对象 |
| 确认 STR-003 | `confirmed=true`，写活动 | 作者确认，不改稿、不代表专业审核 |
| 导出 | 当前导出有效，新增版本/目标/时间记录 | 不创建投稿记录、不生成物理文件 |
| 手动登记 | 增加表单内容与当前版本记录 | 没有要求必须先导出的前置校验；未经平台验证 |
| 新建或切换版本 | 改版本编号，资料确认失效，检查/确认/当前导出失效 | 作者、声明、附件勾选值及要求标志保留；无正文快照 |
| 归档/恢复 | 切换归档标志、记录活动 | 保留历史；不推进未经历阶段 |
| 删除 | 移除内存项目及记录 | 不影响原稿文件，无撤销入口 |

## 5. 双域控制台

### 5.1 论文库

公共论文库、我的收藏、课题组论文库使用内置来源目录。搜索标题、作者或来源，领域/类型/年份精确筛选；结果数及清除筛选位于筛选区下方。卡片展示类型与年份、标题、作者与领域、来源、摘要，以及详情、收藏/取消收藏、加入我的论文。

详情为只读来源抽屉。收藏只改变来源条目的收藏标志；加入我的论文按 `catalogId` 防止重复，生成独立 v1 项目并留在当前库，需从左侧进入个人工作区。加入不转移著作权，不证明作者身份或投稿授权。

添加库要求名称非空、最多 40 字符且不与已有中英文名称忽略大小写重复；默认可加入前两篇内置来源。空自建库可添加内置示例。没有远端库连接、真实课题组权限或自定义文件上传功能。

### 5.2 我的论文：紧凑列表方案 A

```text
顶部：品牌 / 论文 / 语言 / Aa / 设置
┌ 左侧双域导航 ─────────┬ 主体（无常驻右帮助栏）────────────────┐
│ 论文库及其子库         │ 我的论文 / 全部或所选阶段  结果数  [导入论文] │
│ 我的论文（总数）       │ 搜索论文标题       目标期刊       排序       │
│ 全部（独立）          │ □有阻断项  □需要重新检查  [清除辅助筛选]    │
│ ○ 草稿               │ 标题（可点）    任务状态徽标          […]    │
│ ○ 准备中             │ 目标 · 格式未记录 · vN · MS-ID · 更新时间   │
│ ○ 投稿包已生成        │ 七阶段只读时间轴                           │
│ ○ 已记录投稿          │ 下一步原因             [查看详情] [下一步→] │
│ ○ 修回中             │ ……下一篇论文                              │
│ ○ 已完成             │                                           │
│ ○ 已归档             │                                           │
└──────────────────────┴───────────────────────────────────────────┘
```

最终 `.list-split` 为单主体块布局，列表没有右侧帮助/证据栏。流程帮助收纳在设置抽屉；列表工作台分类小标题、页脚和数量计数说明按最终 CSS 隐藏。

卡片不再要求文件图标、单独最近活动行、哈希摘要或固定“继续处理”按钮。标题和“查看详情”打开概览；唯一主按钮为实际下一步任务名称，直接进入对应任务。更多抽屉只有查看档案、归档/恢复、删除，没有重命名或导出副本。

当前格式文案统一为“格式未记录”，即使导入曾选择文件也不持久记录格式。更新时间取最新活动时间，否则显示 `2026-09-14`。

### 5.3 筛选与排序

生命周期只在左侧筛选：全部、草稿、准备中、投稿包已生成、已记录投稿、修回中、已完成、已归档。不要在工具栏重复放一排生命周期。

工具栏辅助条件为标题搜索、目标期刊、“有阻断项”“需要重新检查”，叠加于所选生命周期。可生成投稿包、需要重新检查都不是新增生命周期。“清除辅助筛选”清空搜索和三项辅助条件，不重置所选阶段；空结果页“清除筛选”也采用同样行为。

排序包含最近处理、阻断优先、标题。其中“最近处理”实际按活动条数降序，而非最新时间戳，后续正式开发需修正或确认命名，不得声称已实现严格时间排序。

## 6. 导入交互

1. 列表点击“导入论文”，打开弹窗，没有额外新建空白项目按钮或独立导入页。
2. 选择 DOCX/PDF/TEX，扩展名不区分大小写，最大 `20 × 1024 × 1024` 字节；或使用内置 `New Research Manuscript.docx` 示例。
3. 显示文件名和 KB 大小；未选择或格式/大小不符时禁用创建按钮。没有哈希、正文解析摘要或真实上传进度。
4. 创建触发约 1.8 秒处理弹窗，可取消、触发失败并重试。
5. 成功后以去掉扩展名的文件名作为标题，创建无目标 v1 项目并进入概览，生命周期为草稿，下一步为补充资料。
6. 取消/失败不会创建半成品项目；关闭后重新导入需要重新选择或使用示例。

## 7. 单篇工作区与阶段面板

### 7.1 页面结构

```text
左侧：双域 + 返回我的论文 + 概览 / 投稿准备 / 投稿与修回 / 档案
主体顶部：论文 / MS-ID / vN；标题；目标；原稿保留说明；更多
          七阶段 Tab（真实当前阶段与查看阶段分开）
          当前所查看阶段的信息面板
          归档提示与恢复入口（若已归档）
          所属任务组 Tabs（概览无组内 Tabs）
主体下方：操作面（概览或具体任务） | 只读证据面（宽屏）
```

概览包含任务徽标、唯一下一步卡、目标/资料/当前检查三个固定任务行、无需目标或模型的基础检查次级入口、最多五条最近活动。任务行不是动态严重程度排序；不能把它描述成已实现的多级阻断排序引擎。完整活动进入档案。

### 7.2 列表与详情时间轴契约

- 列表使用只读 `ol/li`，没有阶段点击操作或 Tab 角色；仅标题、详情和下一步进入单篇。
- 详情使用 `tablist`、七个 `tab` 和单一 `tabpanel`，通过 `aria-controls`/`aria-labelledby` 关联。
- `aria-current="step"` 与状态文字表示真实当前阶段；`aria-selected`、实心绿色点与 600 字重表示正在查看的阶段。二者可能不同。
- 点击节点只更新阶段面板；左右方向键循环切换，Home/End 到首尾，采用单一可 Tab 聚焦节点。
- 历史节点展示“已完成 / 历史”；未经历节点可查看未解锁说明，但不会自动解锁或执行任务。
- 自定义 `.life-tip` 最终被 `display:none!important` 隐藏，不能声明 hover tooltip 已实现。按钮仍有 `title` 和 `aria-label`；原生 title 是否浮现及辅助技术朗读需浏览器验证。

### 7.3 各阶段面板内容

| 阶段 | 实际内容与行动 |
|---|---|
| 草稿 | 版本数量、目标；若为当前可继续到概览或设置目标，否则查看历史 |
| 准备中 | 目标、资料、检查三项当前上下文状态；当前阶段可继续处理、补资料、运行基础检查；历史阶段明确不是历史检查快照 |
| 投稿包已生成 | 全部导出时间/版本/目标；查看投稿包；当前阶段可登记投稿 |
| 已记录投稿 | 手动事实未验证说明、平台/编号/日期/版本/备注；查看投稿记录 |
| 修回中 | 规划范围、尚未解锁说明或历史入口；不提供开始修回和同步按钮 |
| 已完成 | 预留完成说明与档案/活动入口，不代表录用；当前没有操作产生该状态 |
| 已归档 | 只读保留说明、版本/导出/记录数量、档案和历史；归档不等于所有阶段完成 |

未经历阶段优先显示未解锁说明，修回面板始终先解释规划范围。归档只暂停任务操作；原型各写操作的只读保护完整性仍需运行验收。

## 8. 投稿准备

### 8.1 目标与要求

主目标下拉为未选择、Journal of Example、Ethics Review、Open Research Letters。保存变更前确认旧检查与要求失效，历史保留；相同目标仅提示未变化。显示要求有效性、当前绑定版本及固定快照日期（有效 `2026-09-15`，无效 `2026-05-01`）。

更新要求需要有目标，使用通用加载/失败/重试；成功仍要求重新检查。另有“标记要求过期”演示入口，不是自动超过 90 天判定。备选区域的 Open Research Letters 仅为静态参考，没有编辑或一键设为主目标按钮；可在上方主目标下拉中选择同名期刊。不存在真实官网来源读取。

### 8.2 投稿资料

表单为通讯作者、邮箱、利益冲突声明、确认补充材料与当前版本关联且所有作者同意的勾选项。提供示例声明，补充文件名固定为 `supplementary.pdf`，没有实际附件上传。必填和邮箱采用原生校验，提交另防作者/声明纯空格。

输入事件将草稿值保存在页面对象中，确认保存才设置资料完整并使检查与当前导出失效。反馈为“声明已保存到本页工作区”，不可写成已经持久保存到本地文件系统。当前不是作者、声明、附件、期刊材料的完整分组任务系统。

### 8.3 检查与修订

操作面展示运行按钮和 STR-003 问题，右侧是只读证据面或窄屏抽屉，不是问题列表/中央详情/右抽屉三栏编辑器。有目标时可运行目标检查或仅基础检查，无目标时运行基础检查；概览始终保留直接基础检查。

运行后显示摘要结构待作者确认、位置“第 1 页 / Abstract”、当前版本、发现及建议，可打开规则依据并确认处理。确认弹窗说明不自动编辑原稿、不代表专业审核。旧活动保留，但没有历史检查报告存储或可回放快照。正式产品需另实现结构化结果与版本/目标绑定，不可复用旧有效结果冒充当前结果。

## 9. 投稿包、手动记录与修回

### 9.1 投稿包

固定清单为 `manuscript-vN.docx`、`cover-letter.txt`、`declarations.txt`、`supplementary.pdf`。预览打开证据内容和上下文说明抽屉，不是实际生成文件内容的逐项预览；当前 PDF/TEX 来源也不改变这套示例清单。

导出按钮受当前完整性与归档状态约束；确认后添加版本、目标、时间记录，显示“导出记录已创建”和手动登记入口。没有导出路径、物理文件、目录选择、导出进度或失败流程。必须保留“导出不等于已投稿”。

### 9.2 手动投稿登记

表单为平台/期刊、日期、外部稿件编号、备注，没有附件控件。前三项必填，期刊与编号另防纯空格。草稿随输入保存在对象中；保存后记录当前版本并追加历史，草稿清空。

登记不要求先生成导出记录，不能在演示说明中把“先导出”写成程序强制。记录仅代表作者输入，不是期刊接收、送审、录用或平台验证，也不自动执行真实投稿。

### 9.3 修回边界

记录页保留修回规划提示，详情修回节点解释审稿意见关联、回复信和任务尚未实现。没有自动投稿、审稿状态同步或真实返修系统；不能用预留阶段宣称完整流程已闭环。

## 10. 档案

四个任务标签：版本、来源与依据、存证、活动记录。

- **版本**：按编号倒序，v1 标为不可变原稿，其余标为工作快照；创建新版本实际取最大编号加一，切换前确认失效影响，随后回到概览。这里的“快照”是原型标签，不是已保存正文。
- **差异**：抽屉只显示 v1 到当前版本以及核对摘要和附件关联的提示，不计算或标注实际差异。
- **来源与依据**：展示固定原稿文件名到当前版本再到目标/基础规则的示意链及依据抽屉，不是完整来源指纹链。
- **存证**：明确本地存证不等于第三方公证；当前只有版本关联和活动时间，不提供可信时间戳。
- **活动**：操作时追加带中英文文案和时间的记录，完整列表不因当前版本切换删除；初始示例可能有导出历史却无活动条目。

## 11. 反馈、弹窗与数据保留

设置、论文来源详情、更多、规则依据、投稿包预览、版本差异使用右侧原生 dialog 抽屉；导入、添加库、字号、确认和异步反馈使用普通 dialog。

目标变更、版本切换、作者确认、归档/删除、导出有明确确认文案；“标记要求过期”、工作区直接恢复等为即时操作，不应概括为所有变更都二次确认。

导入创建、运行检查、更新要求使用通用定时器流程：处理状态、取消、手动触发失败、重试。取消通过令牌防止后续回调提交，不是取消真实网络请求。导出、保存资料、手动记录没有同类异步失败演示。搜索无结果、库为空、未运行检查、无活动和无投稿记录都有对应提示。

原生弹窗打开时聚焦标题，Escape 调用关闭逻辑；关闭后尝试回到仍存在的触发控件，若重渲染移除了它则回退到顶部首按钮。不能声称任意场景都精确恢复原焦点、滚动位置及未提交表单；库新增名称、导入选择等关闭后的保留策略并不等同于资料/投稿草稿。

## 13. 演示路径（待浏览器执行）

以下根据处理逻辑编排，不是已通过的操作记录。演示前刷新恢复项目数据；语言和字号偏好可能保留。

### 13.1 从准备到手动登记

1. 在“我的论文 / 全部”观察 Aerial 卡片，点击标题或“查看详情”进入概览；点击卡片下一步则会直接进入资料页。
2. 从概览下一步进入投稿资料，填入示例声明，检查作者/邮箱与关联勾选，保存确认。
3. 返回概览查看下一步变化，或从投稿准备进入检查与修订。
4. 运行目标要求检查，等待状态反馈，确认 STR-003 已处理；如测试失败分支，点击触发失败后重试。
5. 进入投稿包，核对清单和上下文，点击导出并确认，观察新增导出记录；不要寻找下载文件或目录。
6. 点击手动登记入口，填写外部稿件编号并保存。
7. 返回概览与列表，验证生命周期已记录投稿、活动增加，且登记没有伪称平台验证。

### 13.2 双域与草稿

1. 打开公共论文库，搜索并组合领域/类型/年份筛选，查看来源详情。
2. 收藏并进入我的收藏核对；添加到我的论文，再次添加应禁用。
3. 左侧进入草稿，核对数量、v1、无目标和下一步；来源条目与个人工作副本分离。
4. 添加一个不带示例的本地库，观察空状态，再加入内置示例。
5. 从我的论文导入内置主稿或合法文件，验证取消/失败不创建项目，成功创建草稿。

### 13.3 列表只读与详情 Tab

1. 点击列表时间轴不应进入单篇或更改状态；标题、详情、下一步分别验证对应落点。
2. 在详情选择历史与未来节点，核对面板变化而下方任务页不变。
3. 区分绿色选中点对应查看阶段、`当前阶段`文字对应真实阶段；使用方向键、Home/End 及 Tab 测试。
4. 直接归档未投稿项目，查看已记录投稿/修回/完成节点仍未经历；恢复后核对历史不被删除。
5. hover 不作为已完成能力验收：自定义提示层当前隐藏；另检查原生 title 的实际行为。

### 13.4 新版本与目标失效

1. 对已有导出或投稿记录的项目进入档案，创建新版本或设为历史版本。
2. 确认后核对 vN、资料确认失效、需要重新检查、旧导出与手动事实仍在；生命周期可仍为已生成投稿包或已记录投稿。
3. 重新检查并确认问题，再确认资料；注意保存资料又会使检查失效，需按实际下一步补跑检查，不能把此路径写成一次检查即可结束。
4. 更改目标并确认，先更新要求再完成当前检查/资料条件；核对目标变更本身没有清空资料确认。
5. 差异抽屉仅为核对说明，没有正文 diff；旧检查只可在活动中看到摘要，不是历史报告。

### 13.5 无目标也能基础检查

打开 Graph 示例，在概览点击“直接检查主稿（无需期刊或模型）”；运行完成并确认后，目标仍为空，下一步才提示选择目标/更新要求。基础检查与目标绑定是不同事项，不以选择目标强制锁住基础检查。

## 14. 视觉与响应式基线

### 14.1 视觉与字号

沿用浅色学术工作台：背景 `#FAFAFA`，操作面白色，表面 `#F5F5F5`，正文 `#1C1B19`，次文字 `#4A4845`，边框 `#EBEBEB`/`#E0E0E0`，品牌绿 `#A6CE39`，警告 `#8A5C18`，错误 `#A53D36`。使用系统字体，不加载远程字体。

目标约束为非文章和功能分类标题文字不超过 13px；不能仅凭正文令牌就宣布该目标全站达标。现有 Aa 按钮实际提供根字号 **14 / 15 / 17px**，默认 15px，不是把所有正文改成这三个字号：

| Aa 根字号 | 正文/控件 `--body-size` / `--control-size` | 元信息 `--meta-size` | 分类标题 `--section-size` | 页面标题 `--page-size` |
|---:|---:|---:|---:|---:|
| 14px | 12px | 约 12.33px | 16px | 约 18.67px |
| 15px | 13px | 13px | 17px | 20px |
| 17px | 13px | 13px | 19px | 约 22.67px |

静态确认正文/控件通过 `min(13px,…)` 封顶，多种任务标题被覆盖到正文尺寸。但仍有 `h2/h3` 分类标题使用 `--section-size`，如“当前阻断与任务”“投稿资料”；`.nav-group>button`、证据栏标题使用 `1rem`，普通弹窗标题使用页面字号。它们包含非文章文字且可超过 13px，属于尚未满足的实现差距，不是新推荐尺寸。本次只更新方案，不修改 HTML；后续需收敛这些例外后再验收全站上限。论文标题与文章预览按文章内容单独核对。

### 14.2 按钮与时间轴

桌面基础按钮最小高度为 `1.6rem + 8px`：Aa 14/15/17 时约 30.4/32/35.2px；主按钮再加 2px，顶部与轻量按钮通常减 2px，正文按钮常规内边距为 `5px 10px`、主按钮 `6px 12px`。输入框最小高度为 `1.6rem + 12px`，左侧生命周期按钮最小 40px。标题链接另有零最小高度覆盖。长文案换行可能增高，不要把最小高度当固定实际高度。

粗指针设备额外覆盖按钮、非复选输入、select、summary 最小命中高度至少 44px，按钮最小宽度 44px；不能要求桌面所有紧凑按钮仍固定 44px。

生命周期节点选中规则：

- 列表真实当前节点、详情正在查看节点、左侧选中阶段使用实心绿色点；选中文字 600 字重，无选中背景块、边框框选或阴影。
- 详情真实当前但未被选中的点为空心，仍保留当前阶段文字和 `aria-current`；历史节点通过勾号/状态文字表达，不靠颜色独占信息。
- 详情和列表连线伪元素在点后（时间轴隔离层配合负层级），左侧连线与点分层呈现，不应穿过实心点。
- 无选中边框不等于删除焦点：保留按钮、输入、阶段 Tab、面板和 summary 的 `focus-visible` 轮廓；hover 加粗不推进阶段。
- 该无背景规则针对生命周期选择，不表示全站所有导航都无背景；“全部”、四入口等仍有各自现有选中样式。

### 14.3 响应式实际结构

- **1440 等宽屏**：左侧约 212px；列表始终单主体、无右帮助栏，工具栏三列为搜索/目标/排序。单篇详情才有操作面与只读证据面。
- **960–1179px（含 1024）**：左侧 196px；列表仍单主体，详情继承紧凑 54%/46% 双栏。
- **959px 及以下（含 768）**：左侧 196px；详情证据栏隐藏，以“查看依据”抽屉替代；列表工具栏搜索占整行，目标和排序第二行，辅助复选第三行，清除条件另行。
- **767px 及以下**：整体单列，双域导航在正文前以静态块显示；左侧生命周期改为横向可滚动节点带，“全部”独立；卡片标题和底部行动换行。详情/列表时间轴节点约 100px 最小占位，可横向滚动而非强行压缩七阶段。
- **420px 及以下（含 375）**：顶部操作可另起行，列表卡片底部操作整行；部分主操作继承全宽规则，但标题栏导入和卡片下一步有覆盖，不是“所有主按钮统一全宽”。工具栏仍保留目标/排序双列。
- 抽屉宽 `min(460px,100vw)`、全视口高度；窄屏占满可用宽度，普通 dialog 宽度最多 520px、留 32px 视口边距。
- `prefers-reduced-motion` 关闭动画/过渡。375、768、1024、1440 下的实际溢出、可达性和主路径仍待浏览器验证，不能由媒体查询存在就判定通过。

## 15. 国际化与无障碍

中文和英文通过同一页面键、数据和操作处理切换，语言/字号保存为本机浏览器偏好。库领域、类型、摘要等内置中文内容及部分固定英文展示未完整本地化，不能标记全量翻译已完成。
