# 首次使用与投稿主流程修复方案

- 状态：主要工作包已在 V0.50 本地实现；验收边界和剩余细项见[执行记录](first-use-flow-v050-validation.md)。
- 基线：投稿舱 ManuscriptDock V0.49，2026-09-07 中文 macOS 原生桌面实测。
- 目标：让首次使用的学生理解当前状态、信任判断依据，并能沿明确路径完成投稿准备；无法完成时知道准确原因和恢复办法。
- 范围：本次实测的 F01—F14；相关但未实测的版本延续、任意期刊入口等单列，不混称已复现故障。
- 方案基线为 V0.49；2026-09-08 按用户指示进入修复与测试，显示版本更新为 V0.50，未提交、推送或发布。

## 1. 产品负责人先看这一页

修复顺序采用“共同状态口径 → 数据正确性 → 可操作的主流程 → 来源与版本恢复 → 新手引导”。不能先改页面布局，再让错误的作者、图表和规则继续驱动新流程。

| 顺序 | 工作包 | 解决什么 | 完成后用户获得什么 | 依赖 |
| --- | --- | --- | --- | --- |
| 0 | R0：统一状态与证据口径 | 不同页面对完成、待确认、缺件理解不一致 | 同一问题在所有页面有同一身份和含义 | 无 |
| 1 | R1：修正错误反馈 | 未选刊就材料已齐；通过项显示失败文案；运行检查等同全部完成 | 立即停止误导用户 | R0 的状态定义 |
| 2 | R2：修复论文结构识别 | 作者 9→2、图 14→1、表 2→13；文章类型未经确认 | 核对可靠的论文概况，材料数量有来源 | R0；与 R3 无实现依赖 |
| 3 | R3：修复官方要求与核验 | 时限误作篇幅、重复要求、模糊勾选 | 一条要求对应一件可判断、可追溯的事 | R0；R2 提供结构证据 |
| 4 | R4：打通检查、待办与导出 | 官网失败挡基础检查；按钮跳错；阻断不能定位 | 主流程可前进，失败可恢复，最终导出仍严格核验 | R1—R3 |
| 5 | R5：补足源稿与版本恢复 | PDF 无法修订却无下一步；修改稿可能使准备工作反复失效 | 知道如何用正确源稿继续，历史可追溯 | R2—R4；版本延续先复现 |
| 6 | R6：降低首次使用负担 | 可选表单过重、推荐不解释、同名档案难辨 | 不学技术术语也能完成首次任务 | R1—R5 的稳定行为 |

**优先交付 R1 的轻量纠错，但首个“主流程修复完成”结论必须等待 R2—R4 的联合验收。** R2、R3 可以作为独立实现切片，不必互相等待全部完成；合并到主流程前必须遵守同一 R0 合同。这里描述任务依赖，不要求使用并行 AI 代理。

不预设工期，也不把每个工作包机械对应一个版本。真正交付用户可见更新时按仓库规则递增显示版本 0.01，安装元数据同步为 SemVer，稳定应用标识不变。

## 2. 证据基线与结论边界

实测输入为《高性能智算中心网络：现状、挑战与趋势.pdf》，23 页、约 2.9 MB。首页 9 位作者，全文编号图 1—14、表 1—2；应用显示作者 2、图 1、表 13。文章内容具有技术综述性质，系统自动选择“应用型论文”；最终文章类型应由作者确认。

实际路径：新建工作区 → 默认推荐 → 自动化学报官网失败 → 基础检查被挡 → 改用备选计算机学报 → 获取 6 项要求 → 材料 5/9 → 从侧栏进入检查 → 5 通过、3 待确认 → PDF 修订只读 → “进入投稿包”返回材料页 → 从侧栏进入投稿包 → 导出禁用。

以下区别必须贯穿修复和验收：

- 官网连接失败是本次外部环境事实，Chrome 同样失败；不能据此认定应用网络代码全部失效，也不能降低公网、跳转或身份校验来换取访问成功。
- 导出因未核实的必需项被拒绝，本身合理。缺陷是要求不准确、操作不可达、状态和解释不一致，不能以取消导出校验作为修复。
- 图表在本次清单中属于建议项，不是导致最终导出禁用的四个必需确认。修复不能把所有检测图表自动提升成独立附件义务。
- PDF 只读是既有产品边界，不承诺在本轮实现完整反向编辑、OCR、公式识别或自动排版。
- 本次未保存新稿、未导出成功、未登记投稿、未测试 Windows 或英文全流程；这些不能写成已验证通过或已复现问题。

## 3. R0：统一状态、任务和失效口径

### 3.1 五个导航保留，基础检查不依赖选刊

顶级导航仍为“概览 → 目标期刊 → 投稿资料 → 检查与修订 → 投稿包”。在概览增加“核对识别结果”和“先做基础检查”入口，不新增第六个强制主任务。未选刊时可以发现基本问题；目标专属检查和正式导出仍要求当前有效目标与依据。

核对识别结果可稍后处理，不阻断运行基础检查。任何依赖尚未确认事实的结论必须显示受限状态，不能被用于精确附件要求或确定通过声明。

### 3.2 一份状态来源，多个页面展示

由 Rust 汇总当前任务状态和可执行动作；概览、侧栏、资料页、检查页、导出页读取同一状态。React 不再分别用“有报告”“阻断数为零”“空列表全部满足”判断已经完成。

建议状态至少区分：未建立依据、待处理、处理中、需要核验、有问题、当前范围已完成、结果已过期、执行失败。界面可以合并部分展示，但不得丢失实际含义。

| 对象 | 完成口径 | 不能用作完成证明 |
| --- | --- | --- |
| 结构识别 | 已识别内容可追溯，疑点单列；作者决定有记录 | 文档是文本型、解析器返回成功 |
| 投稿目标 | 当前版本目标已确认，官方依据有效且范围适用 | 有一个期刊名称或主页读取成功 |
| 投稿资料 | 已建立适用要求，当前必需项全部解决 | 没有清单项、附件数量为零 |
| 基础检查 | 已执行，明确列出通过、建议、待确认、问题和受限项 | 有报告就标记全部完成 |
| 目标最终检查 | 对当前目标、要求、材料、决定及规则版本完成评估 | 一份较新的通用检查报告 |
| 投稿包 | 最终预检通过；“已导出”与“已投稿”独立 | 看得到文件预览、点击过导出 |

### 3.3 最小共同合同

保留现有记录结构，按需增加字段，不另建通用任务平台。实现前先完成字段草案和旧记录读取测试。

| 对象 | 至少记录 | 用途 |
| --- | --- | --- |
| 识别对象 | 对象 ID、类型、原始编号／文本、页码或可用定位、来源版本、识别器版本、候选与确认状态 | 解释人数和图表计数，允许核对而不改原稿 |
| 要求条目 | 条目 ID、类别、适用条件、提交阶段、义务强度、数值与单位、来源片段及来源快照 | 防止把“1 天”和“1 页”混为一谈 |
| 作者决定 | 决定 ID、关联条目、符合／不符合／不适用／无法判断、理由与证据、绑定版本、时间 | 替代含义不明确的布尔勾选 |
| 待办投影 | 条目 ID、当前状态、阻断范围、处理动作、目标页面／对象、原因参数 | 跨页保持同一事项和真实下一步 |
| 最终评估 | 主稿、已确认结构、目标、要求、材料、作者决定和规则组合的明确版本引用或指纹 | 防止旧检查用于新材料 |

重复要求合并后保留来源列表和旧 ID 映射；不能仅按显示文字去重。每个决定和待办都必须绑定可验证的具体对象，不能用页面索引作为长期标识。

## 4. R1：先停止错误反馈

覆盖 F05、F07、F14 的状态文案部分；不等待全文解析升级才修正明显显示错误。

1. 未建立目标要求时，资料显示“仅主稿已导入／待确定期刊要求”，不显示“作者资料已齐”。
2. 按检查状态生成对应文案：通过时描述已发现的结构；未找到时才显示失败或受限文案。未知不是零、也不是通过。
3. “已运行检查”与“事项已解决”分开。3 个待确认项可以显示“已检查 · 3 项待核验”，不能笼统显示全部完成。
4. 下一步描述引用真实待办类型。缺模板核验时不能说“发现了新的图片或附件”。
5. 主界面使用任务语言；哈希、覆盖等级、机器字段路径留在可展开依据中，但来源和不确定性不能隐藏。

验收：新工作区、识别缺失、识别成功、含待确认报告、过期报告、重启恢复分别覆盖 zh-CN/en。修复显示的同时保留后台原有严格检查，不通过伪造通过状态消除提示。

## 5. R2：修复论文识别与数量来源

覆盖 F01，以及 F08 的文章类型确认。主要涉及 `structure.rs`、`journal_match.rs`、`workspace.rs` 和概览／准备树界面。

### 5.1 作者识别

- 将姓名与单位、单位序号、通信信息分开；处理中文姓名内空格、上标、跨行和中英作者重复表达。
- 首页可见作者区优先作为证据；PDF 元数据仅辅助，发生冲突时展示候选，不用元数据覆盖页面事实。
- 保留作者顺序、原始片段和来源页；不能把两条作者候选行当作两名作者。
- 提供核对、拆分／合并候选、更正及标记不确定动作；作者更正保存为来源绑定的覆盖记录，不回写原 PDF。

### 5.2 图表识别

- 区分“图表对象”“题注”“正文引用”“表格候选区域”和“独立上传文件”；这些不能互相当作数量。
- 优先依据编号、题注、页面位置及对象邻接关系建立对象清单；同一图表的中英文题注合并，多次引用不重复计数。
- 跨页表格、子图、附录编号及重复编号单独处理；不能简单用最大编号或所有表格形状区域数作为对象总数。
- 保留数字与向量图候选，不因图没有独立位图对象就漏计；无法可靠判断时显示范围或待核验，不伪造精确值。
- 独立附件数量由已核实的对象和期刊交付要求共同决定。允许官方规则认可的合并文件，但必须保留覆盖对象的显式关联。

### 5.3 识别结果如何进入下游

概览显示“系统识别／作者已核对”的区别，并提供来源页定位。第一阶段可用来源片段与页码，原生打开原稿作为回退；不能为少量定位需求强制引入完整 Word/PDF 排版渲染系统。

文章类型展示建议与依据，作者可就地改为综述等类型；修改后重新计算受影响推荐与要求适用性。暂不训练新模型，不把既有关键词推断包装成学术质量评估。

### 5.4 验收必须同时验证自动结果与降级

- 合成正常样本：9 位作者、中英双题注、14 幅图、2 个表，多栏、向量图、跨页及正文引用；自动结果应正确，不能用每次要求人工填写替代修复。
- 合成异常样本：缺编号、重复编号、扫描页、乱码、元数据冲突；应给出待核验对象，不虚报确定数量。
- 本次 PDF 作为本机人工复验材料，要求自动结果与人工基线比较并记录差异；若仍需人工修正，必须列明残余误差，不能宣布自动识别已通过。
- 作者更正后，准备树、检查、知识体来源和组包计划使用同一有效结构版本；历史解析与报告保持可回看。

## 6. R3：把官方要求变成可判断的事项

覆盖 F02、F06、F12 的数据基础。主要涉及 `journal_requirements.rs`、`declarations.rs`、`readiness.rs`、`workspace.rs` 和声明／要求界面。

### 6.1 先识别约束含义，再决定分类和执行方式

分开处理字数、页数、关键词数量、文件份数、时间期限、版式模板、投稿阶段和事实声明。识别数值时同时要求单位与上下文；“注册后 1 天内提交”属于提交时限。

同一义务的重复表达合并为一个事项，保留两段官方证据。不同适用条件、阶段或独立文件数量的要求不能因文字相似被合并。

“并非越长越好”保存为定性指导；如上下文仍暗示存在必需上限但缺乏具体数值，生成“需要补全官方篇幅依据”的待办，不自动改为无关建议以解除阻断。不能自行猜测数字。

### 6.2 四种作者决定

| 决定 | 所需信息 | 对导出的影响 |
| --- | --- | --- |
| 符合 | 对当前要求和版本的核验；需要文件的条目另验真实文件 | 满足该项条件后可解决 |
| 不符合 | 可选说明、对应修订或资料动作 | 适用且必需时阻断 |
| 不适用 | 适用条件及理由；有依据时关联证据 | 后端校验适用性后排除，不可任意豁免明确适用的必需项 |
| 无法判断 | 缺失的依据或待咨询事项 | 基础检查可继续；潜在当前必需义务未澄清时阻断最终导出 |

上传、正文存在、系统填写和真实性确认继续分开。独立文件数量、签字／盖章、允许合并、阶段和历史文件绑定等已有声明合同必须保留；不能让新决定绕过这些检查。

通用“是否需要数据可用性声明”等提示，应关联期刊要求核验任务；没有确定适用义务时，不把每条通用建议强制变成投稿附件。待办根据义务强度决定阻断范围，不能仅看“作者确认”字样。

### 6.3 旧数据处理

旧布尔确认保留为“历史已核验，决定含义未细分”，不能推断成符合或不适用。发生规则重分类、适用性变化或缺少关键含义时，针对受影响条目请求重新核验。

重新解析官方原文生成新快照，保留旧快照和已导出的包；不原地修改历史要求。已有错误分为篇幅的时限条目通过映射转入新快照，原决定不自动继承成时间义务已完成。

验收：中英文时间／篇幅最小对照句、重复义务、互相冲突的指南、模糊上限、阶段变更、必需附件缺失、合并禁止、四种决定、旧布尔记录和导出摘要均需覆盖。

## 7. R4：统一可执行待办，打通主流程

覆盖 F03、F04、F05 的操作闭环、F10、F12。优先复用现有五步导航，不制作新的独立“任务中心”。

### 7.1 页面入口和侧栏使用同一条件

| 当前情况 | 允许继续做的事 | 正式导出的条件 |
| --- | --- | --- |
| 未选期刊 | 核对结构、基础检查、整理本地资料 | 尚不允许目标投稿包导出 |
| 官网访问失败或要求过期 | 基础检查、重试、打开公开来源、粘贴原文、补充依据 | 必须取得有效且适用的目标要求 |
| 材料未齐 | 基础检查、查看部分目标检查结果、处理具体待办 | 当前必需事项解决、最终评估有效 |
| PDF 只读 | 核对原文、处理不修改主稿的事项、使用源稿恢复入口 | 需要改稿的问题未解决时不通过 |
| 条件已满足 | 直接进入组包预览与导出 | 后端再次校验真实材料和评估依赖 |

“继续基础检查”和“准备最终导出”必须清楚区别，不能隐藏地依赖用户从侧栏绕过按钮。

### 7.2 一个问题有一个明确处理入口

在现有页面顶部放当前范围的待办摘要，分缺文件、待核验、需修改、缺依据／已过期。每项点击跳到具体条目并展开、滚动、聚焦；返回后保留阅读位置。

按钮名称由实际动作生成：例如“处理 3 项待核验要求”“重新检查最终材料”“查看投稿包”。数字来自当前合同，不固定为实测中的 4 项；R3 合并重复要求后数量应一致变化。

目标检查界面分别展示通用规则结果和期刊专属事项；明确哪些是自动判定、哪些只是人工核验状态。不能用两套通用规则的成功冒充已自动验证该期刊的全部要求。

### 7.3 最终导出评估

最终报告显式绑定主稿、有效结构、目标、要求快照、材料纳入计划、作者决定和规则组合。任一依赖变化，相关评估失效并说明原因；采用原子保存和后端复验，防止页面过期或重复点击绕过检查。

仅建议项未完成可导出时，要保留未解决说明；当前适用的必需项不符合、未知或文件缺失不得导出。已解决确认与当前评估的关系明确，不要求每次重复点击所有确认。

验收：官网离线、无目标、无材料、部分必需项未完成、可选文件取消纳入、检查中途变更附件、重启恢复、导航深链接、键盘焦点、阻断后恢复到导出。使用合成材料实际生成并检查 `submission/` 与 `records/`，不以按钮变亮代替验收。

## 8. R5：提供诚实的源稿与版本恢复路径

覆盖 F11；同时处理相关但本次未实测的新版本回退风险。

### 8.1 PDF 用户的最小可用恢复

导入时说明“PDF 可检查，不能直接改写；如需修改请使用 DOCX/TEX 源稿”。修订页提供“查看问题所在原文”“选择源稿继续准备”，不给只读空页面安排误导性的成功下一步。

当前版本库要求同格式，不能将 PDF→DOCX 直接写成原工作区 v2。推荐本轮采用可明确解释的最小方案：

1. 原生选择 DOCX/TEX 后，说明将建立一个源稿工作区，并保留原 PDF 工作区。
2. 作者确认两份材料属于同一论文后，建立双向来源关联（原工作区／源稿工作区标识、文件指纹、确认时间）；不以标题相似自动认定等价。
3. 源稿工作区从自己的 v1 开始。原目标和未变公开资料只作为可复核候选；检查结论、声明真实性和文件适用性不自动复制成完成。
4. 提供“返回原 PDF 档案／继续源稿准备”，首页显示关联关系，避免制造两个无法辨识的新重复档案。

这是一条显式关联恢复路径，不是格式转换或同一版本链合并。需要补充 ADR 并更新版本库文档后实施。长期同一工作区多来源链另行设计，本轮不顺带重构整个知识体身份体系。

### 8.2 修改稿延续先复现，再实现

使用合成 TEX 或 DOCX 走“目标与材料完成 → 修改安全字段 → 保存新版本 → 继续导出”。先确认旧目标、要求、材料、决定和检查分别如何失效。

若复现准备工作反复重做，则增加“上一版准备结果复核”：保留同一期刊为待复核目标；未改要求可生成有来源的新绑定；材料按指纹和用途提出沿用候选，由作者确认；受改稿影响的正文声明和语义事项重新核验。新版本最终检查必须重做。

在完成该复现前，此项只能标为风险与计划，不能在完成报告中称已修复本次实测 bug。

## 9. R6：降低新手负担，保留必要解释

覆盖 F08 的推荐解释、F09、F13、F14；以已有行为正确且可继续为前提。

- 初次选刊页优先展示论文主题、语言、文章类型和“生成推荐”；学校、用途细项、模型抽取、全部规则折叠。默认截止日期改为可选或清楚标注“建议准备期限”，不冒充作者填写。
- 推荐成功后聚焦结果并播报完成；卡片用现有可证实信号解释适配和不适配，不编造学术创新性、录用率或新的评分证据。候选不足时说明筛选限制。
- 规则选择提供有依据的建议组合、适用原因及“查看全部”；医学规则不默认占据计算机论文首屏，但不能因自动分类就静默采用规则。
- 本地期刊画像与官方要求分开命名并说明可选性。基础任务不强制设置模型；任何模型发送范围仍邻近操作明确呈现。
- 文件入口提供用途、官方模板链接（确有来源时）、合成示例、允许格式与缺失处理。示例标“示例”，不能自动作为实际伦理、签字或作者声明上传。
- 导入先按内容指纹发现已有本地档案，提供继续已有或明确新建独立工作区。相同内容不制造新版本；同名不同内容提示选择归属；列表显示更新时间、版本、目标、阶段和关联来源。
- 收起实现术语和未来功能宣传，保留当前可做的动作、限制和恢复入口。初次导入成功后直接进入概览，保存说明作为简短反馈。

验收：不配置模型、不填写学校，学生能完成首次推荐；同内容和同名不同内容可区分；三档字号及中英文下主操作可见、结果聚焦正确、键盘可用。使用普通桌面与较窄窗口验证，无需为本轮新增移动端产品。

## 12. 数据保护、国际化与验证交付

### 12.1 兼容和恢复

新结构、规则和决定使用可识别的模式版本；旧源稿、报告、官方快照、导出包保持不可变。打开旧工作区时只对受影响派生数据提示重新计算，不静默改写所有历史结论。

升级先验证读取和迁移，再原子写入新记录。失败保留原文件和可恢复状态；不得出现一部分页面使用新 ID、另一部分仍使用旧确认的混合结果。旧版本若不能识别新写入格式，应明确只读或拒绝安全写入，不承诺无条件降级兼容。

解析更正可能改变知识体候选。重新生成候选必须保留来源与历史作者决定；不能直接覆盖已固化知识体或把旧作者确认自动套到新文本。

### 12.2 双语和无障碍

每个工作包同步覆盖 zh-CN/en 的界面、动态错误、规则与来源标签、数量、四种决定、失效原因、可访问名称和导出摘要。复用 `useI18n().text`、`localize`、`localizeBackendText` 及既有双语字段；新错误优先采用稳定代码和参数。

原文题注、作者姓名及官方引用保持原语言。中英文引导都要测试焦点、展开状态和返回位置；不能只以首页切换语言通过作为证据。不新增国际化专用 Git 钩子或强制构建阻断。

### 12.3 最小联合验收矩阵

| 场景 | 应看到／得到的结果 |
| --- | --- |
| 全新工作区，尚无目标 | 显示待建立要求，可直接运行基础检查 |
| 正常与异常多栏 PDF | 正常样本自动提取正确；异常样本可核对、可定位，不输出虚假确定数量 |
| 官网超时、拒绝访问、无正文 | 保留失败原因，可继续本地任务；不放松网络边界 |
| 官方时限、篇幅、重复或模糊要求 | 分类、合并和适用性正确；模糊义务有补证路径 |
| 四种作者决定与必需文件 | 决定可持久化；不适用有依据；勾选不能替代必需附件 |
| 材料未齐、部分检查完成 | 导航一致；下一步定位实际未完成项 |
| 目标／要求／附件／决定／规则变化 | 对应最终评估失效；原因可见；历史保留 |
| 所有当前必需项解决 | 实际导出成功；出版社文件和内部记录隔离，清单指纹及来源可复验 |
| PDF 补充源稿、同格式修改稿 | 关联关系或版本链符合各自规则；不冒充自动格式转换 |
| 重启、旧工作区、新旧数据读取失败 | 当前状态可恢复；失败不破坏原记录 |
| 中文与英文，默认与较窄窗口、三档字号 | 动态内容完整，按钮与去向一致，键盘可完成任务 |

先运行所改模块的合成回归，再运行仓库现有统一检查 `npm run check` 和对应平台构建。原生文件选择器、工作区保存、来源跳转、导出与重启需在 Tauri 真机验证；浏览器模拟、测试数量和构建成功都不替代这些结果。

真实网站验证与离线确定性回归分开记录。真实论文仅在本机复验解析，不上传模型、不假填声明、不重新投稿；成功导出闭环使用合成稿件、合成附件和明确测试声明。

### 12.4 每批交付应包含

1. 对应问题编号、修复前后行为和未完成项。
2. 数据合同／迁移影响及失败恢复办法。
3. zh-CN/en 自动化与原生页面证据；平台和未测范围。
4. 实际生成文件核验，而非只有状态截图。
5. 同步更新的产品文档与用户手册。
6. 单独报告代码、测试、提交推送、构建／安装／发布状态；未获授权不自行提交、推送或发布。
