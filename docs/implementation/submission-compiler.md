# 投稿包整理器详细实现

- 状态：部分实现；V0.54 已实现 PDF／DOCX 保留式复制、PDF 草稿与显式可编辑 DOCX 正式包边界、作者工具、出版社文件、严格 ZIP、哈希清单、事务导出，以及匿名稿中已确认作者姓名／单位／邮箱的 XML／关系部件完全匹配扫描。真实页预览、正文局部变换、自动匿名、图片／嵌入对象身份识别及双平台渲染仍未完成；本文件未标为已实现的部分继续作为约束。
- 关联：[合同与状态](contracts-and-state.md)、[期刊规则](journal-data-and-matching.md)、[验收](validation.md)。

## 1. 目标与明确边界

输入是不可变 DOCX、作者选择的附件、有效作者事实和内置目标规则。输出是可核对的投稿材料与出版社材料 ZIP。不是从 PDF 反向写 Word，也不是通用全文编辑器。

同一期刊不同文章类型可能需要不同文件。不满足规则时指出缺项，不自动编造研究贡献、伦理审批、基金、未一稿多投和推荐审稿人关系。Word 的复杂布局或引用域不能安全变换时保留内容并给出人工任务，不降级重建成纯文本 DOCX。

## 2. 处理管线

```text
验证源与附件 → 获取有效事实 → 组合目标规则 → 生成 PackagePlan
 → 分类作者任务／自动操作 → 生成 staging 文件
 → 结构与语义保真检查 → 匿名与必需材料检查
 → 本地实页预览／报告 → 固化 CompiledPackage
 → 作者选择本地目录 → 验证上下文 → 写入与复核 → 导出回执
```

每一阶段有明确输入 hash、输出 manifest、取消点和错误；失败不得继续标为成功。计划阶段不修改源稿，正式导出不能跳过输出验证。前端保存按钮只传递意图，后端重新验证当前事实和产物。

## 3. DOCX 支持档案

| 档案 | 特征 | 首批策略 |
| --- | --- | --- |
| D1 常规稿 | 段落、标准标题、表格、嵌入图片、脚注、常规公式 | 在支持操作范围内整理；未修改内容必须保持 |
| D2 复杂稿 | 文本框、浮动图、多节、域代码、交叉引用、引用管理器字段 | 可解析与原样保留；具体变换需独立验证 |
| D3 高风险输入 | 加密、宏容器、破损关系、嵌入可执行对象、非法路径 | 拒绝或仅提示另选安全源；不执行内容 |

分类按特征而非仅扩展名。预检读 `[Content_Types].xml`、关系文件、文档主体、样式、设置及相关 parts，枚举外部关系和不支持对象。解压执行限额与路径检查。文件夹输入和原稿选择复用同一校验器。

内部 DocumentFacts 保存原始 part、段落或对象 ID 定位；结构核对不需要完整渲染也能定位内容，但页面号只能来自最终分页结果。识别不到的内容记录未覆盖，不误判不存在。

## 4. 主稿变换策略

采用 OOXML 包级保留、局部 XML 变换：复制所有未改 parts，只修改明确支持的节点及关系；使用解析器，不用正则表达式替换全文 XML。不用另起空白 DOCX 重建整篇论文。

| 操作 | 首批实施 | 验证与退路 |
| --- | --- | --- |
| 标题层级／样式 | 仅明确匹配到的段落，保留内容 | 核对文本、样式与标题树；未知样式不强行映射 |
| 页码／行号 | 根据目标与节属性设置 | 各节、首页例外、页眉页脚实页验收；不覆盖原有复杂域 |
| 分离标题页 | 从确认的作者与机构事实生成 | 原文研究内容不删除；需匿名时另走匿名策略 |
| 摘要结构 | 检查标题和词数，允许作者填结构化字段 | 不自动重写科学内容；不合规保持待办 |
| 图表位置 | 首批默认保留，按目标复制独立附件 | 不随意重排浮动对象；缺高质量原图向作者请求 |
| 引用格式 | 先检测完整性；仅可解析、无复杂域的受支持条目才转换 | CSL 样式与真实 bibliographic data 分开；不支持的字段提示外部调整 |
| 修订与批注 | 检测并列出作者决定 | 不静默“接受全部修订”；确认后生成新派生稿并复验 |

每个 Transform 定义 preconditions、readParts、writeParts、expectedSemanticDelta 和验证器。未通过前置条件就不执行，不能只发 warning 后继续声称已整理。受影响的内容必须在差异预览中显示。

保真检查覆盖：规范文本序列、表格单元格、公式节点、图片／附件字节哈希、引用目标、脚注与尾注、书签及关系完整性。允许的差异只来自明确计划，例如匿名时移除身份字段；仅对 XML 字节整体比较不足以验证内容保真。

## 5. 模板生成器

本地维护 DOCX 模板，采用类型化占位字段与版本。占位符不跨任意 OOXML 节点拆分；模板加载时检测字段集合与 schema，生成时转义用户输入。模板与测试都是合成信息，不含真实作者资料。

| 文件 | 数据来源 | 完成条件 |
| --- | --- | --- |
| Title page | 已确认作者、单位、通讯方式 | 与作者事实一致；独立文件按规则组织 |
| Cover letter | 题名、期刊、作者确认的贡献与声明 | 模板陈述不超出事实；所有必需声明确认 |
| Highlights | 作者提供或确认的要点 | 条数和长度符合规则，不自动虚构贡献 |
| Declarations | 基金、贡献、利益冲突、伦理、数据、AI 使用 | 依据适用规则，空值与“不适用”区分 |
| Reporting checklist | 明确对应内容及最终定位 | 有依据项填写；缺项不自动回答 Yes |
| Submission fields | 全部已确认元数据与文案 | 本地字段视图和 XLSX 内容一致 |
| Compliance report | 有效规则、检查、限制、确认与产物 | 作者工具，不作为出版社必需文件混入 ZIP |

编译器没有云模型依赖。对不能从事实直接生成的文本，给作者短字段编辑；未来小型本地生成模型另立能力，不成为首批模板生成的必需条件。

## 6. 匿名处理

只在规则明确要求时启用。配置说明应移除或另存哪些身份字段，而不是假设所有期刊都双盲。

检查范围：作者和机构段落、致谢与基金的期刊特定处理、页眉页脚、批注和修订作者、文档属性、自定义属性、图片替代文本、嵌入对象元数据及正文可能自我识别表述。

正文自引、研究地点或试验注册号可能既有学术必要性又暴露身份，不能一律删除。确定性命中形成复核任务；不确定的嵌入对象无法检查时，阻止匿名包的正式完成，允许作者提供已核验的替代匿名稿。

匿名稿生成后再次独立扫描，不只验证“作者字段变空”。Publisher ZIP 中主稿按目标使用匿名版；实名源稿不得误入。同一投稿系统可能要求独立标题页，其槽位用途必须明确，不能把整个压缩包宣传为可盲审转发。

V0.54 当前只对作者确认事实中的姓名、单位和通讯邮箱执行确定性完全匹配：扫描 DOCX 的 XML 与关系部件，事实变化后重新检查，编译前再做一次防御性扫描；命中类别进入双语阻断提示，但不把身份原值发送到 WebView。该检查可发现正文、页眉页脚、批注和常见属性中的相同文本，不能发现别名、自引语义、图片文字或不透明嵌入对象，因此通过不等于已经证明完全匿名。PDF 仅用于本地匹配和草稿检查，不参与这项 DOCX 身份扫描；正式包必须绑定作者明确选择的可编辑或匿名 DOCX，不能用改扩展名的 PDF 代替。

## 7. 图表、附件与报告清单

按内容哈希识别重复文件，但不能据此自动认定两个独立要求允许共享。输入类别、必要数量、格式、尺寸等按可验证项检查；Word 内嵌图片仅证明存在，不证明具备投稿所需分辨率。

Excel／表格输出保留数值与文字，不执行来自稿件的公式；填写表中以 `= + - @` 等开头的作者文字应作为显式字符串，防止被表格软件解释为公式。未知表格结构不自动 OCR 重建数字。

报告清单使用章节／段落引用先组织，只有最终渲染后页码才能固化。没有可靠分页时不填假页码；期刊强制页码对应而渲染不可用时，保留作者待办，不能放行最终包。

## 8. 本地渲染与格式输出技术试验

### 8.1 DOCX 预览及 PDF

首选试验路线是受控本地 LibreOffice 子进程将派生 DOCX 渲染为 PDF，不用它把 PDF 改写回 DOCX，也不用一次 round-trip 转换替代 OOXML 保真策略。官方文档提供 headless、convert-to、outdir 和独立用户配置参数；这些只证明可调用，不能证明格式准确或没有联网。[LibreOffice 官方启动参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)

试验必须比较：Windows/macOS 打包与许可、隔离 profile、进程生命周期、字体可用性、公式／多节／中英文排版、失败退出、体积与冷启动；不得修改用户 Office 设置、静默安装系统软件或开放 UNO 网络监听。宏禁用、外链不刷新及网络隔离需实测，headless 不等于安全沙箱。

通过后把渲染器与所需获准字体纳入离线发行资源，由 Rust 使用参数数组启动，超时终止进程树。渲染结果只供预览／报告，正式主稿仍使用已验证 OOXML 产物。用户输入不得构成 shell 命令。

如果试验不能满足上述条件，选择其他可本地发行的渲染器并记录 ADR；试验失败期间仅开放标明限制的草稿和文件清单预览。最终承诺的实页预览、报告 PDF、页码清单不得以 HTML 假替代，工作包不能标成完成。渲染器定案是完整公开交付的前置，不是让作者运行命令的产品流程。

### 8.2 XLSX 与 ZIP

XLSX 在独立生成器中采用能产生标准 OOXML 的 Rust 写库；工作包内以字符串、长摘要、Unicode、多作者和公式注入样例选型并验证许可证，锁定依赖后再接入。不因已有 XLSX 读取器就声称已经具备写入能力。

ZIP 复用现有 zip 依赖，文件列表完全来自已验证 manifest。路径为包内相对路径，防止穿越、大小写冲突与重复条目；不把目标绝对路径或其他项目文件写入。

## 9. 预览、语言与差异

预览文件读取的是本次 CompiledPackage，不能重新拿原稿渲染后冒充结果。内容有变化时显示实际差异和变换原因；没有变化的保留稿明确写“保留原稿格式”，不声称进行了排版。

界面说明支持 zh-CN/en；稿件和原始引文不翻译。投稿信等面向出版社的文件遵循目标要求和作者确认的文档语言；报告及作者工具采用指定说明语言。改变显示 locale 不应无理由使已确认科学内容失效。

## 10. 输出与恢复

```text
<论文>-<期刊>-<版本>-<导出标识>/
  submission/              主稿和目标要求的附件
  author-tools/            字段 XLSX、核对 PDF 等
  records/                 规则、作者确认与产物 manifest
  publisher-files.zip      只包含 submission/ 的条目
  README.txt               各目录用途及未执行真实投稿
```

父目录名称可能包含作者自定义信息；ZIP 内文件名按匿名规则生成，不能把含作者名的原始文件名照搬到匿名材料。publisher ZIP 是便于取用的材料集合，不保证期刊系统接受整包上传。

正式导出顺序：锁定上下文→校验生成物→在目标父目录创建唯一暂存目录→写入→回读哈希／ZIP 条目验证→原子重命名→保存回执。目标磁盘不支持预期原子语义时必须实测替代事务行为，不把半成品目录标为成功。

导出回执写入失败但文件已完成时保留结果并返回“文件已保存，记录待恢复”，下次按导出 ID 和 manifest 对账；不盲目重导。空间不足、权限拒绝、进程中断只清理本次临时文件，既有输出和原稿不受影响。

正式编译与保存需通过[验收矩阵](validation.md)，ZIP 创建成功或 Word 可以打开并不单独证明目标要求全部满足。
