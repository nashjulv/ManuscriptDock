# 旧代码重写、删除与用户数据处置

- 日期：2026-09-14；状态：V0.54 已完成运行时处置，文档迁移仍按独立计划推进。
- 用户授权：实际实现可全部修改原代码或交互，只保留有用内容，无用内容可直接删除。
- 决策：[ADR 0011](../adr/0011-rebuild-core-and-retire-legacy-flows.md)。

## 1. 判断标准

保留的是经过验证且服务于两个任务的能力，不是原来的文件名、类型名或代码组织。可以重写整个 App、命令层和工作区层；不要求与旧界面、旧 IPC、推荐依赖或知识体 schema 全面兼容。

不把无用模块移进 `legacy/` 后继续随应用编译，不用永久 feature flag 保留云服务入口，不为了通过旧测试恢复已经取消的产品行为。每批删除同步清理调用、导出、依赖、资源、样例与文档；Git 保存源代码历史。

用户论文和已导出文件不是“无用代码”。数据处置遵守明确边界，不因删除功能而静默清空资料；无须维护完整旧功能才能保留历史文件。

## 2. 模块处置清单

路径均相对仓库。分类是后续实现的默认动作；实际删依赖前核对调用图，不根据名称猜测。

| 旧位置／能力 | 动作 | 新落点与完成条件 |
| --- | --- | --- |
| `apps/desktop/src/App.tsx` | 重写 | 两任务 AppShell 和 feature 页面；删除旧生命周期路由、靶图、模型弹窗及相关状态 |
| `styles.css` | 重写并提取少量有效令牌 | 清除旧面板与知识体样式；保留经过验证的颜色、字号和焦点规则 |
| `typography.css`、TextSizeSettings、窗口恢复 | 优先保留可用部分 | 用新页面验证，不为新布局保留旧固定宽度 |
| ActionGuidance | 按新动作合同重做 | 保留清楚错误与定位能力，删除旧阶段 prerequisite 映射 |
| StructureReview、DeclarationRequirements、RequirementDecision | 按需提取业务控件 | 作者事实与材料输入整合到准备页；不强制保留组件 API |
| PackageExportStatus、SourceRecovery | 重做视图 | 服从新任务与回执合同，不再挂接旧投稿登记或源稿链导航 |
| OfficialSourceAccess 与对应测试 | 从客户端删除 | 普通作者不抓取官网；有用公共抓取工具如确需复用则独立开发工具，不进入运行图 |
| Tauri `lib.rs` | 重建命令注册与服务装配 | 删除云模型、网页发现、存证、问答、知识体、备选转投等命令，新增直接目录选目标 |
| `model_service.rs` | 删除 | 不保留 API Key 设置、failover、远程问答和内容外发实现 |
| `official_sources.rs` | 默认删除运行时实现 | 来源规则来自仓库内置；不为维护设新客户端服务 |
| `workspace.rs` | 拆解并可整体替换 | 源稿存储、材料、事实、编译、导出归新模块；不保留万能 WorkspaceLifecycle |
| `knowledge.rs`、`dialogue.rs` | 删除运行时模块与公开导出 | 不重建知识体模型；旧文件原样保存在旧数据根 |
| 存证／人工投稿登记／备选路线 | 删除产品命令与页面 | 输出回执只是文件保存记录；当前目标不依赖实际投稿状态 |
| `journal_match.rs` | 重写算法与 DTO | 静态候选、层级准备天数、成熟度代质量、国内国外 2/3/3 淘汰 |
| `journal_directory.rs` | 保留身份归并、SQLite 与 XLSX 中有效部分 | 删除模型发现混合逻辑，增加真实动态候选接口 |
| `journal_requirements.rs` | 重写入口／提取有用数据类型 | 客户端主要加载内置配置，不维护网页抽取工作流 |
| `structure.rs`、`recognition.rs` | 提取 DOCX 与定位能力 | 不再为知识体构建全部语义对象；复杂 PDF／LaTeX 新任务路径可删除 |
| `revision.rs` | 替换成受限变换组件 | 保留已证明安全的逻辑，删除通用修订台和不需要的 TEX 写回 |
| `declarations.rs`、`readiness.rs` | 提取约束与验证语义后重组 | 事实不编造、附件不混用、未知不通过；旧字段与接口可删除 |
| `rule-packs/` | 有效规则继续数据化 | 无关学科和无实际适用的包可不随新版发布；签名内容不就地篡改 |
| `packages/ui`、`packages/contracts`、空泛 schemas | 无消费者则删除或替换占位说明 | 不为历史架构创建额外 npm 包；新增 schema 只服务新合同 |
| 旧功能测试 | 删除已取消行为，保留有效不变量 | 不以减少测试数为目标，也不保留测试数量作验收指标 |
| 旧截图／演示／文档 | 按文档治理归档或删无价值重复 | 受保护研究路径本轮不动，真正迁移时独立核对引用 |

## 3. 依赖与资源清理

远程功能删除后核对 reqwest、keyring、scraper、encoding_rs、url、flate2 等是否仍被有用路径引用；只删除无消费者项。PDF 深解析淘汰时同样核对 pdf-inspector、pdf-extract、lopdf；报告渲染或验证需要的依赖不能误删。

清理顺序：旧路由／命令调用→业务实现→公共类型与导出→依赖声明→锁文件→已不引用资源与配置→对应文档。一次工作包允许重建而不保留旧 API，完成时整个构建图必须闭合。

核对 Tauri capabilities、CSP、bundle resources、平台配置、前端静态字符串、安装说明和测试 mock；仅删 UI 不算删功能。CI、构建和系统窗口能力只在新功能仍有需要时保留。

API Key 读取与使用代码删除，不主动访问或清空用户系统凭据库。已经存储的凭据可在后续明确的数据管理需求中处理；不能把凭据清除设为首次使用步骤。

## 4. 旧任务数据边界

早期产品版本尚未上线，用户已确认这些任务数据不需要继续使用。V0.54 因此不提供旧任务列表、自动扫描、显式导入、字段迁移、迁移映射或中断恢复，也不为旧 schema 保留读取类型和错误文案。

移除兼容运行时不等于删除文件。应用不会遍历或清理旧工作区、原稿、附件、导出、凭据或历史记录；这些磁盘内容保持原样，但不出现在新版界面，也不被新版项目服务读取。若用户以后需要某个文件，应通过普通系统文件选择重新建立当前项目，而不是恢复旧任务状态。

当前项目仍使用独立的 `workspace-next` 存储根。首页“最近任务移除”只修改 `recent-hidden.json`，可以恢复，且不会删除当前项目 manifest、源快照、材料或生成包。

## 5. 实施与删除验收

1. 先记录源码与命令引用清单，以及当前输入输出不变量，不备份真实稿件到仓库。
2. 按工作包建立新服务、UI 和必要存储，旧实现可在同批直接替换；不要求两套产品长期共存。
3. 删除被替换调用与功能代码后，检查新应用仍只有两个核心入口，旧命令无法调用。
4. 保留核心安全／数据测试，删除只约束被取消体验的测试；新失败场景补齐。
5. 执行受影响测试与编译，再做两任务原生验证。删除量和测试数量都不等于成功。
6. 以源码扫描和双语界面测试确认旧任务入口与命令不可达；不读取或改写真实旧目录。

本计划允许广泛重写，不要求逐文件再确认常规代码删除；遇到原稿、凭据、其他项目或无关用户改动则不在该授权范围内。完整原生验收通过前，不替换用户日常安装或执行部署。
