## 2. 合成样例目录

只在实现对应功能时创建 fixtures，不先提交无法执行的空测试。

- D1：中英文常规稿、不同标题风格、长摘要、多作者、表格、公式、参考文献与脚注。
- D2：多节、首页不同页眉、浮动图片、文本框、交叉引用、复杂引用域、批注和修订。
- 输入异常：损坏 ZIP、缺关系、重复条目、加密文档、超大解压、目录越界链接和多主稿文件夹。
- 匿名：姓名在属性、批注作者、页脚、图片替代文本和嵌入对象；自引或研究地点需作者判断。
- 声明：伦理适用／不适用／未知、基金缺失、独立附件不得共享、修改后旧确认失效。
- 规则：合法继承、指定例外、同级冲突、失效、停用、缺官方依据、错误签名和未知 schema。
- 目录：重复 ISSN、同名不同刊、刊名更改、缺 APC、币种不一致、混合 OA、数据年份不符。
- 存储：当前 schema 的小部分坏 JSON、索引重建、源文件哈希变化、输出回执写失败、最近任务隐藏与恢复。

构造期刊软件样例时显式标为 synthetic，不把合成要求伪装成真实期刊政策。真实官网规则及其短证据可按许可记录进入库，真实未发表稿件不得进入仓库或公共验收报告。

## 3. 必须走通的两个正向场景

### A — 尚未选定期刊

1. 干净离线环境启动应用，无账号和模型配置。
2. 从“推荐期刊”打开本地 DOCX；取消一次选择后仍可继续。
3. 核对一页偏好，选择本地机构名单或跳过。
4. 查看最多三本及依据，修改一次预算并确认结果按条件变化。
5. 选择期刊进入整理，论文和已知事实不重新填写。
6. 补一项事实和一份附件，自动更新缺项。
7. 查看实际派生文件，保存到选择的目录。
8. 打开输出与 ZIP；重启后能找到已完成结果，原稿不变。

### B — 已有目标期刊

1. 从“整理投稿包”直接在本地目录选定期刊，整个过程不创建假推荐记录。
2. 打开材料文件夹；多个主稿候选时选择正确主稿，处理一个未知附件用途。
3. 自动加载内置要求，补齐缺项；不抓取官网，不要求阅读一整份指南。
4. 更换目标后材料仍在，规则和文件用途更新，旧确认仅在有效时保留。
5. 先保存明确标识的草稿，再补齐关键项并正式保存。
6. 输出文件、作者工具与内部记录分离；不要求登记真实投稿。

两个场景均在 zh-CN/en 和 Windows/macOS 执行。界面语言改变不自动翻译论文或改变投稿信目标语言。

## 4. 失败与并发矩阵

| 用例 | 必须观察到的结果 |
| --- | --- |
| 选择取消／损坏／不支持／超限 | 无伪项目成功；可以就地重新选择 |
| 目标规则未覆盖 | 通用草稿标识；不可称具体期刊已合规 |
| 硬条件 fail／unknown | 排除或未知池；不以高分绕过 |
| 返回修改、新目标早于旧任务完成 | 旧响应不覆盖新视图或生成物 |
| 作者确认后改事实、附件或规则 | 受影响确认失效并自动重查 |
| 匿名存在不支持嵌入对象 | 不假通过；提供替代匿名稿或人工处理路径 |
| 渲染器缺失、超时、字体问题 | 明确失败与能力限制，不拿原稿预览冒充派生稿 |
| 无权限、磁盘不足、网络盘特殊写语义 | 不显示正式成功；已完成输出与输入不受损 |
| 文件写完但回执失败 | 保留输出并可对账恢复，不盲重导 |
| 同 requestId 重试、重复点保存 | 返回同一次逻辑任务结果；明确另存才创建新导出 |
| 中途退出／取消／重启 | 任务终态可解释，未完成输出不当完成项目 |
| 当前项目某个未知字段或坏记录 | 隔离该记录，不阻断其他项目；不修改其他原稿 |

## 5. 生成物验收

对每种受支持变换建立独立内容 oracle，不只断言实现函数返回成功。核对允许变化以外的规范文本、表格值、公式、图件字节、脚注尾注、引用、关系目标和研究声明。

DOCX 在至少一台真实 Microsoft Word 上打开检查，结合本地渲染 PDF 逐页查看；XLSX 在 Excel 或兼容阅读器核对字段、长文本与显式字符串；PDF 检查中文字体、截断、页码与报告状态；ZIP 解压后与 manifest 一一比对。完成文件层验收后再对照目标指南逐项核对，不用预览外观替代规则核验。

关键错误零容忍：内容丢失或篡改、匿名泄漏、虚构声明、必需文件漏出、内部记录误入出版社 ZIP。一般规则误报与漏报分别统计；<5% 只是开发目标，不能用总体平均掩盖关键错误。

发布覆盖矩阵按期刊×文章类型×阶段×DOCX 特征档案记录“已验证／部分／未支持”，不是笼统声称支持某期刊所有论文。

## 6. 推荐效果与性能

先建立固定确定性基线，再比较语义增强，独立评测集不参与调权。已发表论文测试需移除刊名、出版 DOI、页眉模板等答案线索，索引剔除原文及近重复版本，尽量使用投稿时点以前数据。

实际发表期刊进入 Top 5≥60% 仅作为辅助目标，UI 仍最多三本。记录样本期刊是否在支持目录、年代、文章类型、作者真实约束是否可得；不能排除未命中样本后只算成功子集。专家对前三本合理性≥80% 需说明是卡片级或整组级，本方案默认整组：三本均无已知不合理项，缺位按实际可推荐数量评判，并单列覆盖不足。至少两位领域评审记录分歧。

首轮样本建议：开发集至少 30 篇，独立测试集至少 50 篇、覆盖不少于 10 本目标期刊；小样本只作工程初验，不据此对外宣传普遍准确率。正式规模可按实际领域调整并先冻结口径。

性能基准固定 CPU、内存、OS、DOCX 字数／图表数、目录规模、资源版本。分别测冷启动与资源就绪后的 P50/P95。建议参考档案为 4 核 CPU、8 GiB 内存、30,000 词以内、20 幅图、20 张表、50 MiB 以内；这是待验证目标，不承诺所有 250 MiB 可选文件都满足三分钟。

三分钟统计推荐与准备清单，作者补事实、初次安装不纳入。生成、渲染和保存另计；人工剩余操作按资料齐备／不齐备分组，目标 10 分钟，未知事实等待时间不伪装成软件节省。

## 7. 隐私验收

核心两任务在断网下通过只是必要条件，还须在联网但受观测环境中检查实际出站。使用合成唯一标记填入标题、摘要、正文、文件名、附件和异常输入，观察应用与渲染辅助进程、日志和错误处理是否外传。

测试带远程图片、外部 OOXML 关系、字体 URL 和恶意网页引用的稿件；解析与预览不得自动请求。确认发布包无旧云模型／网页命令可调用，无内容遥测、默认网络依赖和可执行规则脚本。不能靠 UI 静态“0 KB”作为证据。

分别说明观测范围、工具、时间窗口及发现；不声称控制所有用户同步软件。保留以前发生的外发历史，新状态只描述本次任务。

## 8. 已有可执行检查与后续脚本

现有仓库已声明且可用于相关代码变更的命令：

```bash
npm run typecheck
npm run test
npm run build
cargo test --workspace
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
git diff --check
```

`npm run check` 已组合上述主要检查；每工作包先运行受影响测试，集成阶段运行完整检查，不无依据重复全量测试。上述测试当前覆盖旧实现，替换后须更新测试语义。原生验收与生成物实页 QA 另做；尚不存在的新脚本只有实际创建并验证后才能写成执行命令。

不因国际化要求新增强制 Git hook 或独立阻断机制。zh-CN/en 的字段、错误、解释、可访问性、模板说明和导出物纳入相关功能测试，不另造形式化门禁。
