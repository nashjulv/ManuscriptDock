## 1. 实现原则

围绕“推荐期刊”和“按目标期刊整理投稿包”重建实现。用户已明确允许重写或删除旧代码、接口、交互和无用功能；不以保留旧页面、模型或状态机作为设计目标。只保留能证明有价值的基础能力与数据完整性约束。

删除旧产品代码、隐藏最近任务与删除用户文件是不同操作：V0.54 已移除无用运行时代码和未上线的早期任务扫描／导入／迁移功能；最近任务“移除”仅写入可恢复隐藏索引。应用不主动清理旧目录，但也不再读取它们或创建新版副本。

## 3. 首批交付定义

- 同一个桌面应用内的两个任务；已知目标不依赖任何推荐记录。
- 打开本地 PDF、DOCX 或材料文件夹，直接处理，自动保存并恢复进度；同一个规范化文件夹始终对应同一个项目记录。
- 一页偏好与最多三个解释充分的候选，硬条件未知不冒充通过。
- 按内置目标规则整理必要文件，作者补事实，预览后本地保存。
- AI 与人工只在团队整理公开期刊资料时使用；人工维护直接改仓库配置，不建设维护功能。
- 正式版本不依赖云端模型、期刊实时抓取、PWC、账号或首次在线下载。
- 实际生成能力以经过测试的文档特征与规则覆盖为界，不能用源稿复制代替自动整理完成。

## 4. 决策等级

已确定：Tauri/Rust/React、两个任务、新 IPC、只读原稿、模板文档与受限 OOXML 变换、配置内置、删除远程内容调用与无用生命周期能力。

仍需在对应工作包内完成的技术试验：DOCX 实页预览与报告 PDF 的可发行本地渲染器。XLSX 已采用 Rust 写库并验证字符串／Unicode／单页横向输出；本地嵌入模型因缺少授权发行与独立效果证据而明确不启用，保留确定性推荐。详见整理器、推荐和工作包文档。

需由真实样本决定：首个子领域与文章类型、最终 10—20 本期刊、性能支持档案。准备规则和编译器可先用合成稿件及 3 本真实规则试点；扩大覆盖前确定这些选择。
