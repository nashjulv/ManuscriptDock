# ManuscriptDock 学术知识体服务模型

- 状态：核心产品定义
- 日期：2026-08-24
- 适用范围：产品设计、领域建模、商业模式、市场传播及 PWC 协同

## 1. 核心判断

ManuscriptDock 的用户和付费主体是作者、研究团队与机构，但平台长期管理和持续服务的
核心对象，是一篇论文形成的学术知识体。

> ManuscriptDock 不是为作者提供一组彼此分散的论文工具，而是为每个学术知识体提供
> 从形成、校验、排版、评审、可信存证、投稿、返修到发布和持续演进的运行环境。

自动排版是早期使用抓手，投稿准备是第一条可信闭环，学术知识体是所有服务共同读写的
核心资产。

单体领域模型采用五部分架构：身份与版本、知识边界与证据、能力契约、交互与执行运行时、
验证权利与信誉。大模型属于可替换运行时，不属于知识本体；信誉状态独立于不可变内容快照
持续变化。详见[单篇论文知识体五部分服务架构](single-knowledge-body-service-architecture.md)。

## 2. 与任务型论文工具的区别

常见学术写作或投稿检查产品围绕作者当前任务组织能力：

```text
作者
├── 写作
├── 润色
├── 检查
└── 投稿
```

ManuscriptDock 围绕知识体生命周期组织能力：

```text
作者拥有并控制
        ↓
学术知识体
├── 来源、身份与版本
├── 结构、论点与证据
├── 引用、图表与声明
├── 排版、规则与投稿包
├── 评审、返修与作者回应
├── 权属声明与可信存证
├── 投稿、发布与外部标识
└── AI、PWC 和学术网络投影
```

单次任务结束后，结论不会留在孤立的报告或聊天记录中，而是作为带来源的派生对象回写
同一个知识体。

## 3. 四个产品层级

### 3.1 人：所有者和决策者

作者或合法权利主体拥有和控制知识体，决定修改、评审、外发和发布。平台不能以“服务
知识体”为理由削弱人的知情、撤销和迁移权。

### 3.2 知识体：稳定服务对象

论文知识体具有跨文件和跨平台的稳定身份。DOCX、TEX、PDF、投稿包和预印本只是来源、
工作副本或对外投影，不是知识体本身。

### 3.3 服务：作用于知识体的能力

排版、检查、AI、专业评审、存证、返修和发布都必须声明读取哪些对象、产生什么派生物、
使用哪个版本以及是否发生外发。

### 3.4 网络：经过授权的协作环境

PWC、期刊、预印本、机构和模型只接收完成当前任务所需的授权投影。完整本地知识体默认
不上传，也不因为一次服务调用转移控制权。

## 4. 服务写回规则

每项功能必须向知识体增加可追溯对象或关系：

| 服务 | 写回知识体的内容 |
| --- | --- |
| 自动排版 | 新版本、转换参数、差异和来源版本 |
| 投稿检查 | 规则 ID、规则包、结论、语义位置和处理状态 |
| 语言建议 | 模型、提示策略、原文位置、建议和作者决定 |
| PWC 专业评审 | 评审版本、专业判断、证据、责任域和回应 |
| 可信存证 | 内容承诺、签名主体、时间、凭证和验证方法 |
| 投稿 | 目标、材料清单、实际提交快照和外部状态 |
| 返修 | 审稿意见、修改、证据、回复及版本映射 |
| 发布 | 发布投影、许可、外部标识、替换或撤回关系 |

聊天历史、临时提示词和界面状态不能成为唯一事实来源。能够影响论文判断或交付结果的
信息，必须进入正式领域对象。

## 5. 授权投影模型

外部系统不直接获得整个知识体，而获得用途明确的最小投影：

```text
完整本地知识体
├── 期刊投稿投影
├── 匿名评审投影
├── PWC 专业评审投影
├── 可信存证投影
├── 预印本发布投影
└── 公开知识网络投影
```

每个投影记录：

- 来源知识体与版本；
- 接收方和用途；
- 包含与排除的对象；
- 权限、许可和有效期；
- 生成规则和内容指纹；
- 作者批准、发送时间和返回结果。

## 6. 生命周期状态

知识体不是在“投稿完成”后归档的静态对象：

```text
初稿
→ 已结构化
→ 投稿准备完成
→ 已投稿
→ 审稿中
→ 已返修
→ 已接受
→ 已发布
→ 勘误 / 新版本 / 数据更新
```

状态变化不能覆盖历史版本。转投、返修和发布都从已经存在的知识体派生新的版本与投影。

## 7. ManuscriptDock 与 PWC 分工

### ManuscriptDock 个人端

- 保存知识体主本和不可变来源；
- 提供作者编辑、检查、排版和版本控制；
- 管理服务授权和外发投影；
- 保存返回结果并建立来源关系；
- 在离线状态下维持核心知识体能力。

### PWC 机构中央端

- 维护机构和专业规则；
- 提供身份验证、多方签署和可信存证；
- 运行受保护的专业评审 Agent；
- 承担机构治理、质量控制和服务更新；
- 连接期刊、预印本及其他学术基础设施。

PWC 不默认成为个人知识体的唯一存储端。同步以对象、版本、授权和任务为单位。

## 8. 商业模式含义

服务可以围绕知识体生命周期定价，而不只按聊天次数或通用工具席位收费：

- 基础本地知识体：免费或低门槛；
- 自动排版和投稿包：按目标或生成任务；
- 专业评审：按知识体版本和评审类型；
- 可信存证与共同作者确认：按事件或服务周期；
- 返修管理：按投稿周期；
- 机构规则与治理：按组织和受管知识体规模；
- 发布与网络连接：按连接器和发布任务。

商业收费不能造成知识体锁定。作者应能导出来源、版本、关系、审计和通用投影。

## 9. 产品指标

除活跃用户和收入外，应增加知识体质量指标：

- 来源和版本指纹覆盖率；
- 结构节点稳定标识覆盖率；
- 检查、修复和评审结果的来源完整率；
- 转投和返修时已有知识体对象的复用率；
- 外发投影的最小化程度和授权完整率；
- 投稿版本与实际发布版本的可追溯率；
- 作者能够独立导出并验证的知识体比例；
- 孤立报告、孤立聊天和无法关联文件的数量。

## 10. 传播语言

### 内部战略定义

> ManuscriptDock 的核心服务对象是学术知识体。

### 面向作者

> ManuscriptDock 不只检查一份论文，而是持续管理它从初稿、投稿、评审到发布的每个
> 可信版本。

### 完整品牌定义

> ManuscriptDock 是作者控制的学术知识体工作台。它让每篇论文从投稿前开始，就成为
> 可检查、可修复、可追溯、可评审和可发布的完整学术成果。

首次使用仍然采用“导入论文、检查投稿、生成投稿包”等作者熟悉的任务语言。知识体概念
用于底层连续性和长期价值，不作为完成简单操作的理解门槛。

## 11. 功能准入问题

任何新功能进入开发前必须回答：

1. 它服务知识体的哪个生命周期阶段？
2. 它读取哪些正式对象？
3. 它产生什么对象、关系或状态？
4. 结果能否关联到明确来源和版本？
5. 是否需要外发，最小投影是什么？
6. 作者如何确认、拒绝、撤销和迁移？
7. 如果不能回写知识体，为什么仍值得成为正式产品能力？
