# ManuscriptDock UI 方向：两个任务、简单本地操作

- 日期：2026-09-14
- 状态：交互方案，待实施；不表示 V0.52 界面已改变。
- 范围：[产品总纲](product-design-overview.md)与[实施方案](local-journal-package-plan.md)。
- 本文覆盖旧设计中的生命周期轨道、常驻证据栏和模型入口；保留现有配色、字体、图标、阅读设置与可访问性规范。

## 1. 交互原则

1. 先选择要完成的任务，界面只展示与当前任务有关的内容。
2. 首页两个入口，进入任务后每屏一个主要操作，不永久展示多阶段侧栏。
3. 原生“打开文件／文件夹”是主输入，拖放是快捷方式；不使用云上传框或上传进度语义。
4. 本地解析、保存进度与受影响检查自动执行，不让作者点“建工作区”“提取结构”“重跑规则”。
5. 已知目标直接整理；推荐后转入整理保留已有输入，不重复选择。
6. 依据、完整规则、版本与日志按需展开；有阻断时直接显示原因及恢复操作。
7. 不让聊天、模型配置、规则获取或后台维护成为主流程。

## 3. 推荐期刊

首次进入显示“打开本地论文”，次要提示“也可以选择论文所在文件夹”。成功后自动解析，
同页只展开投稿语言、文章类型和研究关键词；投稿语言默认不限，与客户端界面语言分开，切换界面语言不改变投稿条件。用户明确选择简体中文而目录没有符合条件的已核验可生成目标时，要解释覆盖缺口并提供由作者确认的“改为 English 并重新推荐”，不得静默放宽。文章类型和关键词尽量从论文事实预填。APC／币种、开放获取、单位收录要求和首轮决定速度收入“更多设置”，其中速度偏好默认开启，硬条件不替作者擅自勾选。默认值均可修改，未确定的识别项只在必要时要求确认。
无单位要求、费用限制或期限时可以直接继续，不为学校名称、作者姓名强制增加表单。

主要操作：“推荐期刊”。处理反馈：“正在本机分析论文…”；取消文件选择不是错误。
可以打开另一篇，但不覆盖之前的记录。PDF 的有限支持与打开 DOCX 的路径需清楚说明。

```text
为这篇论文推荐                         修改偏好

综合推荐             进阶选择             准备更省力
期刊 A               期刊 B               期刊 C
为什么推荐           为什么推荐           为什么推荐
主要风险             主要风险             主要风险
需要准备什么         需要准备什么         需要准备什么
查看依据             查看依据             查看依据

选中：期刊 A                    [ 按这本期刊整理投稿包 ]
```

卡片可选择，默认不替作者锁定目标；底部只有一个主操作。不展示靶图、国内国外各八本列表、
总分仪表盘或录用概率。来源和覆盖信息可展开，关键未知直接出现在风险行。
不足三本按实际数量展示；零结果说明冲突条件并提供“修改偏好”，不静默放松条件。
未知候选作为次要“还需核对”列表，不与已满足硬条件的推荐混合。

## 4. 整理投稿包

### 4.1 选择目标并打开材料

独立入口的一页中包括：搜索期刊、文章类型、打开论文、打开材料文件夹。先后顺序不强制。
从推荐进入时这部分已预填，只保留“更换”操作。

文件夹含多个稿件时就地列出候选，作者选择主稿；同一规范化文件夹再次打开时回到同一个项目记录，后续材料和版本化输出都以该文件夹为工作区。其余文件建议为图件、表格、声明等，
不确定项提供用途选择。明确提示未纳入或不支持的文件，但不为每个正常文件弹窗。
材料加载完成且目标清楚后，主要操作“检查并整理”可执行；点击不可执行操作时解释缺项。

### 4.2 补齐与预览

```text
目标：期刊 A · Original Research                 更换
内置要求：已核验 · 日期                         查看要求

还需要你完成 2 项
通讯作者邮箱       [ 输入 ]
利益冲突声明       [ 填写并确认 ]

已准备 4 项                                     展开

                                 [ 预览投稿包 ]
```

缺项列表是当前主操作面。选择本地附件叫“选择文件”，正文补充叫“填写”，事实决定叫
“确认”，不统一包装成上传。已提取字段不重复输入；修改后后台自动重查受影响项。

预览在同页展开或进入一个预览页面，默认显示会生成的文件及用途；文档内容、必要差异和
规则依据按需查看。不强制常驻双栏；窄屏改用单列及返回操作。预览必须说明是真实生成文件
还是草稿，不能用提取文本冒充 Word 实页。

首版无规则维护入口；内置未覆盖时说明“尚无已核验的期刊要求”，主要恢复操作是选择其他
已支持目标或继续通用草稿。不会要求作者调用 AI、抓取官网或编辑规则 JSON。

### 4.3 保存完成

主要操作：“保存投稿包”；调用原生目录选择器。草稿保存明确叫“保存草稿”。
保存中显示本地进度；成功后展示文件数量、文件夹名和“在文件夹中显示”。
出版社材料 ZIP 与作者工具／内部记录分开说明，避免整包误传。

完成页不要求登记稿件号，不跳转模型评审或发布。说明“请在期刊投稿系统提交所需文件”时，
可以使用真实网站上的“上传／提交”，但不可暗示本应用已经执行。

## 5. 失败、返回与恢复

| 情况 | 同页处理 |
| --- | --- |
| 文件选择取消 | 保持原输入，无错误通知 |
| 文件损坏、不支持或无法读取 | 说明文件及原因，提供“重新选择文件” |
| 多个主稿、未知附件 | 在文件列表中选择，不静默判断 |
| 规则不覆盖或关键要求未确认 | 显示支持边界，可保存草稿；不声称可提交 |
| 不支持的复杂格式 | 保留源稿，说明人工处理项；不静默删除内容 |
| 更换期刊 | 说明需重新检查要求，保留已填事实和原材料；重新计算用途与适用性 |
| 返回修改偏好 | 恢复输入，重新推荐；不清空材料 |
| 重启或切换论文 | 从最近任务恢复；历史确认需符合当前稿件与规则上下文 |
| 无保存权限、空间不足 | 提供“选择其他文件夹”；不得显示保存成功 |

同一操作不得反复要求无信息增量的同意。原始文件不会被覆盖；确认用于事实、明确风险和
不可逆操作，不用于创建每个内部快照。

禁止在本地选择动作使用“上传论文／Upload manuscript”“上传附件／Upload attachment”。
“加载”用于处理状态，“打开／选择”用于用户动作，不机械替换所有历史文档中的“上传”。
涉及真实期刊系统上传槽位的内部合同可保留原术语，避免改变事实语义。

日期、币种、数量和动态失败消息按 locale 格式化；按钮、空状态、推荐数据、规则解释、
可访问名称、草稿水印、ZIP 说明和导出报告均覆盖 zh-CN/en。文件名与科研原文不自动翻译。

## 7. 验收

用合成稿件分别完成“未知目标→推荐→整理”和“已知目标→直接整理”，覆盖双语、键盘操作、
窄屏、文件选择取消、规则未知、材料缺失、保存失败及重启恢复。Windows/macOS 的文件与目录
选择必须做原生实测。详细功能与输出指标见实施方案；本次尚未执行这些未来验收。
