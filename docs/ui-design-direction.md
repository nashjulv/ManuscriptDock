# ManuscriptDock UI 方向：简洁学术工作台

- 状态：方向确认 / 已建立视觉实施基线
- 参考：OpenAI 式简洁体验 + PWC 内部工作台秩序 + 学术文档工作流
- 约束：不改动早期 Demo 和研究资料

## 1. 方向结论

ManuscriptDock 的主界面采用“像现代 AI 助手一样容易开始、像专业论文工具一样可以核验”的设计。

具体视觉令牌、PWC 映射、双面板工作区和组件规范已经固化在 [UI 视觉方案](ui-visual-system.md)，实现时以该文档和[全局设计系统](../design-system/manuscriptdock/MASTER.md)为准。

参考 OpenAI 产品的部分是：

- 首屏安静，只突出一个开始入口；
- 使用黑白灰中性色和充足留白；
- 内容优先，导航和工具降低视觉权重；
- 复杂选项按任务逐步出现；
- 用户可以用自然语言发起任务；
- 输出以清晰段落、列表和可执行操作呈现。

ManuscriptDock 必须增加的学术工作能力是：

- 真实论文文件、附件和版本始终可见；
- AI 结论能够定位到段落、图表或规则；
- 自动修改有差异、接受和撤销；
- 本地、联网、外发和发布状态明确；
- 长时间 OCR、解析和格式转换具有可恢复进度；
- 投稿包与返修任务具有稳定结构，不被聊天记录淹没。

## 2. 不做界面复制

不复制 OpenAI 的品牌名称、Logo、专有图标、具体页面比例或视觉资产。产品只借鉴低认知负担的体验原则，并建立属于 ManuscriptDock 的学术语言和隐私状态系统。

## 3. 应用骨架

### 3.1 空白首页

```text
┌──────────────────────────────────────────────────────────┐
│ ManuscriptDock                                      设置 │
│                                                          │
│                  准备好你的下一次投稿                      │
│          导入论文，生成可检查、可提交的投稿包               │
│                                                          │
│       ┌──────────────────────────────────────────┐       │
│       │ ＋ 导入论文，或描述你现在要完成的任务       │  →   │
│       └──────────────────────────────────────────┘       │
│                                                          │
│       在本机处理 · 原稿不覆盖 · 外发前由你确认              │
│                                                          │
│                    最近论文                               │
└──────────────────────────────────────────────────────────┘
```

首屏主输入不是普通聊天框，而是“任务入口”：既能拖入文件，也能输入“帮我准备投往某期刊的材料”。没有论文上下文时，不允许模型凭空生成正式声明。

### 3.2 论文工作区

```text
┌──────┬──────────────────────────┬───────────────────────────┐
│任务轨道│ 操作面                   │ 证据面                    │
│原稿   │ 当前步骤表单、问题与修复   │ 原文、预览、依据与差异      │
│结构   │                          │                           │
│目标   │                          │                           │
│格式   │                          │                           │
│检查   │                          │                           │
│投稿包 │                          │                           │
│知识体 │                          │                           │
└──────┴──────────────────────────┴───────────────────────────┘
```

任务轨道保持窄而稳定；操作面只承担当前步骤；证据面持续显示可核验对象。论文、版本和附件使用侧屉打开，不永久形成第三栏。自然语言输入可以固定在操作面底部，但不遮挡正文，也不承担导航职责。

### 3.3 投稿包完成页

完成页不使用庆祝动画和夸张评分，直接回答三个问题：

1. 已经生成了什么；
2. 还有什么需要作者确认；
3. 下一步可以导出、评审还是发布。

主要操作只有一个，例如“导出投稿包”。专业评审作为次级建议，不用弹窗强推。

### 3.4 返修工作区

审稿意见按来源和编号排列，正文修改与回复证据并列显示。状态使用文字和图标表达：待处理、修改中、待确认、已回复。AI 草稿与作者最终答复必须有明确来源标签。

## 4. 视觉语言

- 背景为略带纸张感的浅中性色，不使用纯白铺满所有层级；
- 主操作使用可信绿色高对比按钮；
- 蓝灰色只用于链接、选区和键盘焦点；
- 绿色同时表达品牌主动作、本地安全、完成和通过，但不作为大面积装饰；
- 卡片圆角克制，主要分组更多依靠留白和细边框；
- 默认无大面积阴影、渐变、玻璃拟态和发光效果；
- 使用系统字体，论文预览与 UI 字体相互隔离；
- 图标采用统一的 SVG 线性图标，不使用 Emoji 充当控件。

## 5. 文案语气

文案像可靠的编辑助理：简短、具体、不夸张、不承诺录用。

推荐：

- “发现 4 个需要确认的问题”；
- “这条要求来自目标期刊的图像规范”；
- “将在本机生成新版本，原稿保持不变”；
- “以下内容将发送给 PWC 专业评审”。

避免：

- “AI 已全面优化你的论文”；
- “一键提高录用率”；
- “论文质量 92 分”；
- “智能体已经替你完成投稿”。

## 6. 第一轮线框图范围

下一轮只设计四个连续画面：

1. 空白首页与导入论文；
2. 本地解析结果和目标选择；
3. 文档预览、问题与修复；
4. 投稿包完成与导出。

先验证用户能否不经教学完成这条路径，再扩展专业评审、返修、PWC 连接和知识体发布。
