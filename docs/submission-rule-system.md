# ManuscriptDock 投稿规则系统

- 状态：产品与架构决策 / 同意执行
- 日期：2026-08-23
- 适用范围：ManuscriptDock 投稿准备、返修和 PWC 规则服务

## 1. 决策结论

ManuscriptDock 不建设“每本期刊一份完整格式模板”的模板仓库，而建设：

> 统一论文模型 + 分层可组合投稿规则包 + 按需生成器。

全球期刊和中国期刊确实存在不同要求，但多数差异可以表达为结构、字数、匿名、声明、引用、图表、附件和投稿阶段规则。期刊层只记录相对于国家、出版商或学科基础规则的差异，不重复整套排版定义。

首版优先解决初投稿和返修，不承担接收后的正式出版排版。

## 2. “格式”的五个组成部分

| 类型 | 示例 | 产品处理方式 |
| --- | --- | --- |
| 论文结构 | 摘要、引言、方法、结果、讨论 | 统一语义模型与完整性检查 |
| 投稿规则 | 字数、匿名、文章类型、作者限制 | 分层规则包 |
| 引用格式 | 顺序编码、作者—年份、标点 | 优先复用 CSL 生态 |
| 图表与附件 | 分辨率、格式、命名、补充材料 | 规则检查与投稿包生成 |
| 最终视觉排版 | 字体、栏宽、页眉、期刊版式 | 仅在明确需要时生成，不作为初投稿默认目标 |

产品不能把“投稿准备”误解为复刻期刊正式出版页面。初投稿的首要目标是材料完整、结构可审阅、身份处理正确、图表可用、引用信息完整以及文件包符合要求。

## 3. 分层规则模型

```text
统一论文结构化模型
        ↓
国际 / 国家基础规则
        ↓
出版商或期刊集团规则
        ↓
具体期刊差异规则
        ↓
文章类型规则
        ↓
投稿阶段规则
        ↓
本次投稿包
```

### 3.1 统一论文模型

内部只维护一份与具体期刊无关的论文语义结构，包括：

- 标题、摘要、关键词；
- 作者、单位、通讯作者与 ORCID；
- 正文层级、段落、公式、脚注；
- 图、表、图注和正文引用；
- 参考文献及可解析元数据；
- 基金、伦理、利益冲突和作者贡献；
- 数据、代码、材料和 AI 使用声明；
- 补充材料；
- 版本、来源与提交记录。

模型设计参考 JATS 等公开标准，但首版只实现投稿闭环实际需要的子集，并保持未来映射能力。

### 3.2 国际或国家基础规则

基础层承载跨期刊共有的标准，例如：

- 通用国际学术论文结构；
- JATS 可映射结构；
- 中国学术论文编写基础规则；
- 中国参考文献著录基础规则；
- 通用研究伦理和贡献声明字段。

中国期刊优先继承中国国家标准基础包，再叠加学科、出版机构和具体期刊差异。

### 3.3 出版商或集团规则

出版商层保存同一集团旗下期刊常见的共同要求，例如：

- 投稿入口接受的文件类型；
- 匿名审稿处理方式；
- 通用声明和作者信息；
- 图表与附件要求；
- 初投稿与返修文件组织方式。

期刊规则优先继承出版商层，不能重复复制相同规则。

### 3.4 期刊差异规则

期刊层只保存必要差异：

- 文章类型及各类型要求；
- 摘要和正文字数上限；
- 摘要是否结构化；
- 图表、参考文献和作者数量限制；
- 特殊声明、清单或附件；
- 期刊特有命名和上传要求；
- 对基础规则的明确覆盖或例外。

### 3.5 文章类型规则

Original Research、Review、Case Report、Brief Communication、Letter 等类型的要求可以跨期刊复用，并由期刊进行限制或覆盖。

### 3.6 投稿阶段规则

同一期刊的要求按阶段区分：

- 初投稿；
- 返修；
- 接收后生产；
- 预印本发布。

规则必须声明适用阶段，避免把接收后的生产排版要求错误应用到初投稿。

## 4. 规则包而不是代码分支

规则包是可读取、可验证、可签名和可独立更新的数据，不应为每本期刊增加应用代码分支。

每个规则包至少记录：

- 唯一标识和规则层级；
- 继承来源；
- 适用期刊、文章类型和投稿阶段；
- 规则内容和严重程度；
- 官方来源链接或文件；
- 发布时间、抓取时间和人工核验时间；
- 规则版本、生效时间和失效状态；
- 维护者和验证者；
- 自动测试样例；
- 与上一个版本的差异。

规则结论分为三类：

1. `必须满足`：来源明确、能够确定性验证；
2. `建议改进`：不一定阻止投稿，但可能影响审阅；
3. `作者确认`：系统无法从稿件中可靠判断，必须由作者负责。

## 5. 引用格式策略

ManuscriptDock 不自行维护全球引用样式库。

- 引用与参考文献格式优先使用 CSL；
- ManuscriptDock 负责引用完整性、文内与文后对应关系和元数据质量；
- 中国国家标准和无法被现有 CSL 准确表达的期刊规则作为受控扩展；
- 引用样式的许可证、来源、版本和更新信息随规则包记录。

引用显示样式和参考文献事实数据必须分离，切换期刊不能改变原始文献记录。

## 6. 规则覆盖等级

选择投稿目标时必须显示覆盖程度，不能笼统声称“完全支持”。

| 等级 | 产品显示 | 定义 |
| --- | --- | --- |
| A | 已验证期刊规则 | 当前作者指南已人工核对并通过测试 |
| B | 出版商增强规则 | 出版商通用要求已覆盖，期刊差异仍需确认 |
| C | 标准投稿规则 | 使用国家、学科或通用论文规则 |
| D | 待确认规则 | 从作者指南提取，但尚未完成可靠核验 |

界面同时显示：

- 规则来源；
- 最后核验时间；
- 适用投稿阶段；
- 当前未覆盖的要求；
- 需要作者确认的事项。

AI 从作者指南抽取的规则默认只能进入 D 级，不能自动标记为已验证。

## 7. 规则生产与更新

### 7.1 PWC 中央端

PWC 负责：

- 维护基础、出版商和重点期刊规则；
- 监测官方作者指南变化；
- 组织自动测试和人工核验；
- 对规则包签名和版本化；
- 保留来源、变更和审核记录；
- 接收机构维护的内部规则扩展。

### 7.2 ManuscriptDock 本地端

ManuscriptDock 负责：

- 用户选择目标后按需下载必要规则；
- 验证签名、版本和适用范围；
- 在本地执行确定性检查和投稿包生成；
- 缓存已经使用的规则以支持离线工作；
- 清楚显示规则来源和覆盖等级；
- 在规则过期或存在冲突时要求用户确认。

规则更新不能改变已经保存的历史投稿快照。历史快照必须继续引用当时使用的规则版本。

## 8. 控制服务重量的原则

1. 不预先覆盖全球全部期刊；
2. 只维护用户真实选择的投稿目标；
3. 复用国家、学科和出版商基础层；
4. 期刊层只保存差异；
5. 初投稿和接收后生产要求分开；
6. 引用格式复用 CSL；
7. 规则与应用版本分离更新；
8. 自动抽取不能替代人工验证；
9. 机构可以维护自己的签名扩展；
10. 无精确期刊规则时仍提供诚实的通用投稿准备。

## 9. 首版覆盖范围

首版只验证一条可维护的窄闭环：

- 一套通用国际初投稿基础规则；
- 一套中国学术论文基础规则；
- 一套中国参考文献基础规则；
- 3–5 个主要出版商或期刊集团规则；
- 第一批用户最常投的 20–50 本重点期刊；
- 初投稿和返修两个阶段；
- 一种主要源文件生态优先；
- CSL 引用样式连接；
- 规则来源、版本、覆盖等级和本地缓存。

重点期刊名单不由团队主观决定，应根据种子用户、合作机构和真实投稿记录排序。

## 10. 产品承诺

对外采用三级承诺：

1. 任何期刊都可以使用通用投稿准备；
2. 主要出版商提供增强适配；
3. 重点期刊提供经过核验的精确规则包。

不使用以下表述：

- “支持全球全部期刊自动排版”；
- “保证完全符合所有投稿要求”；
- “一键生成正式出版版式”；
- “保证通过编辑部初审”。

推荐表述：

> ManuscriptDock 根据可追溯的投稿规则检查论文并生成投稿包，同时明确显示已覆盖、待确认和未覆盖的要求。

## 11. 验证指标

- 基础规则被重点期刊复用的比例；
- 每本期刊平均需要维护的差异规则数量；
- 规则从官方变化到发布更新的时间；
- A、B、C、D 各覆盖等级的使用量；
- 用户需要手工确认和修正的规则比例；
- 规则误报、漏报和过期问题数量；
- 投稿包因格式或材料问题被退回的比例；
- 同一规则包跨期刊和机构复用的次数。

## 12. 单机 MVP 实现基线（2026-08-24）

当前可执行版本已经建立规则系统的首批可选择可信闭环：

- 内置“通用论文结构”和“初投稿阶段”两层基础包，以及 16 套可选择的中国标准、国际伦理、出版商和研究报告增强规则包；
- 用户可以在目标步骤按论文实际情况组合规则，Rust 只执行所选增强包及其依赖；
- Rust 在执行前验证 Ed25519 签名，签名失败、依赖缺失、循环继承或规则冲突都会拒绝整次检查；
- 国家与学科标准显示为 C，出版商通用规则显示为 B；仍不冒充已经核验的具体期刊 A 级规则；
- 结论区分必须满足、建议改进和作者确认，并保留规则 ID、规则包和语义位置；
- 每次执行生成独立 JSON 报告 v2 和 HTML 预览快照，绑定源稿指纹、规则组合和版本；
- MVP 没有任何外发、自动投稿或发布命令，报告明确记录未发生外部传输。

完整目录、官方来源和未覆盖项见[内置出版标准目录](publication-standards-catalog.md)。

远端规则更新尚未开放。正式接入 PWC 前还需要生产签名密钥、撤销与回滚机制、更新通道和来源核验流程。
