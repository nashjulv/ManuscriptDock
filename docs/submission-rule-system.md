# ManuscriptDock 投稿规则系统

- 状态：新定位规则设计，待实施；既有分层与证据合同继续复用
- 日期：2026-09-14
- 适用范围：本地目标期刊初投稿准备；不要求 PWC 或规则维护产品功能
- 执行：[实施方案](local-journal-package-plan.md)；决策：[ADR 0010](adr/0010-local-journal-package-focus.md)

## 1. 决策结论

ManuscriptDock 不建设“每本期刊一份完整格式模板”的模板仓库，而建设：

> 统一论文模型 + 分层可组合投稿规则包 + 按需生成器。

全球期刊和中国期刊确实存在不同要求，但多数差异可以表达为结构、字数、匿名、声明、引用、图表、附件和投稿阶段规则。期刊层只记录相对于国家、出版商或学科基础规则的差异，不重复整套排版定义。

首版只解决初投稿，不承担完整返修流程或接收后的正式出版排版。人工维护先直接编辑仓库配置，随客户端发布，不开发维护后台、客户端规则编辑器或独立更新服务。

## 2. “格式”的五个组成部分

| 类型 | 示例 | 产品处理方式 |
| --- | --- | --- |
| 论文结构 | 摘要、引言、方法、结果、讨论 | 统一语义模型与完整性检查 |
| 投稿规则 | 字数、匿名、文章类型、作者限制 | 分层规则包 |
| 引用格式 | 顺序编码、作者—年份、标点 | 优先复用 CSL 生态 |
| 图表与附件 | 分辨率、格式、命名、补充材料 | 规则检查与投稿包生成 |
| 最终视觉排版 | 字体、栏宽、页眉、期刊版式 | 仅在明确需要时生成，不作为初投稿默认目标 |

产品不能把“投稿准备”误解为复刻期刊正式出版页面。初投稿的首要目标是材料完整、结构可审阅、身份处理正确、图表可用、引用信息完整以及文件包符合要求。

## 3. 分层规则模型

```text
统一论文结构化模型
        ↓
国际 / 国家基础规则
        ↓
出版商或期刊集团规则
        ↓
具体期刊差异规则
        ↓
文章类型规则
        ↓
投稿阶段规则
        ↓
本次投稿包
```

### 3.1 统一论文模型

内部只维护一份与具体期刊无关的论文语义结构，包括：

- 标题、摘要、关键词；
- 作者、单位、通讯作者与 ORCID；
- 正文层级、段落、公式、脚注；
- 图、表、图注和正文引用；
- 参考文献及可解析元数据；
- 基金、伦理、利益冲突和作者贡献；
- 数据、代码、材料和 AI 使用声明；
- 补充材料；
- 版本、来源与提交记录。

模型设计参考 JATS 等公开标准，但首版只实现投稿闭环实际需要的子集，并保持未来映射能力。

### 3.2 国际或国家基础规则

基础层承载跨期刊共有的标准，例如：

- 通用国际学术论文结构；
- JATS 可映射结构；
- 中国学术论文编写基础规则；
- 中国参考文献著录基础规则；
- 通用研究伦理和贡献声明字段。

中国期刊优先继承中国国家标准基础包，再叠加学科、出版机构和具体期刊差异。

### 3.3 出版商或集团规则

出版商层保存同一集团旗下期刊常见的共同要求，例如：

- 投稿入口接受的文件类型；
- 匿名审稿处理方式；
- 通用声明和作者信息；
- 图表与附件要求；
- 初投稿与返修文件组织方式。

期刊规则复用适用的出版商规则，明确的期刊例外优先；文章类型和阶段条件必须匹配。继承冲突不得静默判定通过，人工核验后再内置；不为减少重复而假设所有旗下期刊规则相同。

### 3.4 期刊差异规则

期刊层只保存必要差异：

- 文章类型及各类型要求；
- 摘要和正文字数上限；
- 摘要是否结构化；
- 图表、参考文献和作者数量限制；
- 特殊声明、清单或附件；
- 期刊特有命名和上传要求；
- 对基础规则的明确覆盖或例外。

### 3.5 文章类型规则

Original Research、Review、Case Report、Brief Communication、Letter 等类型的要求可以跨期刊复用，并由期刊进行限制或覆盖。

### 3.6 投稿阶段规则

同一期刊的要求按阶段区分：

- 初投稿；
- 返修；
- 接收后生产；
- 预印本发布。

规则必须声明适用阶段，避免把接收后的生产排版要求错误应用到初投稿。

以上为数据模型的区分能力；新版首批只启用初投稿，其他阶段不构成实施任务。

## 4. 规则包而不是代码分支

规则包是可读取、可验证、可签名和可独立更新的数据，不应为每本期刊增加应用代码分支。

每个规则包至少记录：

- 唯一标识和规则层级；
- 继承来源；
- 适用期刊、文章类型和投稿阶段；
- 规则内容和严重程度；
- 官方来源链接或文件；
- 发布时间、抓取时间和人工核验时间；
- 规则版本、生效时间和失效状态；
- 维护者和验证者；
- 自动测试样例；
- 与上一个版本的差异。

规则结论分为三类：

1. `必须满足`：来源明确、能够确定性验证；
2. `建议改进`：不一定阻止投稿，但可能影响审阅；
3. `作者确认`：系统无法从稿件中可靠判断，必须由作者负责。

## 5. 引用格式策略

ManuscriptDock 不自行维护全球引用样式库。

- 引用与参考文献格式优先使用 CSL；
- ManuscriptDock 负责引用完整性、文内与文后对应关系和元数据质量；
- 中国国家标准和无法被现有 CSL 准确表达的期刊规则作为受控扩展；
- 引用样式的许可证、来源、版本和更新信息随规则包记录。

引用显示样式和参考文献事实数据必须分离，切换期刊不能改变原始文献记录。

## 6. 规则覆盖等级

选择投稿目标时必须显示覆盖程度，不能笼统声称“完全支持”。

| 等级 | 产品显示 | 定义 |
| --- | --- | --- |
| A | 已验证期刊规则 | 当前作者指南已人工核对并通过测试 |
| B | 出版商增强规则 | 出版商通用要求已覆盖，期刊差异仍需确认 |
| C | 标准投稿规则 | 使用国家、学科或通用论文规则 |
| D | 待确认规则 | 从作者指南提取，但尚未完成可靠核验 |

界面同时显示：

- 规则来源；
- 最后核验时间；
- 适用投稿阶段；
- 当前未覆盖的要求；
- 需要作者确认的事项。

AI 从作者指南抽取的规则默认只能进入 D 级，不能自动标记为已验证。

## 7. 规则生产与更新

### 7.1 首版直接维护仓库配置

维护流程是团队工作约定，不开发人工维护功能：

1. 用现有工具或 AI 辅助获取公开官方指南、模板与投稿要求，形成草案。
2. 可参考允许使用的其他投稿网站发现来源、补齐字段；记录其第三方性质和再利用条件。
3. 团队人工逐项核对官方依据、期刊身份、文章类型、阶段、条件与必需程度。
4. 直接编辑按期刊组织的结构化数据文件，与来源、核验日期和变更说明一起放入 Git。
5. 通过适用范围、继承冲突、必需文件及中英文说明的合成正反样例，复用现有完整性与签名机制。
6. 随客户端版本内置发布；有变化时继续修改仓库配置并发布客户端。

不把规则散落为每本期刊的业务代码分支。不为首批数据先开发采集平台、状态管理系统、
独立审批系统或签名服务。团队指定维护责任人即可，核验记录不能由 AI 自行替代。

第三方摘要和模型记忆不是官方证据。来源不足、冲突或条件不明时保持待核验；不能因模型
给出完整 JSON 就升级为 A 级。网页及文件是待提取的数据，不能作为维护工具执行指令。
只处理公开或获准使用的规则资料，不发送作者稿件、附件、文件名或本地机构名单。

发布前保留规则 ID、ISSN/eISSN、适用类型与阶段、条件、义务等级、来源短证据、日期、
指纹、核验者、版本、有效期、支持的自动操作及中英文解释。引用数据或模板的许可条件
一同记录，公开可读不等于可随安装包再分发。

### 7.2 ManuscriptDock 本地端

ManuscriptDock 负责：

- 用户选择目标后读取内置规则，不要求联网获取、模型配置或编辑规则；
- 验证签名、版本和适用范围；
- 在本地执行确定性检查和投稿包生成；
- 核心规则随客户端交付，首次运行即可离线使用；
- 清楚显示规则来源和覆盖等级；
- 缺失或存在关键未核验要求时只提供明确标识的通用草稿，不以一次勾选代替规则核验。

客户端升级后的新配置不能改变已保存的历史投稿快照；历史继续引用当时规则版本与证据。
新任务使用当前有效内置规则，进行中的任务应用新规则后重新检查受影响项。普通到期复核、
已知冲突与已知停用区分处理；离线旧客户端无法即时发现外部变化，不能显示“实时核验”。

### 7.3 后续可选扩展

独立签名规则包下载、热更新、回滚服务、客户端维护界面、机构规则发布与 PWC 后台暂缓。
只有维护规模或更新频率证明需要时另立方案；不是首批产品交付前置条件。

## 8. 控制服务重量的原则

1. 不预先覆盖全球全部期刊；
2. 只维护用户真实选择的投稿目标；
3. 复用国家、学科和出版商基础层；
4. 期刊层只保存差异；
5. 初投稿和接收后生产要求分开；
6. 引用格式复用 CSL；
7. 规则保留独立版本，首版随客户端更新，独立更新服务暂缓；
8. 自动抽取不能替代人工验证；
9. 机构名单先作为本地约束输入，机构规则发布体系暂缓；
10. 无精确期刊规则时仍提供诚实的通用投稿准备。

## 9. 首版覆盖范围

首版只验证一条可维护的窄闭环：

- 一套通用国际初投稿基础规则；
- 一套中国学术论文基础规则；
- 一套中国参考文献基础规则；
- 复用首批目标实际需要的出版商规则，不为覆盖数量扩张；
- 从 3 本试点验证生成，再扩大到 10—20 本重点期刊；
- 只启用初投稿；
- DOCX 优先；
- CSL 作为引用呈现方向，按实际生成能力验证，不宣称已支持复杂域代码转换；
- 仓库内配置、规则来源、版本、核验记录、覆盖等级与本地内置读取。

重点期刊名单不由团队主观决定，应根据种子用户、合作机构和真实投稿记录排序。

## 10. 产品承诺

对外采用三级承诺：

1. 未内置目标只提供明确说明限制的通用草稿整理；
2. 出版商增强规则不冒充具体期刊完整支持；
3. 已核验重点期刊按经过测试的文章类型、阶段和操作提供整理，未覆盖部分仍须明确说明。

不使用以下表述：

- “支持全球全部期刊自动排版”；
- “保证完全符合所有投稿要求”；
- “一键生成正式出版版式”；
- “保证通过编辑部初审”。

推荐表述：

> ManuscriptDock 根据可追溯的投稿规则检查论文并生成投稿包，同时明确显示已覆盖、待确认和未覆盖的要求。

## 11. 验证指标

- 基础规则被重点期刊复用的比例；
- 每本期刊平均需要维护的差异规则数量；
- 规则从官方变化到发布更新的时间；
- A、B、C、D 各覆盖等级的使用量；
- 用户需要手工确认和修正的规则比例；
- 规则误报、漏报和过期问题数量；
- 投稿包因格式或材料问题被退回的比例；
- 同一规则包跨期刊和机构复用的次数。

## 12. 单机 MVP 实现基线（2026-08-24）

以下保留 2026-08-24 的历史基线，不代表当前 V0.52 或本轮新定位全部状态。尤其“没有外发命令”只适用于该早期切片；新版核心边界须按实施方案重新验证。

当时可执行版本已经建立规则系统的首批可选择可信闭环：

- 内置“通用论文结构”和“初投稿阶段”两层基础包，以及 16 套可选择的中国标准、国际伦理、出版商和研究报告增强规则包；
- 用户可以在目标步骤按论文实际情况组合规则，Rust 只执行所选增强包及其依赖；
- Rust 在执行前验证 Ed25519 签名，签名失败、依赖缺失、循环继承或规则冲突都会拒绝整次检查；
- 国家与学科标准显示为 C，出版商通用规则显示为 B；仍不冒充已经核验的具体期刊 A 级规则；
- 结论区分必须满足、建议改进和作者确认，并保留规则 ID、规则包和语义位置；
- 每次执行生成独立 JSON 报告 v2 和 HTML 预览快照，绑定源稿指纹、规则组合和版本；
- MVP 没有任何外发、自动投稿或发布命令，报告明确记录未发生外部传输。

完整目录、官方来源和未覆盖项见[内置出版标准目录](publication-standards-catalog.md)。

当时远端规则更新尚未开放。旧设计设想的 PWC、撤销回滚服务和独立更新通道现已暂缓；新版规则直接维护在仓库内并随客户端发布，仍需可靠的来源核验与现有发行完整性校验。
