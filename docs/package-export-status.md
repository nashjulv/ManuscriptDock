# V0.51 投稿包导出状态修复

日期：2026-09-08。修复 V0.50 复测中“导出成功后，侧栏投稿包仍显示待处理”的问题。

## 用户可见变化

投稿包是否完成由导出记录决定。实际向期刊提交后的回执登记是独立步骤，学生不需要勾选“已投稿”来让导出状态变成完成。

| 情况 | 侧栏、概览与投稿包页面 |
| --- | --- |
| 尚未完成准备 | 待处理 |
| 当前检查通过，尚未导出 | 可导出 |
| 当前准备内容已成功导出 | 已导出 |
| 上次导出后稿件、材料、目标要求或核验状态变化 | 内容已变更；保留上次成功记录，提示重新检查并导出 |
| 仅有旧版审计事件，无法绑定具体内容 | 历史导出待核验 |
| 导出记录损坏或无法验证 | 导出记录待核验，不作为完成依据 |

导出记录可展开查看包名、稿件版本、文件数量、时间和绝对路径。原目录无法访问时单独提示可能已移动或删除，保留历史导出事实。重新检查相同内容不会清除已导出状态；内容变化后仅重新检查不会冒充已经重新导出。

取消选择目录不生成新记录。再次导出失败不清除已有成功记录。文件已生成但记录保存失败时，错误明确说明应先检查所选文件夹，避免用户误以为没有生成文件而重复操作。

## 实现边界

- Rust 在 `exports/target-packages/<exportId>/export.json` 保存不可变导出记录，记录绑定工作区、稿件版本、当前检查上下文指纹、目标选择、文件清单、时间和位置，并进行完整性校验。
- 生成包目录采用独立 UUID。最终移动文件前再次确认检查上下文；只有文件生成与导出记录保存成功才返回成功。
- 材料目录合同升级为 schema 6，新增 `exportStatus`。生命周期恢复、材料刷新和导出后刷新使用同一计算逻辑；前端不再用临时成功消息或投稿登记推断导出完成。
- 历史事件不能恢复旧版导出的确切位置和上下文，不自动补造成功记录。重新导出即可建立 V0.51 的完整记录。
- 原导出目录的存在性仅用于位置提示，不保证用户导出后没有自行修改包内文件。导出记录证明当次生成行为，不代表出版社已经收稿。
- 保持本地操作；不上传稿件，不自动向期刊投稿。
