# ManuscriptDock 设计系统

- 版本：1.4
- 状态：MVP 实施基线
- 产品：ManuscriptDock（投稿舱）
- 平台：Tauri 桌面端优先，兼顾未来 iOS 伴随端

具体页面若存在 `pages/<page-name>.md`，页面规则覆盖本文件；未声明部分继续遵循本文件。

## 1. 体验目标

ManuscriptDock 是处理未发表论文的本地可信工作台。界面首先要让作者感到内容安全、操作可逆、状态清楚，其次才表现智能能力。

整体以 PWC 个人工作台 `/workspace/publish` 的实测桌面布局、灰阶、排版秩序和间距为直接视觉基线，同时保留 ManuscriptDock 自有名称、功能语义和可信边界。为提高长时间阅读舒适度，正文层级在 PWC 基线上整体增加约 1px；所有绿色主按钮统一使用 `#A6CE39`。完整映射见 [UI 视觉方案](../../docs/ui-visual-system.md)。

设计关键词：

- 安静、专业、克制、现代学术；
- 文档优先而不是仪表盘优先；
- 结果可验证而不是强调 AI 魔法；
- 本地状态和外发状态始终可见；
- 一屏一个主要决策；
- 渐进披露复杂投稿规则。

不采用以下主界面风格：

- 科幻 HUD、持续发光和大面积高饱和色；
- 把所有检查项堆成监控大屏；
- 用聊天窗口替代文件、版本和任务结构；
- 隐藏上传、联网或 AI 调用状态；
- 用不可解释的总分代替具体问题和修复路径。

早期知识网络演示可以作为未来分析模块保留，但不定义投稿工作台的主视觉。

## 2. 核心界面模式

### 2.1 首次进入

采用与 PWC 发布页一致的“48px 任务轨道 + 574px 主操作区 + 自适应发布指引”入口，只突出一个主操作：导入论文。首次使用不要求注册，不在首屏展示专业术语清单。

```text
投稿舱 ManuscriptDock

把论文变成可检查、可提交的投稿包
[ 拖入论文，或选择文件 ]

在本机处理 · 原稿不会被覆盖 · 外发前由你确认
```

### 2.2 桌面工作区

使用“任务轨道 + 操作面 + 证据面”的稳定结构：

```text
┌──────┬──────────────────────────┬───────────────────────────┐
│任务轨道│ 操作面 574px             │ 证据面 自适应              │
│ 48px │ 表单、修复、版本操作       │ 原文、预览、依据、差异、状态│
└──────┴──────────────────────────┴───────────────────────────┘
```

- 任务轨道第一项固定为“我的工作台”，通过细分隔线与原稿、版本、结构、目标、修订、检查、投稿包和知识体等论文阶段区分；
- 操作面只显示当前步骤需要完成的输入、修复和版本动作；
- 证据面始终显示与当前操作相关的原文、预览、规则依据或差异；
- 知识体证据面按“单一知识体 / 两体关联 / 关联网络”渐进展开；单体以 KnowledgeBodySnapshot 外圈固定对象版本，以 Claim 十二面体为中心，外围表达八类版本化对象；绿色菱形只表示有依据的一等关系或声明对象；
- 论文、版本和附件从任务轨道打开侧屉，不永久占用第三栏；
- 窗口小于 960px 时切换为“操作 / 证据”单面板页签，不压缩为不可读的三栏；
- 全局设置不与论文任务混在同一层级。

### 2.3 论文生命周期

每篇论文使用相同的阶段模型：

```text
稿件 → 目标 → 投稿包 → 专业评审 → 返修 → 发布
```

阶段导航应显示当前状态和未完成事项，但不能强制用户按顺序完成所有步骤。任何外发行为必须形成独立确认步骤。

## 3. 色彩系统

色彩以黑白灰中性系统为主，结合纸张、墨水和校样标记的轻微暖色感；不模拟期刊排版，也不让界面与文档正文竞争。

### 3.1 浅色主题

| 角色 | 色值 | Token | 用途 |
| --- | --- | --- | --- |
| Primary | `#A6CE39` | `--color-primary` | 主要按钮、当前步骤与工作台标签 |
| On Primary | `#4A4846` | `--color-on-primary` | 所有绿色按钮的文字和图标 |
| Primary Hover | `#98BF2D` | `--color-primary-hover` | 悬停 |
| Background | `#FAFAFA` | `--color-background` | 应用与左侧工作面背景 |
| Surface | `#F5F5F5` | `--color-surface` | 指引与证据面 |
| Surface Subtle | `#F0F0F0` | `--color-surface-subtle` | 轨道选中与安静分组 |
| Foreground | `#1C1B19` | `--color-foreground` | 主文字 |
| Secondary | `#4A4845` | `--color-secondary` | 正文说明和深色步骤圆点 |
| Muted Foreground | `#7A7872` | `--color-muted-foreground` | 元数据与次要信息 |
| Border | `#EBEBEB` | `--color-border` | 默认边框与分隔 |
| Border Strong | `#E0E0E0` | `--color-border-strong` | 双面板边界 |
| Warning | `#8A5C18` | `--color-warning` | 需要确认 |
| Destructive | `#B42318` | `--color-destructive` | 错误和破坏性操作 |
| Focus Ring | `#356A8A` | `--color-focus-ring` | 键盘焦点 |

### 3.2 主题范围

MVP 仅实现并验证 PWC 基线浅色主题；深色主题不在本阶段通过自动反色生成。

### 3.3 使用规则

- 正常正文与背景对比度至少 4.5:1；
- 状态不能只依赖红、黄、绿颜色，必须同时提供图标和文字；
- 每个页面只有一个主要按钮；
- 可信绿色用于主操作、本地安全和通过，蓝灰色用于链接与焦点；
- 文档批注颜色与应用状态颜色分开管理。

## 4. 字体与排版

### 4.1 UI 字体

全部应用界面统一使用苹方细体，Windows 使用系统细体回退：

```css
"PingFang SC", "PingFang HK", "Microsoft YaHei UI Light",
"Segoe UI Light", sans-serif;
font-weight: 300;
```

前端运行时禁止从 Google Fonts 或其他 CDN 加载字体。若未来采用品牌字体，必须随应用打包，并提供系统字体回退。

应用生成的预览界面同样使用苹方细体；嵌入的不可变论文原页保留源稿字形。

### 4.2 字号层级

| Token | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `--type-xs` | `11 / 16px` | 极短元数据，不承载关键说明 |
| `--type-sm` | `13 / 19px` | 标签、来源和状态徽标 |
| `--type-md` | `14 / 21px` | 高密度表单、列表和操作说明 |
| `--type-reading` | `15 / 22.5px` | 问题正文、解释和预览旁注 |
| `--type-lg` | `19 / 27px` | 面板标题 |
| `--type-xl` | `26 / 36px` | 页面主标题 |

- 关键说明不低于 13px；阅读正文不低于 14px；触控端不低于 16px；
- 长段正文宽度控制在约 65–75 个英文字符；
- 版本号、计数和表格数字使用等宽数字特性，不强制使用等宽字体；
- 通过字号、位置、颜色和留白建立层级，不混用粗体，不依赖全大写和过宽字距。

## 5. 间距、形状与层级

采用 4px 基础网格：`4 / 8 / 12 / 16 / 24 / 32 / 48`。

| 元素 | 建议值 |
| --- | --- |
| 控件圆角 | 4–6px |
| 面板圆角 | 0–8px；并列工作面通常无圆角 |
| 输入高度 | 桌面 36–40px，触控命中区至少 44px |
| 主按钮高度 | 30px，`6px` 圆角，`0 11px` 内边距 |
| 面板内边距 | 16–20px；主操作区水平 32px |
| 列表行高度 | 至少 44px，触控端至少 48px |

主要布局依靠边框、背景差异和留白，不普遍使用阴影。阴影仅用于菜单、模态框和跨层拖拽对象，并遵循统一的三档层级。

## 6. 组件原则

### 6.1 文件导入

- 同时提供拖放和“选择文件”按钮；
- 键盘用户无需拖放即可完成同一操作；
- 导入后立即显示文件名、格式、大小和本地状态；
- 解析超过 300ms 显示进度，长任务提供取消；
- 错误同时说明原因和恢复办法。

### 6.2 问题项

每个问题包含：问题是什么、位于哪里、依据哪条规则、建议怎么处理、是否能自动修复。不得只显示“错误 17 个”或模糊评分。

### 6.3 状态徽标

统一使用“图标 + 短文字”：本地、待确认、将要外发、处理中、已完成、失败。禁止只用彩色圆点。

### 6.4 外发确认

所有远程 AI、PWC 专业评审和发布行为都使用相同的确认模式：

- 发送什么；
- 发送给谁；
- 为什么发送；
- 是否包含正文、审稿材料或作者身份；
- 生成哪个不可变快照；
- 取消与继续操作。

### 6.5 图标

使用与 PWC 相同视觉语言的 Lucide 风格 SVG 线性图标：`24 × 24` viewBox、轨道内显示 20px、2px 描边、圆形端点与圆形连接。结构性控件不使用 Emoji；桌面任务轨道按钮保持 36px 视觉尺寸、6px 圆角，并提供可访问名称、可见焦点和明确选中状态；触控端另行扩大命中区。

## 7. 交互与反馈

- 点击或按键后 100ms 内提供视觉反馈；
- 微交互时长为 150–250ms，只动画 `transform` 和 `opacity`；
- 支持 `prefers-reduced-motion`；
- 异步按钮处理中禁用重复提交并显示进度；
- 返回上一层时恢复滚动、筛选和输入状态；
- 删除、覆盖和撤销不了的操作必须二次确认；
- 可逆修改优先提供撤销，而不是频繁弹确认框；
- 每次自动修改都可查看差异、接受或撤销。

### 7.1 界面语言

- 桌面端完整支持中文与英文，产品栏使用紧凑的“中文 / EN”分段控件；
- 中文为首次启动默认语言，选择仅保存在本机，并同步页面语言属性；
- 切换语言不能刷新或重置当前论文、阶段、面板和处理中状态；
- 所有产品界面、可访问名称、确定性规则说明和恢复提示随语言切换；
- 文件名、论文标题、章节名、引用和作者原文保持源语言，不由界面切换自动翻译；
- 语言控件必须具有可见焦点和选中状态，不使用国旗表达语言。

## 8. 跨平台适配

桌面端是完整工作台，支持键盘、拖放、多栏预览和长任务。iOS 首版应定位为伴随端，优先处理状态查看、审稿意见、确认和通知，不压缩复制完整桌面编辑器。

响应式验证宽度：`375 / 768 / 1024 / 1440px`。桌面从 1024px 起使用侧栏；窄屏使用单列和平台标准返回行为，不同时使用同层级侧栏与底部导航。

## 9. 可访问性基线

- 全流程可使用键盘完成；
- 焦点顺序与视觉顺序一致，焦点环始终可见；
- 支持系统文字缩放，关键文字不能被截断；
- 普通文字对比度至少 4.5:1；
- 图标、图片、进度和动态状态具有可访问名称；
- 表单使用可见标签，错误显示在对应字段附近；
- 模态框提供明确退出路径并正确管理焦点；
- 不依赖悬停、颜色或手势传达唯一信息。

## 10. 交付检查

- [ ] 首屏只有一个主要操作；
- [ ] 本地、联网和外发状态清楚可见；
- [ ] 原稿不被覆盖，所有生成物可追溯；
- [ ] 自动修改可以比较、接受和撤销；
- [ ] 键盘、触控和屏幕阅读器路径完整；
- [ ] PWC 基线浅色主题验证对比度；
- [ ] 375px、768px、1024px、1440px 无横向溢出；
- [ ] 运行时不加载远程字体和装饰脚本；
- [ ] 动效支持减少动态效果；
- [ ] 错误包含原因和恢复路径。
- [ ] 中文与英文覆盖同一完整流程，语言偏好可持久化，英文长文案不产生横向溢出。
